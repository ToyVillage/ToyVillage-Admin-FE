# Scenario Draft — reservations-list

출처: `harness/publishing/specs/reservations-list.spec.md` (행동명세가 source of truth)
상태: draft (2026-09-20 디자인 개편 반영 — 재승인 대기)

## 핵심 시나리오

### S1: 리스트 표시
- Given: `/notices/reservations` 진입
- Then: 타이틀 `단체예약 현황`, 상태 카드 3개(사전답사 전/사전답사 완료/방문 완료, 각 카운트), `단체예약 생성하기` 버튼, 테이블(헤더 상담일·예약일·예약 시간·단체명/지역·인원, 검색바, 행), 페이지네이션이 보인다
- And: 행 체크박스와 `페이지 권한주기` 버튼은 보이지 않는다

### S2: 상태 필터
- Given: 리스트 화면(기본 활성 `사전답사 전`)
- When: `방문 완료` 카드를 클릭
- Then: 방문 완료 상태 예약만 테이블에 보이고 `방문 완료` 카드가 활성 표시된다

### S3: 검색
- Given: 리스트 화면
- When: 검색바에 단체명 일부를 입력
- Then: 일치하는 행만 남는다. 없으면 `검색결과가 없습니다`를 표시한다

### S4: 정렬 (상담일순/예약일순)
- Given: 리스트 화면
- When: 필터 아이콘 클릭 → `예약일순` 선택
- Then: 예약일 기준으로 정렬되고 메뉴가 닫힌다

### S5: 행 클릭 → 상세 이동
- Given: 리스트 화면
- When: 첫 행을 클릭
- Then: `/notices/reservations/:id`로 이동한다

### S6: 행 케밥 메뉴
- Given: 리스트 화면
- When: 첫 행의 `⋮` 버튼을 클릭
- Then: `수정`/`삭제` 메뉴가 열린다
- And: 다른 행의 `⋮`를 누르면 앞서 열린 메뉴는 닫히고 그 행 메뉴만 열린다. Escape 로 닫히고 초점이 `⋮` 버튼으로 돌아온다

### S7: 케밥 수정 → 수정 페이지
- Given: 첫 행의 케밥 메뉴가 열림
- When: `수정`을 클릭
- Then: `/notices/reservations/:id/edit`로 이동한다

### S8: 케밥 삭제 → 확인 모달 → 삭제
- Given: 첫 행의 케밥 메뉴가 열림
- When: `삭제`를 클릭
- Then: `정말 삭제하시겠습니까?` 확인 모달이 열린다
- When: `확인`을 클릭
- Then: 삭제 요청이 나가고 목록이 갱신되며 `데이터 삭제에 성공했습니다` 토스트가 뜬다
- And: 삭제 요청이 실패하면 `데이터 삭제에 실패했습니다` 토스트가 뜨고 목록은 그대로다

## 엣지 케이스

### S9: 데이터 없음 빈 상태
- Given: 예약 데이터가 하나도 없음
- Then: 테이블 헤더·검색바는 유지한 채 `아직 단체예약이 없습니다`를 표시한다(검색 결과 없음과 문구로 구분)

### S10: 페이지네이션·리셋
- Given: 여러 페이지 분량의 예약
- When: 2페이지로 이동 후 상태 카드나 검색을 변경
- Then: 목록이 1페이지로 리셋된다

### S11: 생성·수정 복귀 토스트
- Given: 생성(또는 수정) 화면에서 저장에 성공해 목록으로 돌아옴
- Then: `데이터 생성에 성공했습니다`(또는 `데이터 수정에 성공했습니다`) 토스트가 한 번 뜨고, 새로고침해도 다시 뜨지 않는다
