# Scenario Draft — staff-accounts

출처: `harness/publishing/specs/staff-accounts.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

> 계정 생성 요청(`POST /app/admin/employees`)은 테스트에서 Playwright 라우트로 응답을 흉내 낸다(201 / 409 / 500).
> 목록·삭제·비밀번호 초기화는 퍼블리싱 mock 이다.

## 핵심 시나리오

### S1: 진입 시 목록 첫 페이지가 보인다
- Given: 로그인 토큰이 있는 상태로 `/settings/accounts` 로 이동한다.
- When: 화면이 뜬다.
- Then: 제목 `직원 계정 관리`, 부제 `토이빌리지 직원 계정 관리`, `계정 생성하기` 버튼,
  `이름 또는 아이디 검색` 입력이 보인다. 머리행 `이름` / `비밀번호` / `계정 생성일` 이 보이고,
  첫 행은 `김수인` · `suin.kim` · `변경 완료` · `2026.07.03` 이며 행은 5개다.
  `총 12명` 이 보이고 페이지 `1` 이 현재 페이지다.

### S2: 페이지를 옮기면 다음 행들이 보이고 URL 에 남는다
- Given: S1 상태다.
- When: 페이지 `2` 를 누른다.
- Then: 행이 6~10번째 계정으로 바뀌고 URL 에 `page=2` 가 붙는다. 새로고침해도 2페이지다.

### S3: 이름 또는 아이디로 검색한다
- Given: 2페이지를 보고 있다.
- When: 검색 입력에 `jia` 를 넣는다.
- Then: `이지아` 행만 남고 `총 1명` 이며, URL 에 `keyword=jia` 가 붙고 `page` 는 빠진다(1페이지).
  검색어를 `김수` 로 바꾸면 `김수인` 행만 남는다.

### S4: 계정을 만들면 모달이 닫히고 목록 맨 위에 추가된다
- Given: 1페이지이고 계정 생성 요청이 201 로 응답한다.
- When: `계정 생성하기` 를 누르고, 이름 ` 김직원 `, 아이디 ` employee01 ` 을 넣고 `계정 생성` 을 누른다.
- Then: 요청 본문이 `{ "username": "employee01", "name": "김직원" }` 으로 한 번 간다.
  모달이 닫히고 `계정 생성에 성공했습니다` 토스트가 뜬다.
  목록 첫 행이 `김직원` · `employee01` · `초기 비밀번호` 이고 `총 13명` 이다.

### S5: 비밀번호를 초기화하면 배지가 초기 비밀번호로 바뀐다
- Given: 1페이지, `김수인` 행 배지가 `변경 완료` 다.
- When: `김수인` 행 케밥을 눌러 `비밀번호 초기화` 를 고르고,
  확인 모달(`비밀번호를 초기화하시겠습니까?`)에서 `초기화` 를 누른다.
- Then: 모달이 닫히고 `김수인` 행 배지가 `초기 비밀번호` 가 되며
  `비밀번호 초기화에 성공했습니다` 토스트가 뜬다.

### S6: 계정을 삭제하면 목록에서 사라진다
- Given: 1페이지, `총 12명` 이다.
- When: `이승현` 행 케밥을 눌러 `삭제` 를 고르고, 확인 모달에서 `확인` 을 누른다.
- Then: 모달이 닫히고 `이승현` 행이 사라지며 `총 11명` 이 된다.
  `데이터 삭제에 성공했습니다` 토스트가 뜬다.

### S7: 사이드바에서 직원 계정 관리로 들어온다
- Given: `/` 에 있다.
- When: 사이드바를 열고 `설정` 을 펼쳐 `직원 계정 관리` 를 누른다.
- Then: `/settings/accounts` 로 이동해 이 화면이 보인다. 다시 사이드바를 열면 `직원 계정 관리` 가 활성이고,
  같은 그룹의 첫 항목 라벨이 `팀 관리` 다.

## 엣지 케이스

### S8: 빈 값으로 제출하면 두 오류가 함께 보이고 요청하지 않는다
- Given: 계정 생성 모달이 열려 있다.
- When: 아무것도 넣지 않고 `계정 생성` 을 누른다.
- Then: `이름을 입력해주세요` 와 `아이디를 입력해주세요` 오류가 함께 보이고 두 입력이 `aria-invalid` 다.
  이름 입력에 포커스가 가고 생성 요청은 가지 않는다. 공백만 넣은 경우도 같다.

### S9: 오류가 난 필드에 입력하면 그 필드 오류만 사라진다
- Given: S8 상태다.
- When: 이름 입력에 `김직원` 을 넣는다.
- Then: 이름 오류는 사라지고 아이디 오류는 남는다.

### S10: 아이디가 중복이면 아이디 아래에 알려준다
- Given: 계정 생성 요청이 409 로 응답한다.
- When: 이름 `김직원`, 아이디 `employee01` 로 `계정 생성` 을 누른다.
- Then: 모달이 열린 채 `이미 사용 중인 아이디예요` 가 아이디 아래에 보이고 아이디 입력에 포커스가 있다.
  토스트는 뜨지 않고 목록은 그대로다. 아이디를 고치면 그 오류가 사라진다.

### S11: 서버 오류면 입력을 유지하고 실패 토스트를 띄운다
- Given: 계정 생성 요청이 500 으로 응답한다.
- When: 이름 `김직원`, 아이디 `employee01` 로 `계정 생성` 을 누른다.
- Then: `데이터 생성에 실패했습니다` 토스트가 뜨고, 모달은 열린 채 두 입력값이 그대로다.

### S12: 제출 중에는 다시 제출되지 않는다
- Given: 계정 생성 요청 응답이 늦다.
- When: 유효한 값으로 `계정 생성` 을 누르고 응답 전에 한 번 더 누르거나 `Enter` 를 누른다.
- Then: 요청은 한 번만 가고, 응답 전까지 `계정 생성` 버튼은 비활성이며 `aria-busy="true"` 다.

### S13: 생성 모달을 취소하면 아무것도 만들지 않고 다음에 빈 상태로 열린다
- Given: 계정 생성 모달에 이름을 넣었다.
- When: `Escape` 를 누른다(또는 `취소`, 딤 바깥 클릭).
- Then: 모달이 닫히고 요청은 가지 않으며 포커스가 `계정 생성하기` 버튼으로 돌아온다.
  다시 열면 입력이 비어 있고 이름 입력에 포커스가 있다.

### S14: 확인 모달에서 취소하면 아무것도 바뀌지 않는다
- Given: 1페이지다.
- When: `김수인` 행 케밥 → `비밀번호 초기화` 후 `취소`, 이어서 `이승현` 행 케밥 → `삭제` 후 `Escape`.
- Then: 두 모달 모두 닫히고 `김수인` 배지는 `변경 완료`, `이승현` 행은 남아 있으며 `총 12명` 이고 토스트는 없다.

### S15: 케밥 메뉴는 Escape 와 바깥 클릭으로 닫힌다
- Given: 1페이지다.
- When: 첫 행 케밥을 누른다.
- Then: `비밀번호 초기화`, `삭제` 순서의 메뉴가 열린다.
  `Escape` 를 누르면 닫히고, 다시 열어 메뉴 바깥을 누르면 닫힌다.

### S16: 검색 결과가 없으면 빈 문구를 보인다
- Given: `/settings/accounts` 다.
- When: 검색 입력에 `없는사람` 을 넣는다.
- Then: 행이 없고 `검색결과가 없습니다` 와 `총 0명` 이 보이며 페이지네이션은 없다.

### S17: 마지막 페이지의 마지막 행을 지우면 앞 페이지로 간다
- Given: `/settings/accounts?page=3` 에 행이 2개 있다.
- When: 두 행을 차례로 삭제한다.
- Then: 두 번째 삭제 후 2페이지로 옮겨져 5개 행이 보이고 `총 10명` 이다.

### S18: 옛 계정 생성 주소는 목록으로 옮겨진다
- Given: 로그인 상태다.
- When: `/settings/accounts/create` 로 이동한다.
- Then: 주소가 `/settings/accounts` 로 바뀌고 이 화면이 보인다.
