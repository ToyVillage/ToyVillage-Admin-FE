# Scenario Draft — task-edit

출처: `harness/publishing/specs/task-edit.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 목록에서 수정 화면 진입
- Given: `/tasks` 목록 화면
- When: 목록의 첫 행을 클릭한다
- Then: 해당 업무의 `/tasks/:id` 로 이동한다

### S2: 기존 값 표시
- Given: 기본 mock 업무의 `/tasks/:id` 화면
- When: 화면이 렌더된다
- Then: 우선순위 `상`이 선택 상태이고 완료기한·공개범위·담당자·제목·상세 업무 내용과 첨부 파일명 3건이 보인다

### S3: 제목·상세 내용 수정 후 저장
- Given: `/tasks/:id` 화면
- When: 제목과 상세 업무 내용을 고치고 `저장하기` 를 클릭한다
- Then: `/tasks` 로 이동하고 같은 ID 한 행에 수정된 제목이 보인다

### S4: 우선순위 변경 후 저장
- Given: `/tasks/:id` 화면, 우선순위가 `상`
- When: 우선순위를 `하` 로 바꾸고 `저장하기` 를 클릭한다
- Then: `/tasks` 로 이동하고 해당 행의 우선순위 배지가 `하` 로 바뀐다

### S5: 완료기한 변경 후 저장
- Given: `/tasks/:id` 화면
- When: 완료기한을 다른 날짜로 바꾸고 `저장하기` 를 클릭한다
- Then: `/tasks` 로 이동하고 해당 행의 완료기한이 바뀐다

### S6: 첨부 제거와 추가
- Given: `/tasks/:id` 화면, 첨부 3건이 있음
- When: 기존 첨부 하나를 제거하고 새 파일을 추가한다
- Then: chip 목록이 즉시 갱신된다

### S7: 삭제 취소
- Given: `/tasks/:id` 화면
- When: `삭제하기` 를 클릭한 뒤 확인 모달에서 `취소` 를 누른다
- Then: URL 과 업무가 유지되고 `삭제하기` 버튼으로 포커스가 복귀한다

### S8: 삭제 확인
- Given: `/tasks/:id` 화면
- When: `삭제하기` 를 클릭하고 확인 모달에서 `확인` 을 누른다
- Then: `/tasks` 로 이동하고 같은 ID 업무가 목록에서 사라진다

### S9: 변경 없이 저장
- Given: `/tasks/:id` 화면, 아무것도 고치지 않은 상태
- When: `저장하기` 를 클릭한다
- Then: 현재 값으로 한 번 요청되고 `/tasks` 로 이동한다

### S10: 변경 없이 뒤로가기
- Given: `/tasks/:id` 화면, 아무것도 고치지 않은 상태
- When: `뒤로가기` 를 클릭한다
- Then: 이탈 확인 없이 `/tasks` 로 돌아간다

## 엣지 케이스

### S11: 제목 누락 검증과 포커스 복귀
- Given: `/tasks/:id` 화면
- When: 제목을 비우고 `저장하기` 를 클릭한 뒤 모달의 `확인` 을 누른다
- Then: 저장 요청 없이 `제목을 입력해주세요` 모달이 표시되고, 확인 후 제목 입력으로 포커스가 이동한다

### S12: 상세 업무 내용 누락 검증
- Given: `/tasks/:id` 화면
- When: 상세 업무 내용을 비우고 `저장하기` 를 클릭한다
- Then: 저장 요청 없이 `상세 업무 내용을 입력해주세요` 모달이 표시된다

### S13: 삭제 모달 `Esc` 로 닫기
- Given: `/tasks/:id` 화면에서 삭제 확인 모달이 열려 있음
- When: `Esc` 키를 누른다
- Then: 삭제되지 않고 모달이 닫히며 `삭제하기` 로 포커스가 복귀한다

### S14: 삭제 실패 토스트
- Given: `/tasks/:id` 화면에서 삭제가 실패하는 조건
- When: 삭제 확인 모달에서 `확인` 을 누른다
- Then: 현재 화면과 입력이 유지되고 `데이터 삭제에 실패했습니다` 토스트가 표시된다

### S15: 저장 실패 시 입력 보존
- Given: `/tasks/:id` 화면에서 저장이 실패하는 조건
- When: 값을 고치고 `저장하기` 를 클릭한다
- Then: URL 과 모든 입력이 보존되고 실패가 표시된다

### S16: 존재하지 않는 ID
- Given: 존재하지 않는 업무 ID 의 `/tasks/:id` URL
- When: 화면에 진입한다
- Then: 입력 폼 대신 not-found 문구와 목록 복귀 링크가 표시된다

### S17: 수정 후 이탈 보호
- Given: `/tasks/:id` 화면에서 제목을 고친 상태
- When: `뒤로가기` 또는 브라우저 뒤로가기를 시도하고 이탈 확인 모달에서 `취소` 를 누른다
- Then: 현재 URL 과 입력이 그대로 유지된다

### S18: 이탈 확인 후 이동
- Given: S17 과 같은 상태에서 이탈 확인 모달이 떠 있음
- When: `확인` 을 누른다
- Then: 시도한 경로로 이동한다

### S19: 저장·삭제 중 중복 제출 방지
- Given: `/tasks/:id` 화면
- When: `저장하기` 또는 삭제 `확인` 을 연속으로 두 번 클릭한다
- Then: 요청은 한 번만 전송된다

### S20: 키보드 전용 조작
- Given: `/tasks/:id` 화면
- When: 키보드만으로 편집·첨부·검증·저장·삭제 취소를 시도한다
- Then: 모든 조작이 가능하다

### S21: `업무 보고 상세조회` 버튼으로 업무보고 상세 이동
- Given: 업무보고가 올라온 업무의 `/tasks/:id` 화면
- When: 우측 상단 `업무 보고 상세조회` 버튼을 클릭한다
- Then: 그 업무의 업무보고 상세 `/task-reports/:reportId` 로 이동한다

---

## 승인 메모

- S2 의 담당자는 mock 에 저장값(`이승현 사원`)을 채운 기준으로 검증한다(Figma placeholder 잔재 미채택).
- S6 의 기존 첨부는 제거 가능하다(Figma `visible: false` 는 디자인 누락으로 판단).
- S16 의 not-found 문구는 `업무를 찾을 수 없습니다.` 로 확정했다.
- S15 는 저장 실패 시 화면과 입력이 보존되는 것만 검증한다. 저장 결과 토스트는 만들지 않는다.
- S21 은 `task-report` 슬라이스에서 이동 대상 화면이 생겨 `이동 검증` 으로 갱신했다(기존 `비활성` 검증 대체).
- 우선순위·완료기한·공개범위·담당자 검증은 `task-create` 와 동일하므로 중복을 피해 여기서는 제외한다.
