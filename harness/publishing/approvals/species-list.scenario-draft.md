# Scenario Draft — species-list

출처: `harness/publishing/specs/species-list.spec.md` (행동명세가 source of truth)
기준 Figma: `yot`(`P7Jhnu8qV5m9q2QJNzkwAN`) `39:8751` + `39:8913` / `51:8701` / `71:8888`
상태: draft — 게이트 ② 결정 반영(2026-09-15), 시나리오 승인 대기

전제: 퍼블리싱 슬라이스라 실제 API 없이 `entities/species/model/mock.ts` 13건(spec `데이터` 표)을 쓴다.
기본 정렬은 최신순(id 큰 순)이라 `전체` 탭 1페이지는 id 13~4(첫 행 `피라냐`), 2페이지는 id 3·2·1 이다. 분류군별 포유류 5 · 파충류 3 · 조류 3 · 어류 2.

## 핵심 시나리오

### S1: 목록 진입 기본 상태
- Given: 종 목록 라우트 `/species`
- When: 화면에 진입한다
- Then: 제목 `개체 카드`와 부제 `토이빌리지의 등록된 개체 목록`이 보이고, `전체` 탭이 활성이며,
  표 헤더가 `분류군` `국명` `학명` `마리수` 순서이고, 검색바 placeholder 가 `개체이름 또는 국명을 입력해주세요` 이며,
  최신순 1페이지 10행(첫 행 `피라냐`)이 표시된다

### S2: 등록 버튼 이동
- Given: `/species` 화면
- When: `개체 등록하기` 버튼을 클릭한다
- Then: `/species/create` 로 이동한다

### S3: `포유류` 탭 필터
- Given: `/species` 화면, `전체` 탭 활성
- When: `포유류` 탭을 클릭한다
- Then: `포유류` 탭이 활성이 되고 분류군 셀이 `포유류` 인 5행만 남는다

### S4: `파충류` 탭 필터
- Given: `/species` 화면
- When: `파충류` 탭을 클릭한다
- Then: `파충류` 탭이 활성이 되고 분류군 셀이 `파충류` 인 3행만 남는다

### S5: `조류` 탭 필터
- Given: `/species` 화면
- When: `조류` 탭을 클릭한다
- Then: `조류` 탭이 활성이 되고 분류군 셀이 `조류` 인 3행만 남는다

### S6: `어류` 탭 필터
- Given: `/species` 화면
- When: `어류` 탭을 클릭한다
- Then: `어류` 탭이 활성이 되고 분류군 셀이 `어류` 인 2행만 남는다

### S7: `전체` 탭 복귀
- Given: `/species` 화면, `조류` 탭 활성
- When: `전체` 탭을 클릭한다
- Then: `전체` 탭이 활성이 되고 여러 분류군의 행이 다시 1페이지 10행으로 보인다

### S8: 국명 검색
- Given: `/species` 화면, `전체` 탭 활성
- When: 검색바에 `카피` 를 입력한다
- Then: 국명이 `카피바라` 인 행 하나만 남는다

### S9: 개체명 검색
- Given: `/species` 화면, 개체 `동식이` 가 종 `카피바라` 에 속함(individual mock)
- When: 검색바에 `동식` 을 입력한다
- Then: `카피바라` 행이 보인다

### S10: 행 본문 클릭 → 종 상세 이동
- Given: `/species` 화면
- When: `피라냐` 행의 본문 영역(케밥 버튼 밖)을 클릭한다
- Then: `/species/13`(종 상세)로 이동한다

### S11: 페이지네이션 이동
- Given: `/species` 화면, `전체` 탭 1페이지
- When: `2 페이지` 버튼을 클릭한다
- Then: `반달가슴곰` `플라밍고` `카피바라` 3행으로 목록이 바뀐다

### S12: 마리수 표시
- Given: `/species` 화면
- When: `포유류` 탭에서 `카피바라` 행의 마리수 셀을 확인하고, `어류` 탭에서 `피라냐` 행의 마리수 셀을 확인한다
- Then: `카피바라` 는 `3`, `피라냐` 는 `0` 으로 보인다

### S13: 케밥 메뉴 열기
- Given: `/species` 화면
- When: `피라냐` 행 우측 끝 `⋮`(`피라냐 관리 메뉴`) 버튼을 클릭한다
- Then: 그 행의 메뉴가 열려 `수정` / `삭제` 두 항목이 보이고, URL 은 `/species` 그대로다

### S14: 케밥 메뉴는 하나만 열린다
- Given: `/species` 화면, `피라냐` 행의 케밥 메뉴가 열려 있음
- When: `흰동가리` 행의 `⋮` 버튼을 클릭한다
- Then: `피라냐` 행 메뉴가 닫히고 `흰동가리` 행 메뉴만 열려 있다

### S15: 케밥 메뉴 닫기
- Given: `/species` 화면, 케밥 메뉴가 열려 있음
- When: 메뉴 바깥을 클릭하거나 `Escape` 를 누른다
- Then: 메뉴가 닫히고, `Escape` 로 닫은 경우 초점이 해당 `⋮` 버튼으로 돌아온다

### S16: 케밥 `수정` → 종 수정 이동
- Given: `/species` 화면, `피라냐` 행의 케밥 메뉴가 열려 있음
- When: `수정` 을 클릭한다
- Then: 메뉴가 닫히고 `/species/13/edit` 로 이동한다

### S17: 케밥 `삭제` → 확인 모달
- Given: `/species` 화면, 케밥 메뉴가 열려 있음
- When: `삭제` 를 클릭한다
- Then: 메뉴가 닫히고 제목 `정말 삭제하시겠습니까?`, 본문 `등록된 개체와 관찰 기록도 함께 삭제되며` /
  `삭제 후에는 복구할 수 없습니다`, 버튼 `취소` / `확인` 의 확인 모달이 열린다

### S18: 삭제 취소
- Given: `흰동가리` 행의 삭제 확인 모달이 열려 있음
- When: `취소` 를 클릭하거나 `Escape` 를 누른다
- Then: 모달이 닫히고 `흰동가리` 행이 목록에 그대로 남는다

### S19: 삭제 확인 → 성공 토스트
- Given: `흰동가리` 행의 삭제 확인 모달이 열려 있음
- When: `확인` 을 클릭한다
- Then: `흰동가리` 행이 목록에서 사라지고 우상단에 `데이터 삭제에 성공했습니다` 토스트가 표시된 뒤 사라진다

## 엣지 케이스

### S20: 페이지네이션 경계 비활성
- Given: `/species` 화면, `전체` 탭
- When: 1페이지와 마지막(2)페이지에서 각각 페이지네이션을 확인한다
- Then: 1페이지에서 `이전 페이지` 버튼이 비활성이고, 마지막 페이지에서 `다음 페이지` 버튼이 비활성이다

### S21: 탭 전환·검색 입력 시 1페이지로 리셋
- Given: `/species` 화면에서 `전체` 탭 2페이지를 보는 중
- When: 다른 탭으로 전환한다 / (다시 2페이지로 간 뒤) 검색어를 입력한다
- Then: 각각 목록이 1페이지부터 표시된다

### S22: 검색 결과 없음
- Given: `/species` 화면
- When: 어떤 국명·개체명에도 없는 검색어(예: `없는종`)를 입력한다
- Then: 행이 사라지고 `검색결과가 없습니다` 가 표시되며 페이지네이션이 보이지 않는다

### S23: 검색어 유지한 채 탭 전환
- Given: `/species` 화면, 검색어 `카피` 입력 상태(`카피바라` 행만 보임)
- When: `조류` 탭을 클릭한다
- Then: 검색바에 `카피` 가 그대로 남아 있고, `조류` 이면서 검색어에 맞는 종이 없어 `검색결과가 없습니다` 가 표시된다

### S24: 종이 없는 탭 → 빈 상태
- Given: 어류 종(`흰동가리` `피라냐`)이 모두 삭제된 상태(mock 삭제 기록 `toyvillage:species:deleted` 에 id 12·13)로 `/species` 진입
- When: 검색어 없이 `어류` 탭을 클릭한다
- Then: 행 대신 `등록된 개체 카드가 없습니다` / `오른쪽 위 [개체 등록하기]로 첫 개체 카드를 추가해주세요` 두 줄이 표시되고 페이지네이션이 보이지 않는다

### S25: 삭제 실패 토스트
- Given: 다음 삭제가 실패하도록 주입된 상태(mock 실패 주입 `toyvillage:species:fail` = `delete`)에서 `흰동가리` 행의 삭제 확인 모달이 열려 있음
- When: `확인` 을 클릭한다
- Then: 모달이 닫히고 `데이터 삭제에 실패했습니다` 토스트가 표시되며 `흰동가리` 행은 목록에 남는다

### S26: 생성 성공 토스트
- Given: `/species/create` 에서 종 생성에 성공해 생성 성공 토스트 요청과 함께 `/species` 로 돌아온 상태
- When: 목록 화면이 렌더된다
- Then: 우상단에 `데이터 생성에 성공했습니다` 토스트가 표시되고 일정 시간 후 사라진다

### S27: 마지막 페이지의 유일한 행 삭제
- Given: id 12·13 이 삭제된 상태(mock 삭제 기록)로 `/species` 2페이지에 `카피바라` 한 행만 보이는 중(최신순)
- When: `카피바라` 행을 케밥 `삭제` → `확인` 으로 삭제한다
- Then: 1페이지로 되돌아가 10행이 보이고 `데이터 삭제에 성공했습니다` 토스트가 뜨며 페이지네이션이 보이지 않는다

### S28: 키보드 조작
- Given: `/species` 화면
- When: 키보드만으로 탭 전환·검색 입력·정렬 메뉴 선택·페이지 이동·행 진입(`Enter`)·케밥 메뉴 열기/항목 선택을 시도한다
- Then: 모든 조작이 가능하고 포커스 표시가 outline 으로 보인다

### S29: 사이드바 `개체관리 바로가기`
- Given: `/tasks` 화면에서 사이드바를 연 상태
- When: `개체관리 바로가기` 를 클릭한 뒤, `/species/1` 로 이동해 사이드바를 다시 연다
- Then: 첫 클릭 후 `/species` 로 이동하고 사이드바가 닫히며, 종 상세(`/species/1`)에서도 `개체관리 바로가기` 메뉴가 활성으로 표시된다

### S30: 정렬 전환
- Given: `/species` 화면, `전체` 탭 2페이지를 보는 중(기본 최신순)
- When: 검색바 우측 정렬 버튼을 눌러 `오래된순` 을 선택한다
- Then: 목록이 1페이지로 리셋되고 첫 행이 `카피바라`(id 1)로 바뀐다
