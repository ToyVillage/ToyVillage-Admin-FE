데이터 전제(spec 데이터 절): 종 `1` 카피바라 — 개체 `1` 동식이(수컷, 2019, 기타정보 있음, 관찰 11건),
`2` 미미(암컷, 기타정보 없음, 관찰 1건), `3` 두리(관찰 0건). 종 `2` 플라밍고 — 개체 `7` 체리(미상, species-detail mock).
관찰 id 1 은 첨부 3개(`상처사진.jpg`, `상처사진_측면.jpg`, `처치기록.pdf`), id 2 는 1개, id 3 은 없음.
데이터는 e2e 가짜 서버(`tests/e2e/support/animal-manage-api.ts`)가 옛 mock 과 같게 주고, 삭제 실패는 `failNext('observation.delete')` / `failNext('animal.delete')` 로 만든다(API 연동 2026-09-17).

## 핵심 시나리오

### S1: 개체 상세 진입 기본 상태
- Given: 개체 상세 라우트 `/species/1/individuals/1`
- When: 화면에 진입한다
- Then: `뒤로가기`, 이름 `동식이`, 성별 뱃지 `수컷`, 출생연도 `2019년`, 기타정보 `알락꼬리여우원숭이와 합사 중`,
  `먹이 급여 기록 확인하기` 버튼, 섹션 헤더 `관찰 및 특이사항 11건` 이 보인다

### S2: 관찰 표 컬럼·정렬·페이지 크기
- Given: `/species/1/individuals/1` 화면
- When: 관찰 표를 확인한다
- Then: 컬럼이 `날짜` `관찰자` `제목` `첨부` 이고, 1페이지에 10행이 날짜 최신순으로 보이며 첫 행은 `2026.06.01` · `김유영` ·
  `얼굴 콧잔등 부위 약 3cm 긁힌 상처 있음` 이다

### S3: 첨부 칸 표기
- Given: `/species/1/individuals/1` 화면
- When: 첨부 칸을 확인한다
- Then: 첨부 3개 행은 `상처사진.jpg` chip 과 `외 2개`, 첨부 1개 행(`배변상태 평소보다 조금 묽음`)은 `배변사진.jpg` chip 만,
  첨부 없는 행(`식욕 정상, 활동량 양호`)은 `—` 가 보인다

### S4: 행 클릭 → 관찰 상세
- Given: `/species/1/individuals/1` 화면
- When: 첫 행의 제목을 클릭한다
- Then: `/species/1/individuals/1/observations/1` 로 이동한다

### S5: 첨부 chip 다운로드
- Given: `/species/1/individuals/1` 화면
- When: 첫 행의 `상처사진.jpg` chip 을 클릭한다
- Then: 파일명 `상처사진.jpg` 로 다운로드가 일어나고 경로는 `/species/1/individuals/1` 그대로다

### S6: `외 N개` hover → 첨부 팝오버
- Given: `/species/1/individuals/1` 화면
- When: 첫 행의 `외 2개` 에 마우스를 올린다
- Then: 팝오버가 열리고 `상처사진.jpg` 를 포함한 첨부 3개 chip 이 보인다

### S7: 팝오버에서 다운로드
- Given: 첫 행의 첨부 팝오버가 열려 있음
- When: 팝오버의 두 번째 chip(`상처사진_측면.jpg`)을 클릭한다
- Then: 그 파일명으로 다운로드가 일어나고 경로는 그대로다

### S8: 페이지네이션
- Given: `/species/1/individuals/1` 화면(관찰 11건)
- When: `2 페이지` 를 클릭한다
- Then: 11번째 관찰(`2026.01.07` · `겨울철 실내 적응 양호`) 1행이 보이고 `다음 페이지` 가 비활성이다.
  1페이지로 돌아가면 `이전 페이지` 가 비활성이다

### S9: 뒤로가기
- Given: `/species/1/individuals/1` 화면
- When: `뒤로가기` 를 클릭한다
- Then: 확인 없이 `/species/1` 로 이동한다

### S10: 카드 케밥 메뉴 열기
- Given: `/species/1/individuals/1` 화면
- When: 카드 오른쪽 위 `⋮` 를 클릭한다
- Then: `수정` / `삭제` 두 항목이 보인다

### S11: 카드 메뉴 수정 → 개체 수정
- Given: 카드 케밥 메뉴가 열려 있음
- When: `수정` 을 클릭한다
- Then: `/species/1/individuals/1/edit` 로 이동한다

### S12: 카드 메뉴 삭제 → 개체 삭제 모달
- Given: 카드 케밥 메뉴가 열려 있음
- When: `삭제` 를 클릭한다
- Then: 메뉴가 닫히고 `정말 삭제하시겠습니까?` 모달이 열리며 본문에 `등록된 관찰 기록도 함께 삭제되며` / `삭제 후에는 복구할 수 없습니다` 가 보인다

### S13: 개체 삭제 확인 → 종 상세
- Given: 개체 삭제 확인 모달이 열려 있음
- When: `확인` 을 클릭한다
- Then: `/species/1` 로 이동하고 `데이터 삭제에 성공했습니다` 토스트가 뜬다

### S14: 행 케밥 메뉴 열기
- Given: `/species/1/individuals/1` 화면
- When: 첫 행의 `⋮` 를 클릭한다
- Then: 그 행의 `수정` / `삭제` 메뉴가 열리고 경로는 그대로다(행 이동 없음)

### S15: 행 메뉴 수정 → 관찰 수정
- Given: 첫 행의 케밥 메뉴가 열려 있음
- When: `수정` 을 클릭한다
- Then: `/species/1/individuals/1/observations/1/edit` 로 이동한다

### S16: 관찰 삭제 확인
- Given: 첫 행의 케밥 메뉴가 열려 있음
- When: `삭제` 를 클릭하고 확인 모달에서 `확인` 을 클릭한다
- Then: 모달이 닫히고 그 행이 표에서 사라지며 섹션 헤더가 `관찰 및 특이사항 10건` 이 되고 `데이터 삭제에 성공했습니다` 토스트가 뜬다.
  경로는 `/species/1/individuals/1` 그대로다

### S17: 먹이 급여 기록 확인하기 이동
- Given: 급여 이력이 있는 개체 `/species/1/individuals/1` 화면
- When: `먹이 급여 기록 확인하기` 를 클릭하고, 이동한 화면에서 `뒤로가기` 를 클릭한다
- Then: 가장 최근 급여 기록 상세 `/feeds/:feedLogId` 로 이동하고, `뒤로가기` 로 `/species/1/individuals/1` 에 돌아온다

## 엣지 케이스

### S18: 관찰 0건
- Given: 관찰이 없는 개체
- When: `/species/1/individuals/3` 로 진입한다
- Then: 섹션 헤더가 `관찰 및 특이사항 0건`, 표 헤더 아래 `등록된 관찰 기록이 없습니다` 가 보이고 페이지네이션이 없다

### S19: 기타정보 없음 · 암컷/미상 뱃지
- Given: 기타정보가 없는 암컷 개체(미미)와 성별 미상 개체(체리, 종 2)
- When: `/species/1/individuals/2` 와 `/species/2/individuals/7` 로 각각 진입한다
- Then: 미미는 성별 뱃지 `암컷` 과 기타정보 값 `—` 가, 체리는 성별 뱃지 `미상` 이 보인다

### S20: 케밥 메뉴 닫기
- Given: 카드 또는 행의 케밥 메뉴가 열려 있음
- When: 메뉴 바깥을 클릭하거나 `Escape` 를 누른다
- Then: 메뉴가 닫힌다. `Escape` 로 닫으면 초점이 그 `⋮` 로 돌아온다

### S21: 메뉴는 하나만 열림
- Given: 카드 케밥 메뉴가 열려 있음
- When: 첫 행의 `⋮` 를 클릭한다
- Then: 카드 메뉴가 닫히고 첫 행 메뉴 하나만 열려 있다

### S22: 첨부 팝오버 닫기
- Given: 첫 행의 첨부 팝오버가 열려 있음
- When: `Escape` 를 누른다
- Then: 팝오버가 닫히고 초점이 `외 2개` 로 돌아온다

### S23: 개체 삭제 취소
- Given: 개체 삭제 확인 모달이 열려 있음
- When: `취소` 를 클릭한다
- Then: 모달이 닫히고 `/species/1/individuals/1` 상세 화면이 그대로 남는다

### S24: 관찰 삭제 취소
- Given: 첫 행의 관찰 삭제 확인 모달이 열려 있음
- When: `취소` 를 클릭한다
- Then: 모달이 닫히고 행과 `관찰 및 특이사항 11건` 이 그대로다

### S25: 개체 삭제 실패
- Given: 개체 삭제가 실패하는 조건
- When: 개체 삭제 모달에서 `확인` 을 클릭한다
- Then: 모달이 닫히고 상세 화면에 `데이터 삭제에 실패했습니다` 토스트가 뜨며 경로가 그대로다

### S26: 관찰 삭제 실패
- Given: 관찰 삭제가 실패하는 조건
- When: 첫 행의 관찰 삭제 모달에서 `확인` 을 클릭한다
- Then: 모달이 닫히고 `데이터 삭제에 실패했습니다` 토스트가 뜨며 행과 `관찰 및 특이사항 11건` 이 그대로다

### S27: 마지막 페이지의 유일한 행 삭제
- Given: `/species/1/individuals/1` 에서 2페이지(1행)를 보는 중
- When: 그 행을 케밥 `삭제` → `확인` 으로 삭제한다
- Then: 1페이지 10행이 보이고 페이지네이션이 사라지며 섹션 헤더가 `관찰 및 특이사항 10건` 이다

### S28: 없는 개체
- Given: 존재하지 않는 개체 id, 또는 다른 종에 속한 개체 id
- When: `/species/1/individuals/999` 또는 `/species/2/individuals/1` 로 진입한다
- Then: `개체를 찾을 수 없습니다.` 와 경로의 종 상세(`/species/1` 또는 `/species/2`)로 가는 `종 상세로 돌아가기` 링크가 보인다

### S29: 관찰 상세 삭제 후 복귀 토스트
- Given: 관찰 상세에서 삭제에 성공해 navigate state `{ toast: 'delete-success' }` 로 이 화면에 온 상태
- When: `/species/1/individuals/1` 이 렌더된다
- Then: `데이터 삭제에 성공했습니다` 토스트가 보인다

### S30: 키보드 조작
- Given: `/species/1/individuals/1` 화면
- When: 키보드만으로 행 진입(Enter), 첨부 chip 다운로드, `외 N개` 팝오버 열기, 카드·행 케밥 열기와 항목 실행을 시도한다
- Then: 모든 조작이 가능하고, 첨부 chip·`외 N개`·`⋮` 에서 누른 Enter 는 행 이동을 일으키지 않으며 포커스 표시가 outline 으로 보인다

### S31: 급여 이력이 없으면 토스트
- Given: 급여 이력이 없는 개체 화면
- When: `먹이 급여 기록 확인하기` 를 클릭한다
- Then: 경로가 바뀌지 않고 `급여 기록이 없습니다` 토스트가 뜬다

### S32: 급여 이력 조회 실패 토스트
- Given: 급여 이력 조회가 500 으로 실패하는 개체 화면
- When: `먹이 급여 기록 확인하기` 를 클릭한다
- Then: 경로가 바뀌지 않고 `급여 기록을 불러오지 못했습니다` 토스트가 뜬다

## 승인 메모

- 게이트 ② 결정 반영(2026-09-15): 첨부 팝오버 여닫기(hover·focus 열림, mouseleave·blur·`Escape` 닫힘, `외 N개` 아래), 먹이 급여 버튼 `aria-disabled`,
  관찰 0건 한 줄, 관찰 삭제 기본 문구, not-found 종 상세 링크, 관찰 표 날짜 최신순 고정. **시나리오 id·문구 변경 없음.**
- #119(2026-09-17): 먹이 급여 버튼을 최신 급여 기록 상세로 연결했다. S17 을 이동으로 바꾸고 S31(이력 없음 토스트)·S32(조회 실패 토스트)를 더했다.
  급여 이력은 e2e 가짜 서버 `tests/e2e/support/feed-api.ts` 가 준다.
- 라우트·토스트 문구·한 페이지 10행은 개체관리 공통 결정이다. S4·S9·S11·S13·S15·S28 경로가 이에 기댄다.
- S13 은 종 상세(`species-detail`)가 navigate state 토스트를 받아 띄워야 통과한다. S29 는 관찰 상세(`observation-detail`)가 같은 state 로 이동해야 실제 흐름이 된다
  (이 feature 테스트에서는 state 를 직접 주고 진입해도 된다).
- S6·S7·S22 는 Figma `970:26390`(첨부 hover) 근거이고 여닫는 규칙은 게이트 ② 에서 확정했다. S30 의 키보드 팝오버 열기는 focus 규칙이다.
- S12 는 `DeleteConfirmationDialog.description`, S20 의 `Escape` 초점 복귀는 `KebabMenu` 보강을 전제로 한다(게이트 ② 채택).
- S19 의 `미상` 개체(체리 `7`)는 species-detail 개체 mock 명세에 기댄다.
- 개체 삭제의 관찰 연쇄 삭제는 이 화면에서 보이지 않는다(삭제 뒤 종 상세로 이동). 모달 문구만 S12 로 확인한다.
- 첨부 팝오버·다운로드의 시각 규격(위치·그림자)은 시나리오로 넣지 않았다 — ⑦ 육안 확인.
- S28 복귀 링크는 not-found 공통 규칙(부모 화면 링크) `종 상세로 돌아가기` 다.
