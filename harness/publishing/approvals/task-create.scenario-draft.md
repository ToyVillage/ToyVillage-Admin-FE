# Scenario Draft — task-create

출처: `harness/publishing/specs/task-create.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 생성 화면 진입 기본 상태
- Given: `/tasks` 목록 화면
- When: `업무 등록하기` 버튼을 클릭한다
- Then: `/tasks/create` 로 이동하고 우선순위가 미선택이며 모든 입력이 placeholder 상태다

### S2: 우선순위 단일 선택
- Given: `/tasks/create` 화면
- When: 우선순위 `중` 버튼을 클릭한다
- Then: `중`만 선택 상태가 되고 `상`·`하`는 선택되지 않는다

### S3: 완료기한 선택
- Given: `/tasks/create` 화면, 완료기한이 `연도. 월. 일`
- When: 완료기한 필드를 열어 날짜를 선택한다
- Then: 선택한 날짜가 완료기한 필드에 표시된다

### S4: 공개범위 선택
- Given: `/tasks/create` 화면
- When: 공개범위 드롭다운을 열고 다른 값을 선택한다
- Then: 목록이 닫히고 공개범위 값이 선택한 값으로 바뀐다

### S5: 담당자 선택
- Given: `/tasks/create` 화면, 담당자가 `직원 목록에서 선택`
- When: 담당자 드롭다운을 열고 직원을 선택한다
- Then: 목록이 닫히고 담당자 값이 선택한 직원으로 바뀐다

### S6: 제목·상세 내용 입력
- Given: `/tasks/create` 화면
- When: 제목과 상세 업무 내용에 텍스트를 입력한다
- Then: 입력한 값이 각 필드에 표시된다

### S7: 첨부 추가
- Given: `/tasks/create` 화면, 첨부자료가 비어 있음
- When: 업로드 드롭존으로 파일을 추가한다
- Then: 첨부자료에 해당 파일 chip 이 나타나고 `첨부파일 등록에 성공했습니다` 토스트가 표시된다

### S8: 첨부 제거
- Given: `/tasks/create` 화면, 첨부 chip 이 하나 이상 있음
- When: chip 의 제거 컨트롤을 클릭한다
- Then: 해당 chip 이 목록에서 사라진다

### S9: 정상 생성
- Given: `/tasks/create` 화면에서 우선순위·완료기한·공개범위·담당자·제목·상세 내용을 모두 채운 상태
- When: `생성하기` 버튼을 클릭한다
- Then: `/tasks` 로 이동하고 목록에 새 업무 행이 보인다

### S10: 뒤로가기 (변경 없음)
- Given: `/tasks/create` 화면, 아무것도 입력하지 않은 상태
- When: `뒤로가기` 를 클릭한다
- Then: 이탈 확인 없이 `/tasks` 로 돌아간다

## 엣지 케이스

### S11: 우선순위 미선택 검증
- Given: `/tasks/create` 화면, 우선순위만 비어 있고 나머지는 채워진 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `우선순위를 선택해주세요` 모달이 표시된다

### S12: 완료기한 미선택 검증
- Given: `/tasks/create` 화면, 완료기한만 비어 있는 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `완료기한을 선택해주세요` 모달이 표시된다

### S13: 공개범위 미선택 검증
- Given: `/tasks/create` 화면, 공개범위만 비어 있는 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `공개범위를 선택해주세요` 모달이 표시된다

### S14: 담당자 미선택 검증
- Given: `/tasks/create` 화면, 담당자만 비어 있는 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `담당자를 선택해주세요` 모달이 표시된다

### S15: 제목 누락 검증과 포커스 복귀
- Given: `/tasks/create` 화면, 제목만 비어 있는 상태
- When: `생성하기` 를 클릭하고 모달의 `확인` 을 누른다
- Then: 생성 요청 없이 `제목을 입력해주세요` 모달이 표시되고, 확인 후 제목 입력으로 포커스가 이동한다

### S16: 상세 업무 내용 누락 검증
- Given: `/tasks/create` 화면, 상세 업무 내용만 비어 있는 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `상세 업무 내용을 입력해주세요` 모달이 표시된다

### S17: 드롭다운 `Esc` 로 닫기
- Given: `/tasks/create` 화면에서 공개범위 또는 담당자 드롭다운이 열려 있음
- When: `Esc` 키를 누른다
- Then: 선택 없이 목록이 닫히고 기존 값이 그대로 유지된다

### S18: 드롭다운 바깥 클릭으로 닫기
- Given: `/tasks/create` 화면에서 드롭다운이 열려 있음
- When: 드롭다운 바깥 영역을 클릭한다
- Then: 선택 없이 목록이 닫히고 기존 값이 유지된다

### S19: 50MB 초과 파일 거부
- Given: `/tasks/create` 화면
- When: 50MB 를 초과하는 파일을 첨부하려 한다
- Then: 해당 파일이 첨부되지 않고 오류가 표시된다

### S20: 입력 후 이탈 보호
- Given: `/tasks/create` 화면에서 제목을 입력한 상태
- When: `뒤로가기` 또는 브라우저 뒤로가기를 시도하고 이탈 확인 모달에서 `취소` 를 누른다
- Then: 현재 URL 과 입력이 그대로 유지된다

### S21: 이탈 확인 후 이동
- Given: S20 과 같은 상태에서 이탈 확인 모달이 떠 있음
- When: `확인` 을 누른다
- Then: `/tasks` 로 이동한다

### S22: 생성 중 중복 제출 방지
- Given: `/tasks/create` 화면에서 모든 필수값을 채운 상태
- When: `생성하기` 를 연속으로 두 번 클릭한다
- Then: 생성 요청은 한 번만 전송된다

### S23: 키보드 전용 조작
- Given: `/tasks/create` 화면
- When: 키보드만으로 우선순위·완료기한·공개범위·담당자·제목·상세 내용을 입력하고 생성한다
- Then: 모든 조작이 가능하고 `/tasks` 로 이동한다

---

## 승인 메모

- 검증 순서(S11→S12→S13→S14→S15→S16)는 화면 시각 순서로 확정했다.
- S13 은 유효하다. 빈 폼의 `전체 직원` 표시는 placeholder 로 해석하고 미선택 시 검증한다.
- S7 의 토스트는 성공 아이콘 + 성공 문구로 매칭한다(Figma 인스턴스 잔재 미채택).
- S20·S21 의 이탈 보호는 생성 화면에도 적용한다(기존 `create-notice` 관례).
- S3 의 날짜 표시 형식은 폼 `YYYY.MM.DD` 로 Figma 를 그대로 따른다. 과거 날짜도 허용한다.
- S19 의 오류 표시는 기존 `NoticeAttachmentField` 방식을 따른다.
