## 핵심 시나리오

### S1: 목록 진입 기본 상태
- Given: 업무보고 목록 라우트 `/task-reports`
- When: 화면에 진입한다
- Then: 제목 `업무보고`와 부제 `토이빌리지 업무 보고 관리`가 보이고, `심사대기` 탭이 활성이며 1페이지 행이 표시된다

### S2: 컬럼 표시 확인
- Given: `/task-reports` 화면
- When: 테이블 헤더를 확인한다
- Then: `담당자` `제목` `상태` `우선순위` `완료기한` `공개범위` 6개 컬럼이 순서대로 보인다

### S3: 탭 라벨에 건수 표시
- Given: `/task-reports` 화면
- When: 탭바를 확인한다
- Then: `심사대기` `완료` `반려` `재제출` 네 탭이 각각 `{상태명} {건수}` 형태로 보이고, `팀이름` 탭은 없다

### S4: `완료` 탭 필터
- Given: `/task-reports` 화면, `심사대기` 탭 활성
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭이 활성이 되고 심사 상태가 `완료`인 보고만 남는다

### S5: `재제출` 탭 필터
- Given: `/task-reports` 화면
- When: `재제출` 탭을 클릭한다
- Then: `재제출` 탭이 활성이 되고 해당 보고만 남는다

### S6: 페이지네이션 이동
- Given: `/task-reports` 화면, `심사대기` 탭 결과가 한 페이지(3건)를 초과해 페이지 버튼이 보임
- When: `2 페이지` 버튼을 클릭한다
- Then: 2페이지의 행으로 목록이 바뀐다

### S7: 탭 전환 시 첫 페이지로 복귀
- Given: `/task-reports` 화면, `심사대기` 탭에서 2페이지를 보고 있음
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭의 1페이지가 표시된다

### S8: 행 클릭 → 상세 이동
- Given: `/task-reports` 화면
- When: 목록의 행을 클릭한다
- Then: 해당 보고의 `/task-reports/:id` 로 이동한다

### S9: 상세 표시 내용
- Given: 업무보고 상세 `/task-reports/:id`
- When: 화면을 확인한다
- Then: `우선순위:` `상태:` `담당자:` `완료 기한:` `공개 범위:` 요약과 `제목`, `상세 업무 내용`, `첨부자료`가 보이고,
  하단에 `반려하기` `승인하기` 버튼이 보인다

### S10: 첨부자료는 조회 전용
- Given: 첨부가 있는 업무보고 상세
- When: 첨부자료 영역을 확인한다
- Then: 파일명과 다운로드 버튼만 있고 삭제 버튼과 업로드 영역은 없다

### S11: 승인 처리
- Given: 심사대기 보고의 상세 화면
- When: `승인하기` 버튼을 클릭한다
- Then: `/task-reports` 로 이동하고, 해당 보고가 `완료` 탭에서 조회된다

### S12: 반려 처리 (수정 — 반려 사유 모달 경유)
- Given: 심사대기 보고의 상세 화면에서 `반려하기` 를 눌러 반려 사유 모달이 열려 있음
- When: 반려 사유를 입력하고 `확인` 을 클릭한다
- Then: `/task-reports` 로 이동하고, 해당 보고가 `반려` 탭에서 조회된다

## 엣지 케이스

### S13: 처리 중 중복 제출 차단
- Given: 처리 지연이 주입된 상세 화면
- When: `승인하기` 버튼을 연속으로 두 번 클릭한다
- Then: 두 버튼이 비활성 상태가 되고 처리 요청은 한 번만 전송된다

### S14: 결과 없음 → 빈 상태
- Given: `/task-reports` 화면
- When: 결과가 없는 탭으로 전환한다
- Then: 행이 사라지고 `등록된 업무보고가 없습니다.` 가 표시되며 페이지네이션이 보이지 않는다

### S15: 없는 보고 진입
- Given: 존재하지 않는 id 의 `/task-reports/:id`
- When: 화면에 진입한다
- Then: `업무보고를 찾을 수 없습니다.` 안내와 목록으로 돌아가는 링크가 보인다

### S16: 업무 상세에서 그 업무의 업무보고 상세로 진입
- Given: 업무보고가 올라온 업무의 상세 `/tasks/:id`
- When: `업무 보고 상세조회` 버튼을 클릭한다
- Then: 그 업무의 업무보고 상세 `/task-reports/:reportId` 로 이동한다

### S17: 사이드바 업무보고 메뉴 이동
- Given: 다른 화면에서 사이드바를 연 상태
- When: `업무보고 바로가기` 를 클릭한다
- Then: `/task-reports` 로 이동하고 사이드바가 닫힌다

### S18: 상세에서 뒤로가기
- Given: 업무보고 상세 `/task-reports/:id`
- When: 상단 `뒤로가기` 를 클릭한다
- Then: 승인·반려 처리 없이 `/task-reports` 로 이동한다

### S19: 반려하기 → 반려 사유 모달 표시
- Given: 심사대기 보고의 상세 화면
- When: `반려하기` 버튼을 클릭한다
- Then: `반려 사유를 작성해주세요` 제목과 `반려 사유 작성` placeholder 입력란, `확인` 버튼이 있는 모달이 열리고,
  화면은 상세에 머무르며 반려 요청은 아직 전송되지 않는다

### S20: 사유 미입력 시 확인 불가
- Given: 반려 사유 모달이 열려 있고 입력란이 비어 있음
- When: 모달의 `확인` 버튼을 확인한다
- Then: `확인` 버튼이 비활성이고, 공백만 입력해도 비활성이 유지된다

### S21: 모달 이탈 시 반려되지 않음
- Given: 반려 사유 모달이 열려 있음
- When: Esc 를 누른다(또는 모달 바깥 영역을 클릭한다)
- Then: 모달이 닫히고 상세 화면에 머무르며, 반려 요청은 전송되지 않는다

### S22: 입력한 반려 사유 저장
- Given: 반려 사유 모달에 사유를 입력하고 `확인` 을 눌러 반려가 끝난 상태
- When: 저장된 반려 사유를 확인한다
- Then: 해당 보고 id 로 입력한 사유가 mock 저장소에 남아 있다

### S23: 모달 처리 중 중복 확인 차단
- Given: 처리 지연이 주입된 상태에서 반려 사유를 입력한 모달
- When: `확인` 버튼을 연속으로 두 번 클릭한다
- Then: `확인` 버튼이 비활성이 되고 반려 요청은 한 번만 전송된다

### S24: 모달 처리 중 초점 유지
- Given: 처리 지연이 주입된 상태에서 반려 사유를 입력한 모달
- When: `확인` 을 눌러 반려 요청이 진행 중인 상태에서 Tab 을 누른다
- Then: 초점이 사유 입력란에 남아 모달 밖으로 빠져나가지 않는다
