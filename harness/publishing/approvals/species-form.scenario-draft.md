## 핵심 시나리오

### S1: 등록 화면 진입 기본 상태
- Given: 종 mock 이 준비된 상태
- When: `/species/create` 로 진입한다
- Then: 제목 `종 등록` 이 보이고, 국명·영문명·학명·세부 분류 입력이 비어 각 placeholder(`국명을 입력해주세요` 등)를 보여준다
- And: 분류군 pill 4개(`포유류` `파충류` `조류` `어류`) 중 `포유류` 가 선택돼 있다
- And: 법정지정분류 기본 선택지 pill 3개(`지정관리 야생동물` `멸종위기 야생생물 I급` `천연기념물`)가 미선택이고 X 버튼이 없으며 `+ 법정분류 추가` 가 있다
- And: 사진 chip 이 없고 업로드 드롭존과 `생성하기` 버튼이 보인다

### S2: 분류군 단일 선택
- Given: `/species/create` 화면
- When: `조류` 를 클릭한 뒤 `어류` 를 클릭한다
- Then: `조류` 클릭 직후에는 `조류` 만 선택되고, `어류` 클릭 후에는 `어류` 만 선택된다

### S3: 법정지정분류 기본 선택지 토글
- Given: `/species/create` 화면
- When: `지정관리 야생동물` 과 `천연기념물` 을 클릭하고, `천연기념물` 을 다시 클릭한다
- Then: 두 번째 클릭까지 두 pill 이 모두 선택 상태(`aria-pressed="true"`)이고, 마지막 클릭 후 `천연기념물` 만 해제된다

### S4: 법정분류 추가 모달 열기
- Given: `/species/create` 화면
- When: `+ 법정분류 추가` 를 클릭한다
- Then: 제목 `법정분류 추가`, placeholder `분류 이름을 입력해주세요` 인 입력, `취소` / 비활성 `추가하기` 버튼이 있는 모달이 열리고 입력에 포커스가 있다

### S5: 새 법정분류 추가
- Given: 법정분류 추가 모달이 열린 상태
- When: `해양보호생물` 을 입력하고 `추가하기` 를 클릭한다
- Then: 모달이 닫히고 `+ 법정분류 추가` 바로 앞에 `해양보호생물` pill 이 선택 상태로 추가되며, 그 pill 에 `해양보호생물 삭제` 버튼이 있다

### S6: 사진 업로드
- Given: `/species/create` 화면
- When: 드롭존으로 이미지 파일(`capybara.jpg`) 1개를 올린다
- Then: 사진 카드에 `capybara.jpg` chip 이 1개 나타난다

### S7: 종 생성 성공
- Given: 국명·영문명·학명을 입력하고 사진을 올린 상태(분류군은 기본 `포유류`)
- When: `생성하기` 를 클릭한다
- Then: `/species` 로 이동하고 `데이터 생성에 성공했습니다` 토스트가 보이며, 목록 1페이지 첫 행(기본 최신순)에 새 종의 국명이 보인다

### S8: 수정 화면 진입 머리
- Given: 종 `1`(카피바라)이 있는 상태
- When: `/species/1/edit` 로 진입한다
- Then: 제목 `종 수정`, 부제 `카피바라의 종 정보를 수정합니다`, 버튼 `저장하기` 가 보인다

### S9: 수정 화면 값 복원
- Given: 종 `1`(카피바라)이 있는 상태
- When: `/species/1/edit` 로 진입한다
- Then: 국명 `카피바라`, 영문명 `Capybara`, 학명 `Hydrochoerus hydrochaeris`, 세부 분류 `설치목 - 천축서과` 가 채워져 있다
- And: 분류군은 `포유류` 만 선택, 법정지정분류는 `지정관리 야생동물` 만 선택, 사진 chip `카피바라_2026.jpg` 가 보인다

### S10: 수정 저장 성공
- Given: `/species/1/edit` 화면
- When: 국명을 `카피바라(수정)` 으로 고치고 `저장하기` 를 클릭한다
- Then: `/species/1` 로 이동하고 상세에 `카피바라(수정)` 이 보인다

## 엣지 케이스

### S11: 전부 빈 채 생성 — 오류 줄 동시 표시
- Given: `/species/create` 에서 아무것도 입력하지 않은 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 국명 카드 아래 `국명을 입력해주세요!`, 영문명·학명 카드 아래 `영문명과 학명을 모두 입력해주세요!`, 사진 카드 아래 `사진을 등록해주세요!` 오류 줄이 함께 보인다
- And: 포커스는 옮겨지지 않는다

### S12: 국명만 입력
- Given: 국명만 입력한 상태
- When: `생성하기` 를 클릭한다
- Then: 국명 오류 줄은 없고 `영문명과 학명을 모두 입력해주세요!` · `사진을 등록해주세요!` 줄이 보인다

### S13: 학명만 빈 채 생성
- Given: 국명·영문명만 입력한 상태
- When: `생성하기` 를 클릭한다
- Then: 영문명·학명 카드 아래 `영문명과 학명을 모두 입력해주세요!` 줄이 보인다

### S14: 고친 뒤 다시 제출하면 오류 줄 갱신
- Given: S11 처럼 세 오류 줄이 보이는 상태
- When: 국명을 입력한 뒤 줄을 확인하고, 다시 `생성하기` 를 클릭한다
- Then: 입력 직후에는 국명 오류 줄이 그대로 남아 있고, 다시 제출하면 국명 오류 줄만 사라지고 나머지 두 줄은 남는다

### S15: 사진 검증
- Given: 사진만 빼고 필수값을 모두 채운 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 사진 카드 아래(드롭존 위)에 `사진을 등록해주세요!` 줄만 보인다

### S16: 공백만 입력한 국명
- Given: 국명에 공백만 넣고 나머지 필수값을 채운 상태
- When: `생성하기` 를 클릭한다
- Then: 생성 요청 없이 `국명을 입력해주세요!` 줄이 보인다

### S17: 선택 항목 없이 생성
- Given: 세부 분류·법정지정분류를 비우고 필수값만 채운 상태
- When: `생성하기` 를 클릭한다
- Then: 오류 줄 없이 `/species` 로 이동하고 생성 성공 토스트가 보인다

### S18: 모달 빈 이름
- Given: 법정분류 추가 모달이 열리고 입력이 비었거나 공백만 있는 상태
- When: `추가하기` 버튼 상태를 확인하고 입력에서 `Enter` 를 누른다
- Then: `추가하기` 가 비활성이고, pill 이 추가되지 않으며 모달이 열린 채로 남는다

### S19: 모달 중복 이름
- Given: 법정분류 추가 모달이 열린 상태
- When: `천연기념물` 을 입력하고 `추가하기` 를 클릭한다
- Then: 새 pill 이 생기지 않고(같은 이름 pill 1개) 모달이 유지되며 입력 아래에 `이미 있는 분류입니다!` 가 보인다

### S20: 모달 취소
- Given: 법정분류 추가 모달에 이름을 입력한 상태
- When: `취소` 를 클릭한다(또는 `Esc`)
- Then: 아무것도 추가되지 않고 모달이 닫히며 `+ 법정분류 추가` 에 포커스가 돌아온다

### S21: 직접 추가한 법정분류 제거
- Given: 모달로 `해양보호생물` 을 추가한 상태
- When: `해양보호생물 삭제` 버튼을 클릭하고 삭제 확인 모달에서 `확인` 을 클릭한다
- Then: 서버 공용 목록에서 `해양보호생물` 이 삭제되어 pill 이 사라지고, 기본 선택지 3개 pill 에는 삭제 버튼이 없다

### S22: 사진 교체
- Given: `capybara.jpg` chip 이 있는 상태
- When: 다른 이미지 `capybara-2.png` 를 올린다
- Then: chip 은 1개이고 파일명이 `capybara-2.png` 로 바뀐다

### S23: 사진 제거
- Given: `capybara.jpg` chip 이 있는 상태
- When: chip 의 `capybara.jpg 삭제` 를 클릭한다
- Then: chip 이 사라지고 드롭존만 남으며, 필수값을 채우고 `생성하기` 를 눌러도 생성되지 않고 `사진을 등록해주세요!` 줄이 보인다

### S24: 이미지가 아닌 파일 거부
- Given: `/species/create` 화면
- When: `report.pdf` 를 올린다
- Then: chip 이 생기지 않고 `이미지 파일만 등록할 수 있습니다.` 가 보인다

### S25: 50MB 초과 거부
- Given: `/species/create` 화면
- When: 50MB 를 넘는 이미지 파일을 올린다
- Then: chip 이 생기지 않고 `<파일명>은 50MB를 초과해 첨부할 수 없습니다.` 가 보인다

### S26: 여러 파일 동시 선택 거부
- Given: `/species/create` 화면
- When: 이미지 2개를 한 번에 올린다
- Then: chip 이 생기지 않고 `대표 사진은 1장만 등록할 수 있습니다.` 가 보인다

### S27: 등록 화면 이탈 보호
- Given: `/species/create` 에서 국명을 입력한 상태
- When: `뒤로가기` 를 클릭한다
- Then: `정말 나가시겠습니까?` 모달이 뜨고, `취소` 를 누르면 화면과 입력이 유지된다

### S28: 수정 화면 무변경 이탈
- Given: `/species/1/edit` 에서 아무것도 바꾸지 않은 상태
- When: `뒤로가기` 를 클릭한다
- Then: 확인 모달 없이 `/species/1` 로 이동한다

### S30: 저장 실패 시 입력 보존
- Given: `/species/1/edit` 에서 국명을 고치고, 다음 수정 요청이 실패하도록 mock 실패를 주입한 상태
- When: `저장하기` 를 클릭한다
- Then: URL 이 `/species/1/edit` 로 유지되고 고친 국명이 남아 있으며 `저장하지 못했습니다. 다시 시도해 주세요.` 가 보인다

### S31: 없는 종 수정 진입
- Given: id `999` 인 종이 없는 상태
- When: `/species/999/edit` 로 진입한다
- Then: `종을 찾을 수 없습니다.` 와 `목록으로 돌아가기` 링크가 보인다

### S33: 수정 화면 사진 제거
- Given: `/species/1/edit` 에서 저장된 사진 chip 이 있는 상태
- When: chip 의 삭제 버튼을 클릭하고 `저장하기` 를 누른다
- Then: `사진을 등록해주세요!` 줄이 보이고, 다른 이미지를 올린 뒤 저장하면 `/species/1` 로 이동한다

### S32: 키보드 조작
- Given: `/species/create` 화면
- When: 키보드만으로 텍스트 입력, 분류군 선택, 법정분류 선택·추가·직접 추가 항목 삭제(확인 모달 포함), 사진 업로드 컨트롤 접근, `생성하기` 를 수행한다
- Then: 모든 조작이 가능하고 포커스 이동 순서가 화면 순서와 같다

## 승인 메모

- 게이트 ② 결정 반영(2026-09-15): 필수값 오류 인라인(개발자 결정), 법정지정분류 기본 목록 선택 + 직접 추가 항목만 X(개발자 결정),
  세부 분류 선택 입력·`설치목 - 천축서과`(개발자 결정), 분류군 기본값 `포유류`, 지연 주입 키 없음.
- **삭제(번호 공백 유지)**:
  - S29(생성 중복 제출 방지) — 저장소 mock 에 지연 주입이 없어 요청 진행 중 상태를 만들 수 없다. 중복 제출 방지는 spec `동작` 에 남기고,
    지연은 `/api` 단계 route mock(`mutationDelayMs`)에서 검증한다.
- **문구 변경(id 유지)**: S1(분류군 `포유류` 선택·기본 선택지 X 없음), S3(기본 선택지), S4(`추가하기` 비활성), S5(X 버튼),
  S7(1페이지 첫 행), S9(세부 분류·사진 파일명), S11~S16(모달 → 인라인 오류 줄), S14(분류군 검증 → 재제출 시 오류 갱신),
  S17(오류 줄 없음), S18(빈 값 비활성), S19(중복 → `이미 있는 분류입니다!`), S21(직접 추가 항목만 제거), S32(직접 추가 항목 제거 포함).
- S11~S16 의 오류 동작(제출 시 전체 검증 · 다음 제출 때 갱신 · 포커스 이동 없음)은 `reservation-form` 기존 패턴이다.
- S7·S17 의 토스트 표시는 `species-list` 가 소유한다. 이 시나리오는 이동 후 결과만 확인한다.
- S30 은 e2e 가짜 서버 실패 주입(`failNext('kind.update')`)이 전제다.
- **API 연동 반영(2026-09-17)**: 법정지정분류 X 는 서버 공용 목록 삭제(개발자 결정)라 삭제 확인 모달을 거친다 — S21·S32 문구 변경.
- 수정 저장 성공 토스트는 넣지 않기로 결정해 시나리오에 없다.
- **버그 수정 반영(2026-09-18, 이슈 #149)**: 사진 chip 에 ✕ 를 채택해 S23(사진 제거)을 복원하고 S33(수정 화면 사진 제거)을 추가했다.
