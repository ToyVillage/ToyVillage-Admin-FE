# Scenario Draft — observation-edit

출처: `harness/publishing/specs/observation-edit.spec.md` (행동명세가 source of truth)

공통 전제: 기준 URL 은 `/species/1/individuals/1/observations/1/edit`(종 1 카피바라 · 개체 1 동식이 · 관찰 1)이다.
관찰 상세 경로는 `/species/1/individuals/1/observations/1` 이다.

## 핵심 시나리오

### S1: 관찰 상세에서 수정 진입
- Given: 관찰 상세 화면(`/species/1/individuals/1/observations/1`)
- When: 제목 행 케밥 메뉴에서 `수정` 을 클릭한다
- Then: `/species/1/individuals/1/observations/1/edit` 로 이동한다

### S2: 개체 상세 관찰 표에서 수정 진입
- Given: 개체 상세 화면(`/species/1/individuals/1`)의 관찰 표
- When: 관찰 1 행의 케밥 메뉴에서 `수정` 을 클릭한다
- Then: `/species/1/individuals/1/observations/1/edit` 로 이동한다

### S3: 헤더 표시
- Given: 기준 URL 로 진입했다
- When: 화면 상단을 확인한다
- Then: `뒤로가기`, 제목 `관찰 및 특이사항`, 부제 `카피바라 · 동식이의 정보를 수정합니다`, `저장하기` 버튼이 보인다

### S4: 기존 값 복원
- Given: 기준 URL 로 진입했다
- When: 폼을 확인한다
- Then: 제목·관찰사항이 관찰 1 의 저장된 값으로 채워져 있고, 날짜는 `2026.06.01`, 관찰자는 `김유영` 이다

### S5: 기존 첨부 표시
- Given: 첨부가 있는 관찰 1 의 수정 화면
- When: `첨부` 카드를 확인한다
- Then: 저장된 첨부 개수만큼 chip 이 보이고, 각 chip 에 `<파일명> 다운로드` / `<파일명> 삭제` 컨트롤이 있다

### S6: 날짜·관찰자 읽기 전용
- Given: 기준 URL 로 진입했다
- When: 날짜 입력과 관찰자 입력에 포커스를 두고 글자를 입력한다
- Then: 두 값이 `2026.06.01` / `김유영` 그대로 바뀌지 않는다

### S7: 제목·관찰사항 수정 저장
- Given: 기준 URL 화면
- When: 제목과 관찰사항을 고치고 `저장하기` 를 클릭한다
- Then: 관찰 상세(`/species/1/individuals/1/observations/1`)로 이동하고 바뀐 제목·관찰사항이 보인다

### S8: 첨부 다운로드
- Given: 첨부 chip 이 보이는 수정 화면
- When: 첫 chip 의 다운로드 컨트롤을 클릭한다
- Then: 그 chip 의 파일명으로 다운로드가 일어난다

### S9: 기존 첨부 제거 저장
- Given: 첨부 chip 이 보이는 수정 화면
- When: 한 chip 의 삭제 컨트롤을 클릭하고 `저장하기` 를 클릭한다
- Then: 클릭 즉시 그 chip 이 사라지고, 저장 후 관찰 상세에서도 그 첨부가 보이지 않는다

### S10: 새 첨부 추가 저장
- Given: 수정 화면
- When: 업로드 드롭존으로 50MB 이하 파일을 추가하고 `저장하기` 를 클릭한다
- Then: 추가 즉시 기존 chip 뒤에 새 chip 이 보이고, 저장 후 관찰 상세에서 그 파일명이 보인다

### S11: 무변경 뒤로가기
- Given: 아무 값도 바꾸지 않은 수정 화면
- When: `뒤로가기` 를 클릭한다
- Then: 확인 모달 없이 관찰 상세로 이동한다

## 엣지 케이스

### S12: 제목 미입력 검증
- Given: 제목을 비우거나 공백만 남긴 상태
- When: `저장하기` 를 클릭한다
- Then: 수정 요청을 보내지 않고 제목 카드 아래에 `제목을 입력해주세요!` 오류 줄이 보인다. 포커스는 옮겨지지 않는다

### S13: 관찰사항 미입력 검증
- Given: 관찰사항을 비운 상태(제목은 채워짐)
- When: `저장하기` 를 클릭한다
- Then: 수정 요청을 보내지 않고 관찰사항 카드 아래에 `관찰사항을 입력해주세요!` 오류 줄이 보인다

### S14: 오류 줄 동시 표시
- Given: 제목과 관찰사항을 모두 비운 상태
- When: `저장하기` 를 클릭한다
- Then: `제목을 입력해주세요!` · `관찰사항을 입력해주세요!` 두 오류 줄이 각 카드 아래에 함께 보인다

### S15: 첨부 전부 제거 후 저장
- Given: 첨부 chip 을 모두 제거한 상태
- When: 화면을 확인한 뒤 `저장하기` 를 클릭한다
- Then: 제거 직후에도 `첨부` 라벨이 남아 있고, 오류 줄 없이 저장되어 관찰 상세로 이동한다

### S16: 50MB 초과 파일
- Given: 수정 화면
- When: 50MB 를 넘는 파일을 업로드 드롭존으로 추가한다
- Then: chip 이 늘지 않고 `<파일명>은 50MB를 초과해 첨부할 수 없습니다.` 오류 문구가 보인다

### S17: 변경 후 뒤로가기 이탈 보호
- Given: 제목을 바꾼 상태
- When: `뒤로가기` 를 클릭한다
- Then: `정말 나가시겠습니까?` 모달이 뜬다. `취소` 를 누르면 모달이 닫히고 바꾼 제목이 유지되며, 다시 `뒤로가기` → `확인` 을 누르면 관찰 상세로 이동한다

### S18: 변경 후 사이드바·브라우저 뒤로가기 이탈 보호
- Given: 관찰사항을 바꾼 상태
- When: 사이드바 `개체관리 > 개체 카드` 로 다른 화면 이동을 시도하거나 브라우저 뒤로가기를 한다
- Then: 같은 `정말 나가시겠습니까?` 모달이 뜨고, `취소` 시 현재 URL 과 입력이 유지된다

### S20: 저장 실패
- Given: 다음 수정 요청이 실패하도록 설정된 상태(e2e 가짜 서버 `failNext('observation.update')`)에서 제목을 바꿨다
- When: `저장하기` 를 클릭한다
- Then: URL 이 그대로이고 바꾼 제목·관찰사항·첨부 chip 이 유지되며 `저장하지 못했습니다. 다시 시도해 주세요.` 가 보인다

### S21: 없는 관찰
- Given: 존재하지 않는 `observationId`, 또는 URL 의 개체·종과 맞지 않는 관찰 id
- When: `…/observations/:observationId/edit` 로 진입한다
- Then: 폼 대신 `관찰 기록을 찾을 수 없습니다.` 와 `개체 상세로 돌아가기` 링크가 보인다

### S22: 키보드 조작
- Given: 기준 URL 화면
- When: 키보드만으로 제목·관찰사항 편집, 첨부 chip 삭제, `파일 업로드` 버튼 활성화, `저장하기` 를 수행한다
- Then: 모든 조작이 가능하고 포커스 순서가 뒤로가기 → 제목 → 날짜 → 관찰자 → 관찰사항 → 첨부 컨트롤 → 파일 업로드 → 저장하기 이며, 포커스 표시가 outline 으로 보인다
