# 로그인 페이지 행동명세

## 목적

토이빌리지 관리자가 아이디와 비밀번호를 입력해 관리자 화면 진입을 시도하는 로그인 화면을 제공한다. 이 퍼블리싱 범위에서는 실제 인증 API를 연결하지 않고, 이후 API 연동에서 교체할 수 있는 제출 경계까지만 구현한다.

## 범위

- 포함: `/login` 라우트, 아이디·비밀번호 입력, 비밀번호 표시 전환, 필수값 검증, 제출 중 중복 방지, 성공·실패 결과를 받을 수 있는 제출 경계
- 제외: 실제 로그인 API, 토큰 발급·저장·갱신, 사용자 권한 조회, 비밀번호 찾기, 회원가입, 소셜 로그인, 인증 가드

## 라우트와 진입

- `/login` 직접 진입 → 로그인 페이지를 표시한다.
- 브라우저 새로고침 후에도 `/login` 라우트가 직접 열려야 한다.
- 로그인 페이지에는 전역 사이드바와 사이드바 토글을 표시하지 않는다.
- 제출 성공 후 이동 목적지는 `/`로 둔다. 실제 인증 API 연동 시 서버 계약과 인증 가드 정책에 맞춰 확정한다.

## 화면 구조

Figma `1830:17172`의 1920×1080 데스크톱 프레임을 시각 기준으로 사용한다.

1. 연한 회색 페이지 배경
2. 좌측 760px 초록 브랜드 패널(장식 도형 6개, `Toy Village Operator`, `동물원의 하루를,\n한 곳에서 관리해요.`, `공지부터 업무 지시, 개체 기록까지\n운영에 필요한 모든 것을 담았습니다.`)
3. 우측 영역 중앙의 흰색 로그인 카드(radius 24px, 그림자)
4. 토이빌리지 로고
5. 제목 `로그인`
6. 안내 문구 `토이빌리지 관리자에 로그인하고\n토이빌리지의 업무들을 관리하세요` (Figma의 `로그인 하고` 띄어쓰기는 맞춤법·승인 e2e에 맞춰 붙여 쓴다)
7. `아이디` 입력 필드
8. `비밀번호` 입력 필드와 표시 전환 버튼
9. 주요 액션 `로그인`(초록 버튼)

- 브랜드 패널의 도형과 문구는 장식이며 보조기술에 노출하지 않는다. 브랜드 문구는 Figma의 Inter 대신 저장소 공통 글꼴(Wanted Sans)을 쓴다.
- yot 프레임에는 `계정 생성하기` 링크가 없으므로 추가하지 않는다.

## 입력 필드

### 아이디

- label: `아이디`
- placeholder: `아이디를 입력해주세요`
- 한 줄 텍스트 입력이며 자동 완성 힌트는 `username`을 사용한다.
- 제출 시 앞뒤 공백을 제거한다.
- 공백 제거 후 빈 문자열이면 입력하지 않은 것으로 판단한다.

### 비밀번호

- label: `비밀번호`
- placeholder: `비밀번호를 입력해주세요`
- 기본 상태에서는 `type="password"`로 값을 가린다.
- 자동 완성 힌트는 `current-password`를 사용한다.
- 비밀번호 값은 공백을 포함해 사용자가 입력한 그대로 제출하며 임의로 정규화하지 않는다.
- 표시 전환 버튼 클릭 → 입력값을 평문으로 표시한다.
- 다시 클릭 → 입력값을 가린다.
- 표시 전환은 입력값과 포커스를 유지한다.

## 동작

### 초기 상태

- 아이디와 비밀번호는 비어 있다.
- 비밀번호는 가려진 상태다.
- 로그인 버튼은 화면에 노출한다.

### 필수값 검증

- 로그인 버튼 클릭 또는 비밀번호 필드에서 Enter 입력 → 아이디, 비밀번호 순서로 검증한다.
- 아이디가 비어 있음 → 제출하지 않고 아이디 입력으로 포커스를 이동하며 필수 입력 오류를 연결한다.
- 비밀번호가 비어 있음 → 제출하지 않고 비밀번호 입력으로 포커스를 이동하며 필수 입력 오류를 연결한다.
- 필수 입력 오류는 입력 아래에 빨간 원형 `!` 표시와 문구로 보여준다: `아이디를 입력해주세요!`, `비밀번호를 입력해주세요!`. 모달은 추가하지 않는다.

### 로그인 제출 경계

- 두 값이 유효함 → `{ username, password }`를 로그인 제출 함수에 한 번 전달한다.
- 제출 중에는 중복 제출을 막기 위해 로그인 버튼을 비활성화하고 진행 상태를 접근 가능한 방식으로 알린다.
- 성공 → `/`로 이동한다.
- 실패 → 현재 페이지와 아이디 입력값을 유지하고, 비밀번호는 보안상 비운 뒤 비밀번호 입력으로 포커스를 이동한다.
- 실패 메시지의 문구와 시각 규격은 API·제품 정책 확인 전 확정하지 않는다.
- 퍼블리싱 단계의 페이지는 실제 HTTP 요청을 만들지 않는다. 제출 함수는 테스트 가능한 임시 mock 경계를 사용하며 API 작업에서 교체한다.

## 데이터와 API 경계

퍼블리싱 단계의 후보 입력 타입은 다음과 같다.

```ts
interface LoginCredentials {
  username: string
  password: string
}
```

- 실제 endpoint, request/response 필드, 토큰 형식과 저장 정책은 API 연동 작업에서 별도 승인한다.
- 현재 `src/shared/api/auth.ts`는 `localStorage.accessToken`이 있으면 공통 Axios 요청에 Bearer 헤더를 추가하지만, 이 퍼블리싱 작업에서는 해당 값을 생성하거나 변경하지 않는다.
- 비밀번호를 localStorage, sessionStorage 또는 전역 상태에 저장하지 않는다.

## 컴포넌트 구조와 소유권

- `LoginPage` (`pages/login`) — 로그인 페이지 레이아웃과 성공 후 이동 조합
- `LoginForm` (`features/login`) — 입력 상태, 필수값 검증, 표시 전환과 제출 상태
- `PasswordVisibilityButton` (`features/login` 내부) — 비밀번호 표시 상태 전환
- 로고와 눈 아이콘 — 기존 에셋을 우선 검색하고 없으면 Figma에서 내려받아 해당 UI 소유 경계에 둔다.
- Figma의 일반 `FRAME`과 `TEXT` 노드는 별도 컴포넌트로 분리하지 않는다.
- 범용 입력 컴포넌트는 실제 재사용 근거가 생기기 전 새 `shared` 추상화로 만들지 않는다.

## 접근성

- 모든 label은 대응하는 input과 프로그램적으로 연결한다.
- 아이디와 비밀번호 input은 각각 `required`와 적절한 `autocomplete` 값을 제공한다.
- 비밀번호 표시 전환은 `button` 요소로 구현하고 상태에 따라 `비밀번호 표시` 또는 `비밀번호 숨기기`라는 접근 가능한 이름을 제공한다.
- 로고가 제품 식별 정보를 전달하면 `alt="토이빌리지"`를 제공하고, 장식 목적의 중복 이미지라면 빈 대체 텍스트를 사용한다.
- 오류는 해당 input과 `aria-describedby`로 연결하고, 오류 상태는 색상에만 의존하지 않는다.
- 기본 키보드 순서는 아이디 → 비밀번호 → 비밀번호 표시 전환 → 로그인이다.
- focus-visible 상태를 명확히 표시한다.

## 반응형

- 1920×1080에서 좌측 760px 브랜드 패널과 우측 영역 중앙의 720×843 카드, 내부 640px 폼 너비를 기준으로 한다.
- 브랜드 패널과 카드가 함께 들어가지 않는 너비(1279px 이하)에서는 브랜드 패널을 숨기고 카드만 가운데 둔다.
- 뷰포트가 카드보다 좁으면 카드와 입력 영역은 좌우 여백을 유지하며 가용 너비로 축소한다.
- 작은 화면에서는 고정 높이 때문에 내용이 잘리지 않도록 최소 높이와 세로 스크롤을 허용한다.
- 모바일 정밀 배치는 Figma 미제공 항목이며 데스크톱 수용 기준을 대체하지 않는다.

## 기능 테스트 수용 기준

- S1: `/login` 직접 진입 → 로고, 제목, 안내 문구, 아이디·비밀번호 입력과 로그인 버튼이 보인다.
- S2: 초기 진입 → 비밀번호 값이 가려져 있다.
- S3: 비밀번호 표시 전환 클릭 → 입력값과 포커스를 유지한 채 표시·숨김 상태가 전환된다.
- S4: 아이디가 빈 상태로 제출 → 제출 함수를 호출하지 않고 아이디 입력으로 포커스가 이동한다.
- S5: 아이디만 입력하고 제출 → 제출 함수를 호출하지 않고 비밀번호 입력으로 포커스가 이동한다.
- S6: 유효한 아이디와 비밀번호로 로그인 버튼 클릭 → 정규화된 아이디와 원본 비밀번호로 제출 함수를 한 번 호출한다.
- S7: 비밀번호 필드에서 Enter 입력 → 로그인 버튼 클릭과 동일하게 제출한다.
- S8: 제출 중 다시 제출 시도 → 중복 제출 함수를 호출하지 않는다.
- S9: 제출 성공 → `/`로 이동한다.
- S10: 제출 실패 → 아이디는 유지하고 비밀번호를 비운 뒤 비밀번호 입력으로 포커스가 이동한다.
- S11: 키보드만 사용 → 두 입력, 표시 전환과 제출을 수행할 수 있다.

## 미결 사항

- 모바일 전용 Figma 프레임

## 비고 / 제약

- 스타일은 Emotion을 사용한다.
- 기존 theme의 `#F5F5F7`, `#848491`, `#C6C6CE`, Wanted Sans를 우선 재사용한다.
- px·spacing·radius 등 화면 한정 구현값은 해당 Emotion 스타일에 직접 작성한다.
- Tailwind 또는 새 form 의존성을 추가하지 않는다.
- 실제 API 연동은 이 퍼블리싱 작업에 포함하지 않는다.
