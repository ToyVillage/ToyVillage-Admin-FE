## 목적

운영 관리자가 직원에게 내릴 새 업무 지시를 작성한다. 우선순위·완료기한을 정하고 팀/개인 단위로 담당자를
고른 뒤 제목·상세 내용을 입력하고 참고 자료를 첨부해 등록한다. 실수로 이탈해도 입력을 잃지 않아야 한다.

## 동작 (behavioral spec — source of truth)

### 진입 기본 상태

- 우선순위는 아무것도 선택되지 않는다.
- 완료기한은 `연도. 월. 일` placeholder 를 보여준다.
- 담당자 트리는 모든 체크박스가 해제(`0/N명`)이고 모든 팀이 접혀 있다.
- 제목은 `제목을 입력해주세요`, 상세 내용은 `상세 업무 내용을 입력해주세요` placeholder 를 보여준다.
- 첨부자료는 비어 있고 업로드 드롭존만 보인다.

### 우선순위

- `상` / `중` / `하` 중 하나 클릭 → 그 항목만 선택 상태가 된다(단일 선택, 토글 해제 없음).

### 완료기한

- 필드 클릭 → 캘린더 오버레이(`1:5799`)가 열린다. 헤더에 `YYYY년 MM월` 과 좌우 이동 chevron 이 있다.
- 날짜를 고르고 `확인` → 오버레이가 닫히고 값이 표시된다. 과거 날짜도 허용한다(비활성 규칙 없음).
- 바깥 클릭 또는 `Esc` → 선택 없이 닫히고 기존 값이 유지된다.

### 담당자 (팀 트리 다중 선택)

- 트리는 `전체 직원` 행 하나와 팀 행 여러 개로 구성된다. 팀 행 아래에 소속 직원 행이 붙는다.
- 각 행의 체크박스는 3상태다 — 해제 / 전체 선택(`on`) / 부분 선택(`mixed`).
  - 팀: 소속 직원이 전부 선택되면 `on`, 일부만 선택되면 `mixed`, 아무도 없으면 해제다.
  - `전체 직원`: 모든 직원이 선택되면 `on`, 일부면 `mixed`, 아무도 없으면 해제다.
- `전체 직원` 체크박스 클릭 → 해제 상태면 모든 직원을 선택하고, 그 외에는 전부 해제한다.
- 팀 체크박스 클릭 → 해제 상태면 그 팀 전원을 선택하고, 그 외에는 그 팀 전원을 해제한다.
- 직원 체크박스 클릭 → 그 직원만 토글한다. 상위 팀과 `전체 직원` 의 상태가 함께 갱신된다.
- 행 우측 카운트는 `선택 인원/전체 인원명` 이다 (`전체 직원` 은 전체 기준, 팀은 그 팀 기준).
- 팀 행의 chevron 클릭 → 그 팀이 펼쳐져 소속 직원 행이 보이고, chevron 이 `>` 에서 `⌄` 로 바뀐다.
  다시 클릭하면 접힌다. **여러 팀을 동시에 펼칠 수 있다.**
- 펼침/접힘은 선택 상태를 바꾸지 않는다. 접어도 선택된 직원은 유지된다.
- **진입 시에는 모든 팀이 접혀 있다**(선택이 복원되는 수정 화면도 같다 — `task-edit` 결정 사항).
- `전체 직원` 행에는 chevron 이 없다.

### 제목·상세 내용

- 텍스트를 입력할 수 있다. 저장 시 앞뒤 공백을 제거한다.

### 첨부

- 업로드 드롭존 클릭 또는 파일 드래그 앤 드롭 → 파일이 첨부자료에 chip 으로 추가된다(다중 가능).
- 첨부 chip 의 제거 컨트롤 클릭 → 해당 첨부가 사라진다.
- 파일 하나가 50MB 를 초과하면 → 첨부하지 않고 오류를 알린다.
- 첨부 추가 성공 → `첨부파일 등록에 성공했습니다` 토스트, 실패 → `첨부파일 등록에 실패했습니다` 토스트.

### 생성

- `생성하기` 클릭 시 필수값이 비어 있으면 → 요청을 보내지 않고 첫 번째 누락 항목의 검증 모달을 띄운다.
  모달의 `확인` 을 누르면 해당 필드로 포커스가 이동한다.
- 모든 필수값이 채워진 상태에서 `생성하기` → 생성 요청을 한 번만 보낸다. 요청 중에는 중복 제출을 막는다.
- 생성 성공 → 업무 목록 query 를 갱신하고 `/tasks` 로 이동한다.
- 생성 실패 → 현재 URL 과 모든 입력을 보존하고 실패를 알린다.

### 이탈 보호

- 입력이 하나라도 있는 상태에서 `뒤로가기` / 사이드바 이동 / 브라우저 뒤로가기 → 이탈 확인 모달을 띄운다.
  제목 `정말 나가시겠습니까?`, 본문 `저장하지 않고 돌아갈 시 입력된 정보가 삭제됩니다`, 버튼 `취소` / `확인`.
- `취소` 또는 `Esc` 는 현재 화면과 입력을 유지하고, `확인` 은 이동한다.
- 생성 성공에 의한 이동은 이탈 확인 대상에서 제외한다.

## 데이터와 API 경계

```ts
interface TaskTeam {
  id: string
  name: string // 동물 관리팀 / 창고팀 / 사육장 청소팀 / 사육팀
}

interface TaskMember {
  id: string
  teamId: string
  name: string // 이승현 — 목록·상세의 담당자 표기
  label: string // 이승현 사원 — 트리 행 표기
}

interface CreateTaskInput {
  priority: TaskPriority // 상 / 중 / 하
  dueDate: string // YYYY-MM-DD
  assigneeIds: string[] // 담당자 (1명 이상)
  title: string
  content: string
  attachments: string[]
}
```

- **`visibility`(공개범위) 필드를 모델에서 제거한다.** yot 폼·목록·상세 어디에도 없다.
- **`assigneeId: string` → `assigneeIds: string[]` 로 바꾼다.** `task-list` 의 `외 N명` 표기가
  지금은 mock 표시값(`additionalAssigneeCount`)인데, 이 전환으로 실제 데이터에서 파생된다.

## 접근성

- 우선순위는 fieldset/legend + radio semantics 를 유지한다(시각은 pill).
- 담당자 트리는 `role="tree"` / `role="treeitem"` + `aria-expanded` / `aria-checked="true|false|mixed"` 로
  3상태와 펼침을 노출한다. 각 행의 접근 가능한 이름에 팀·직원 이름과 카운트를 포함한다.
- 팀 펼침 컨트롤은 키보드로 조작 가능하고 접근 가능한 이름에 팀 이름을 포함한다.
- 제목 input 과 상세 내용 textarea 는 프로그램적 label 과 required 상태를 제공한다.
  **포커스 링은 그리지 않는다**(2026-09-08 개발자 결정 — 카드 안의 큰 텍스트라 테두리가
  튀어 보인다). 캐럿이 포커스 표시를 대신하고, 검증 모달의 포커스 이동은 그대로 동작한다.
- 파일 chip 은 `${파일명} 다운로드`, `${파일명} 삭제` 이름을 제공한다.
- 업로드 드롭존은 키보드로 조작 가능한 `파일 업로드` 버튼이다.
- 검증 모달과 이탈 확인 모달은 modal semantics, 포커스 트랩, 호출 컨트롤 복귀를 제공한다.
- 기본 키보드 순서: 뒤로가기 → 우선순위 → 완료기한 → 제목 → 상세 내용 → 담당자 트리 →
  첨부 컨트롤 → 파일 업로드 → 생성하기.

## 반응형

- 980px 이하에서는 `priority / due row` 를 세로로 쌓고 카드 padding 을 줄인다.
- 우선순위 pill 은 좁은 화면에서 폭을 나눠 쓰고 gap 을 줄인다.
- 담당자 트리 행은 카운트를 라벨 아래로 내려 두 줄로 접는다.
- 가로 스크롤 없이 모든 입력과 모달을 조작할 수 있어야 한다.

## 결정 사항

- 라우트는 `/tasks/create` 로 유지한다.
- **공개범위 필드와 그 검증을 삭제한다**(2026-09-07, yot 근거).
- 검증 순서는 화면 시각 순서(우선순위 → 완료기한 → 제목 → 상세 내용 → 담당자)로 확정한다.
- 완료기한은 과거 날짜를 허용한다. 표시 형식은 공용 `DateField` 의 기존 포맷을 그대로 쓴다
  (구 spec ⑦ 육안 확인에서 수용한 결정 승계).
- 생성 성공 토스트는 목록 화면이 띄운다(`task-list` S21). 이 화면에서는 띄우지 않는다.
- 삭제 버튼은 이 폼에서 빼고 상세 화면 케밥이 맡는다(`task-detail`).
- **우선순위 pill 의 선택색은 Figma 의 회색 채움(`#DDDDE3`) 대신 `accentBg`/`accent` 를 쓴다**
  (2026-09-07 개발자 결정, ⑦ 육안 확인 중). 같은 폼의 담당자 체크박스·상세의 `승인` 배지와
  선택 표현을 하나로 묶기 위해서다. 규격(252×68, radius 800px)과 미선택 색은 Figma 그대로다.
- **제목·상세 내용·첨부자료는 각각 독립 카드다**(2026-09-08 Figma 갱신 반영, `145:12270`).
  세로 간격은 다른 카드와 같은 32px 다. 이전 렌더의 `내용 카드`(한 카드 3단)는 폐기했다.
- **담당자 카드는 상세 업무 내용 아래·첨부자료 위로 내린다**(2026-09-08 Figma 갱신 반영,
  `145:12270` 자식 순서 = priority/due → title → body text → assignee → add file → upload file).
  검증 순서와 키보드 순서도 이 시각 순서를 따라간다.
- 상세 내용 입력의 최소 높이는 Figma 의 한 줄(21px)에 맞추되, 입력이 늘어나면 textarea 높이를
  내용에 맞춰 키운다. Figma 에 여러 줄 상태가 없어 스크롤 대신 카드가 늘어나는 쪽을 택했다.
