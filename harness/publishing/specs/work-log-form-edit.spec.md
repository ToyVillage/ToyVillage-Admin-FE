## 목적

운영 관리자가 이미 등록된 업무일지 양식을 열어 양식명·질문 구성·구역 번호를 고치고 저장한다.

## 범위

- 포함: 기존 값이 채워진 2단계 위저드, 저장, 나가기 확인 모달, 구역 삭제 확인 모달
- 제외: 실제 API 연동(`/api` 스킬 담당), 양식 생성(`work-log-form-create.spec.md`),
  양식 삭제(목록에서 수행), 양식 상세

## 라우트와 진입

- `/work-logs/forms/:id/edit` → 1단계 `항목 설정`
- `/work-logs/forms/:id/edit/zones` → 2단계 `구역 번호 설정`
- 목록(`/work-logs?tab=forms`)의 케밥 메뉴 `수정`으로 진입한다(목록 쪽은 이미 구현되어 있음).
- 생성과 같이 **단계를 URL 로 구분한다**(생성 spec 참고).
- 진입 시 스크롤은 항상 맨 위에서 시작한다.
- 목록에서 삭제된 양식의 id 로 진입하면 → `/work-logs?tab=forms`로 되돌린다
  (상세 spec `work-log-form-detail` 와 같은 규칙).

## 로딩

- 상세를 불러오는 동안에는 **생성 화면과 같은 레이아웃의 빈 폼**을 그대로 보여 준다.
  별도의 로딩 화면·스피너·스켈레톤을 만들지 않는다(Figma 에 없다).
- 값이 도착하면 같은 자리에 채워 넣어 박스가 튀지 않게 한다.

## 동작 (behavioral spec — source of truth)

생성 spec 의 1단계 조작·선택지 규칙·2단계 조작 규칙을 그대로 따른다. 아래는 수정 전용 동작이다.

### 초기 상태

- 1단계 진입 → 스텝 인디케이터 1단계 활성, 기존 양식명과 질문 카드가 정의된 순서대로 채워져 있다.
- 질문 카드의 유형 배지는 저장된 유형을 보여 준다.

### 저장

- 1단계의 `저장하기` 클릭 → 1단계 검증을 먼저 돌린다.
  - 검증 실패 → 생성과 같은 방식으로 카드 테두리·에러 메시지를 표시하고 저장하지 않는다.
  - 검증 통과 → 현재 구역 설정을 그대로 둔 채 저장 요청을 보낸다.
- 2단계의 `저장하기` 클릭 → 구역이 0개면 `구역 번호를 설정해주세요` 모달을 띄우고 저장하지 않는다.
  구역이 1개 이상이면 저장 요청을 보낸다.
- 저장 요청은 한 번만 보내고, 요청 중에는 `저장하기`를 비활성화한다.
- 성공 → `['work-log-forms','list']` 를 무효화하고 `/work-logs?tab=forms`로 이동한다.
  상세 쿼리(`['work-log-forms','detail',id]`)도 해당 id 만 무효화한다.
- 실패 → 입력값과 현재 단계를 유지하고 다시 시도할 수 있게 한다.

### 다음

- 1단계의 `다음` 클릭 → 생성과 같은 검증 후 2단계로 전환한다.

### 나가기 확인 (`1:5016`)

- **입력값이 처음 불러온 값에서 바뀌어 있으면** 이 화면을 벗어나는 모든 이동에 나가기 확인 모달을 띄운다.
  `뒤로가기` 링크뿐 아니라 브라우저 뒤로가기·앞으로가기, 새로고침도 포함한다.
  - 제목 `정말 나가시겠습니까?`
  - 설명 `저장하지 않고 돌아갈 시 입력된 정보가 삭제됩니다`
  - 버튼 `취소` / `확인`
  - `확인` → 변경을 버리고 이동한다. 1단계면 `/work-logs?tab=forms`, 2단계면 1단계로 돌아간다.
  - `취소` → 모달만 닫는다.
- 바뀐 값이 없으면 모달 없이 바로 이동한다.
- 저장 성공으로 이동할 때는 모달을 띄우지 않는다.

### 구역 삭제 확인 (`1:5091`)

- 2단계에서 이미 저장되어 있던 구역을 칩의 X 로 지울 때 삭제 확인 모달을 띄운다.
- `전체 삭제`는 저장 여부와 무관하게 항상 확인 모달을 띄운다(생성 화면과 같은 규칙).
  - 아이콘 + 제목 `정말 삭제하시겠습니까?`
  - 설명 `삭제하신 뒤에는 영구삭제되며 복구 할 수 없습니다`
  - 버튼 `취소` / `확인`
  - `확인` → 해당 구역(또는 전체)을 목록에서 지운다. `취소` → 아무것도 지우지 않는다.
- 이번 편집 세션에서 방금 추가한 구역은 확인 없이 바로 지운다.

## 기능 테스트 수용 기준

- S1: `/work-logs/forms/:id/edit` 진입 → 스텝 인디케이터(1단계 활성), 기존 양식명과 질문 카드,
  `다음`, `저장하기`가 보인다.
- S2: 질문 카드에 저장된 유형 배지와 선택지가 그대로 보인다.
- S3: 값을 바꾸지 않고 `뒤로가기` 클릭 → 모달 없이 `/work-logs?tab=forms`로 이동한다.
- S4: 양식명을 고친 뒤 `뒤로가기` 클릭 → `정말 나가시겠습니까?` 모달이 보인다.
- S5: 나가기 모달의 `취소` 클릭 → 모달이 닫히고 화면과 입력값이 유지된다.
- S6: 나가기 모달의 `확인` 클릭 → `/work-logs?tab=forms`로 이동한다.
- S7: 양식명을 비우고 `저장하기` 클릭 → `양식명을 입력해주세요!`가 보이고 저장되지 않는다.
- S8: 1단계에서 `다음` 클릭 → 2단계가 보이고 저장된 구역이 칩으로 채워져 있다.
- S9: 저장되어 있던 칩의 X 클릭 → `정말 삭제하시겠습니까?` 모달이 보인다.
- S10: 삭제 모달의 `취소` 클릭 → 칩이 그대로 남는다. `확인` 클릭 → 칩이 사라진다.
- S11: 이번 편집에서 방금 추가한 칩의 X 클릭 → 모달 없이 바로 사라진다.
- S12: 구역을 모두 지운 상태로 `저장하기` 클릭 → `구역 번호를 설정해주세요` 모달이 보이고 저장되지 않는다.
- S13: 유효한 상태로 `저장하기` 클릭 → 저장 요청이 한 번 전송되고 `/work-logs?tab=forms`로 이동한다.
- S14: 저장 실패 → 입력값과 현재 단계가 유지되고 다시 저장할 수 있다.
- S15: 삭제된 양식의 id 로 진입 → `/work-logs?tab=forms`로 되돌아간다.
- S16: 키보드만 사용 → 값 수정, 단계 이동, 모달 확인·취소, 저장을 수행할 수 있다.
- S18: 값을 고친 뒤 브라우저 뒤로가기 → `정말 나가시겠습니까?` 모달이 뜬다.
