업무관리(`/tasks`)와 업무일지관리(`/work-logs`)는 별개 네임스페이스다.

## 목적

운영 관리자가 특정 날짜에 직원들이 작성한 업무일지를 조회하고, 일지 작성에 쓰이는 양식을 관리한다.
조회날짜(년·월·일)로 범위를 좁히고, 두 탭(작성된 일지 / 양식 관리)을 오가며 목록을 훑는다.

## 범위

- 포함: 두 탭의 목록 조회, 조회날짜 필터, 페이지네이션, 행 클릭 이동, 케밥 메뉴, 삭제 확인 모달,
  빈 상태, 삭제 결과 토스트, 사이드바 항목 라우트 연결
- 제외: 실제 API 연동(`/api` 스킬 담당), 업무일지 상세 화면, 양식 생성·수정 화면,
  검색·정렬, 다중 선택

## 라우트와 진입

- `/work-logs` → 업무일지관리 목록을 표시한다. 기본 탭은 `작성된 일지`다.
- 탭 상태는 쿼리스트링으로 유지한다: `?tab=logs`(작성된 일지) / `?tab=forms`(양식 관리).
  `tab` 파라미터가 없거나 알 수 없는 값이면 `logs` 로 간주한다.
- `양식 생성하기` 클릭 → `/work-logs/forms/create` 로 이동한다. (해당 화면은 이 spec 범위 밖)
- `작성된 일지` 행 클릭 → `/work-logs/:id` 로 이동한다. (해당 화면은 이 spec 범위 밖)
- `양식 관리` 행 클릭 → `/work-logs/forms/:id` (양식 상세)로 이동한다.
  상세 화면 계약은 `harness/publishing/specs/work-log-form-detail.spec.md` 를 따른다.
- `양식 관리` 케밥의 `수정` 클릭 → `/work-logs/forms/:id/edit` 로 이동한다. (해당 화면은 이 spec 범위 밖)
- 사이드바 `업무일지관리 바로가기` 항목의 이동 대상을 `/work-logs` 로 지정한다.
  사이드바 자체의 동작 계약은 `harness/publishing/specs/sidebar.spec.md` 를 따르며 이 spec 은 `to` 지정만 한다.

## 동작 (behavioral spec — source of truth)

### 공통

- 화면 진입 → 제목 `업무일지관리`, 부제 `토이빌리지의 업무일지관리`, 우상단 `양식 생성하기` 버튼,
  `조회날짜` 필터, `작성된 일지` 탭 활성, 1페이지 목록이 보인다.
- 조회날짜의 초기값은 오늘 날짜(년·월·일)다.
- `조회날짜`의 년/월/일 각 드롭다운 클릭 → 해당 드롭다운이 열리고 선택지 목록이 보인다.
  다른 드롭다운을 열면 앞서 열린 드롭다운은 닫힌다.
- 드롭다운의 항목 클릭 → 그 값이 선택되고 드롭다운이 닫히며, 목록이 선택 날짜 기준으로 다시 걸러지고
  1페이지로 리셋된다. 선택된 항목은 진한 글자(`colors.textStrong`), 나머지는 흐린 글자로 표시한다.
- 드롭다운이 열린 상태에서 바깥을 클릭하거나 `Escape` → 드롭다운이 닫히고 선택은 바뀌지 않는다.
- 년 선택지는 현재 연도 기준 최근 5개 연도(내림차순), 월은 1~12월, 일은 선택된 년·월의 실제 일수만큼이다.
  년 또는 월을 바꿔 선택된 일이 그 달에 없으면(예: 1월 31일 → 2월) 일은 그 달의 마지막 날로 보정한다.
- 탭 클릭 → 해당 탭의 목록으로 바뀌고 1페이지로 리셋되며, URL의 `tab` 파라미터가 갱신된다.
  조회날짜 선택값은 탭을 바꿔도 유지된다.
- 페이지 번호 클릭 → 해당 페이지의 행으로 목록이 바뀐다. 한 페이지는 4행이다.
- `이전 페이지` / `다음 페이지` 클릭 → 한 페이지씩 이동한다. 1페이지에서 `이전 페이지`,
  마지막 페이지에서 `다음 페이지`는 비활성이다.
- 케밥 버튼 클릭 → 그 행의 케밥 메뉴가 열린다. 다른 행의 케밥을 누르면 앞서 열린 메뉴는 닫힌다.
  같은 행의 케밥을 다시 누르면 닫힌다. 바깥 클릭이나 `Escape` 로도 닫힌다.
- 케밥 메뉴의 `삭제` 클릭 → 메뉴가 닫히고 삭제 확인 모달(`정말 삭제하시겠습니까?`)이 열린다.
- 삭제 확인 모달에서 `취소` 클릭 → 모달이 닫히고 목록은 그대로다.
- 삭제 확인 모달에서 `확인` 클릭 → 해당 행이 목록에서 사라지고 모달이 닫히며,
  우상단에 `데이터 삭제에 성공했습니다` 토스트가 뜬다.
- 삭제로 현재 페이지가 비면 → 직전 페이지로 이동한다(1페이지면 그대로 빈 상태를 보여준다).

### 작성된 일지 탭 (`?tab=logs`)

- 표의 열은 `작성자` / `양식` / `날짜` 와 케밥 열이다.
- 행 클릭 → 해당 일지의 `/work-logs/:id` 로 이동한다.
  케밥 버튼과 케밥 메뉴를 클릭할 때는 행 이동이 일어나지 않는다.
- 케밥 메뉴 항목은 `삭제` 하나뿐이다.
- 선택한 조회날짜에 작성된 일지가 없으면 → 행 대신 `해당 날짜에 작성된 업무일지가 없습니다.` 를
  표시하고 페이지네이션을 숨긴다.

### 양식 관리 탭 (`?tab=forms`)

- 표의 열은 `양식` / `작성자` / `날짜` 와 케밥 열이다.
- 양식 목록은 조회날짜의 영향을 받지 않는다(양식은 날짜에 종속되지 않는다).
- 행 클릭 → 해당 양식의 `/work-logs/forms/:id` 로 이동한다.
  케밥 버튼과 케밥 메뉴를 클릭할 때는 행 이동이 일어나지 않는다.
- 케밥 메뉴 항목은 `수정`, `삭제` 두 개다. `수정` 클릭 → `/work-logs/forms/:id/edit` 로 이동한다.
- 등록된 양식이 없으면 → 행 대신 `등록된 양식이 없습니다.` 를 표시하고 페이지네이션을 숨긴다.

## 비고 / 제약

- Figma `form list table` 의 `항목`(600~760) 열은 헤더 텍스트도 셀 내용도 비어 있는 미사용 열이다.
  `양식` 열을 760px 로 합쳐 구현하고 별도 열로 만들지 않는다.
- `작성된 일지` 표의 케밥 열(80px)은 헤더 텍스트가 없다. empty 상태(`1:3509`)에는 케밥 열 자체가 없다.
- 조회날짜 드롭다운의 스크롤 막대(`Frame 456`)는 네이티브 오버플로 스크롤로 구현하고 별도 요소를 만들지 않는다.
- 신규 색 후보: `#9999A5`(gray/50 — 드롭다운 비선택 항목 텍스트). 중간 게이트에서 이름을 확정한다.
- 이 spec 은 목록 화면만 다룬다. 이동 대상 화면 중 일지 상세(`work-log-detail`)와
  양식 상세(`work-log-form-detail`)는 각자의 spec 이 담당하고, 양식 생성·수정은 아직 라우트만 연결한다.
