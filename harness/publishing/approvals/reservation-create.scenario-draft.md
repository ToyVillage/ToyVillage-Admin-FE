# Scenario Draft — reservation-create

출처: `harness/publishing/specs/reservation-create.spec.md` (행동명세가 source of truth)
상태: draft (2026-09-20 개편 확인 — 폼 구조 불변, 토스트 시나리오 S10 추가로 재승인 필요)

## 핵심 시나리오
### S1: 생성 폼 표시
- Given: `/notices/reservations/create` 진입
- When: 화면 렌더
- Then: `뒤로가기`, 4개 섹션 헤더(상담일/방문일/사전답사/페이지 권한), 필수 라벨(`단체명 *` 등), `생성하기` 버튼이 보인다. 초기 인풋은 플레이스홀더.

### S2: 섹션 접기/펼치기
- Given: 생성 폼
- When: `상담일 관련` 헤더 chevron 클릭
- Then: 해당 섹션 필드가 접히고, 접힌 헤더에 상태 배지(미완료/완료)가 보인다. 다시 클릭하면 펼쳐진다.

### S3: 필수 미입력 검증(인라인)
- Given: 빈 생성 폼
- When: `생성하기` 클릭
- Then: 빈 필수 텍스트/숫자 필드 하단에 `내용을 입력해주세요!`, date에 `날짜를 선택해주세요!`, time에 `시간을 입력해주세요!`가 빨강으로 표시되고 목록 이동은 일어나지 않는다.

### S4: 정상 생성
- Given: 모든 필수값 입력
- When: `생성하기` 클릭
- Then: 생성 요청이 나가고 `/notices/reservations`로 이동한다.

## 엣지/상호작용
### S5: 시간 직접 입력(24시간제)
- Given: 방문 시간 필드(입장·퇴장이 한 박스, 드롭다운·am/pm 없음)
- When: 입장시간 칸에 `2230`을 입력하고, 퇴장시간 칸에 `9`를 입력한다
- Then: 입장은 `22 : 30`, 퇴장은 `09 : 00`으로 보인다. Backspace 로 분을 지우면 `00`으로 돌아간다.

### S6: 페이지 권한 배정 추가/취소
- Given: 페이지 권한 섹션(배정팀 비어있음)
- When: 배정가능 직원의 `추가하기` 클릭 → 이후 배정팀 직원의 `취소하기` 클릭
- Then: 추가 시 배정팀에 나타나고 배정가능에서 빠지며, 취소 시 원복된다.

### S7: 뒤로가기
- Given: 생성 폼
- When: `뒤로가기` 클릭
- Then: `/notices/reservations`로 이동한다.

### S9: 퇴장이 입장보다 빠르면 인라인 에러
- Given: 방문 시간 입장 `14 : 00`, 퇴장 `09 : 00`
- When: `생성하기` 클릭
- Then: 해당 시간 필드가 빨간 테두리가 되고 아래에 `퇴장 시간은 입장 시간보다 빠를 수 없습니다.` 가 보이며, 생성 요청은 나가지 않는다.

### S8: 한 자리만 입력해도 보이는 값으로 제출
- Given: 모든 필수값이 채워진 폼에서 방문 입장시간을 `1` 한 자리만 입력(화면은 `10 : 00`)
- When: `생성하기` 클릭
- Then: 시간 인라인 에러 없이 생성되고, 요청 바디의 `visitTime`이 화면과 같은 `10:00`으로 전송된다.

### S10: 생성 결과 토스트
- Given: 모든 필수값이 채워진 폼
- When: `생성하기` 클릭 후 생성이 성공한다
- Then: 목록으로 이동하며 `데이터 생성에 성공했습니다` 토스트가 뜬다
- And: 생성 요청이 실패하면 목록으로 이동하지 않고 `데이터 생성에 실패했습니다` 토스트가 뜬다
