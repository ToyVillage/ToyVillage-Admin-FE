## 핵심 시나리오

### S1: 목록 진입 기본 상태
- Given: 업무관리 목록 라우트 `/tasks`
- When: 화면에 진입한다
- Then: 제목 `업무관리`와 부제 `토이빌리지 업무 지시`가 보이고, `전체 업무` 탭이 활성이며, 1페이지 10행이 표시된다

### S2: 업무 등록하기 이동
- Given: `/tasks` 화면
- When: `업무 등록하기` 버튼을 클릭한다
- Then: `/tasks/create` 로 이동한다

### S3: `진행중` 탭 필터
- Given: `/tasks` 화면, `전체 업무` 탭 활성
- When: `진행중` 탭을 클릭한다
- Then: `진행중` 탭이 활성이 되고 상태가 `진행중`인 행만 남는다

### S4: `완료` 탭 필터
- Given: `/tasks` 화면
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭이 활성이 되고 상태가 `완료`인 행만 남는다

### S24: `지연` 탭 필터
- Given: `/tasks` 화면
- When: `지연` 탭을 클릭한다
- Then: `지연` 탭이 활성이 되고, 완료되지 않고 완료기한이 지난 행만 남는다

### S5: 행 본문 클릭 → 상세 이동
- Given: `/tasks` 화면
- When: 행의 본문 영역(케밥 버튼 밖)을 클릭한다
- Then: 해당 업무의 `/tasks/:id`(읽기 전용 상세)로 이동한다

### S6: 페이지네이션 이동
- Given: `/tasks` 화면, 결과가 한 페이지(10건)를 초과해 페이지 버튼이 보임
- When: `2 페이지` 버튼을 클릭한다
- Then: 2페이지의 행으로 목록이 바뀐다

### S11: 컬럼 구성 확인
- Given: `/tasks` 화면
- When: 테이블 헤더를 확인한다
- Then: `담당자` `제목` `상태` `우선순위` `완료기한` 5개 컬럼이 순서대로 보이고, `공개범위` 컬럼은 없다

### S12: 담당자 다중 표기
- Given: `/tasks` 화면, 담당자가 여럿인 업무와 1명인 업무가 섞여 있음
- When: 담당자 셀을 확인한다
- Then: 담당자가 여럿인 행은 `이승현 외 5명` 형태로, 1명인 행은 `김수인` 처럼 이름만 보인다

### S13: 케밥 메뉴 열기
- Given: `/tasks` 화면
- When: 행 우측 끝 `⋮` 버튼을 클릭한다
- Then: 그 행의 메뉴가 열려 `수정` / `삭제` 두 항목이 보이고, 행 클릭 이동은 일어나지 않는다

### S14: 케밥 메뉴는 하나만 열린다
- Given: `/tasks` 화면, 1행의 케밥 메뉴가 열려 있음
- When: 2행의 `⋮` 버튼을 클릭한다
- Then: 1행 메뉴가 닫히고 2행 메뉴만 열려 있다

### S15: 케밥 메뉴 닫기
- Given: `/tasks` 화면, 케밥 메뉴가 열려 있음
- When: 메뉴 바깥을 클릭하거나 `Escape` 를 누른다
- Then: 메뉴가 닫히고 초점이 해당 `⋮` 버튼으로 돌아온다

### S16: 케밥 `수정` → 수정 폼 이동
- Given: `/tasks` 화면, 케밥 메뉴가 열려 있음
- When: `수정` 을 클릭한다
- Then: 메뉴가 닫히고 해당 업무의 `/tasks/:id/edit` 로 이동한다

### S17: 케밥 `삭제` → 확인 모달
- Given: `/tasks` 화면, 케밥 메뉴가 열려 있음
- When: `삭제` 를 클릭한다
- Then: 메뉴가 닫히고 `정말 삭제하시겠습니까?` 확인 모달이 열린다

### S18: 삭제 취소
- Given: 삭제 확인 모달이 열려 있음
- When: `취소` 를 클릭하거나 `Escape` 를 누른다
- Then: 모달이 닫히고 해당 행이 목록에 그대로 남는다

### S19: 삭제 확인 → 성공 토스트
- Given: 삭제 확인 모달이 열려 있음
- When: `확인` 을 클릭한다
- Then: 해당 행이 목록에서 사라지고 우상단에 `데이터 삭제에 성공했습니다` 토스트가 표시된 뒤 사라진다

## 엣지 케이스

### S7: 페이지네이션 경계 비활성
- Given: `/tasks` 화면, 목록 1페이지를 보는 중
- When: 페이지네이션을 확인한다
- Then: `이전 페이지` 버튼이 비활성이고, 마지막 페이지에서는 `다음 페이지` 버튼이 비활성이다

### S8: 탭 전환 시 1페이지로 리셋
- Given: `/tasks` 화면에서 2페이지를 보는 중
- When: 다른 탭으로 전환한다
- Then: 목록이 다시 1페이지부터 표시된다

### S9: 결과 없음 → 빈 상태
- Given: `/tasks` 화면
- When: 결과가 없는 탭으로 전환한다
- Then: 행이 사라지고 `등록된 업무가 없습니다.` 가 표시되며 페이지네이션이 보이지 않는다

### S10: 완료기한 초과 표시
- Given: `/tasks` 화면, 완료기한이 오늘보다 이전인 업무가 있음
- When: 목록을 확인한다
- Then: 상태와 무관하게 해당 행의 완료기한 셀이 위험색으로 표시된다

### S20: 삭제 실패 토스트
- Given: 삭제 확인 모달에서 `확인` 을 눌렀고 삭제가 실패하는 조건
- When: 실패 응답이 도착한다
- Then: 모달이 닫히고 `데이터 삭제에 실패했습니다` 토스트가 표시되며 해당 행은 목록에 남는다

### S21: 생성 성공 토스트
- Given: `/tasks/create` 에서 업무 생성에 성공해 `/tasks` 로 돌아온 상태
- When: 목록 화면이 렌더된다
- Then: 우상단에 `데이터 생성에 성공했습니다` 토스트가 표시되고 일정 시간 후 사라진다

### S22: 키보드 조작
- Given: `/tasks` 화면
- When: 키보드만으로 탭 전환·페이지 이동·행 진입·케밥 메뉴 조작을 시도한다
- Then: 모든 조작이 가능하고 포커스 표시가 outline 으로 보인다

### S23: 사이드바 `업무관리` 메뉴 이동
- Given: 임의의 화면에서 사이드바를 연 상태
- When: `업무 관리 바로가기` 메뉴 항목을 클릭한다
- Then: `/tasks` 로 이동하고 사이드바가 닫힌다

## 승인 메모

- **S12 는 표시만 검증한다.** `Task.assigneeId: string` → `assignees[]` 모델 전환은 `task-create` ·
  `task-edit` · 업무보고서 · API 계약에 함께 번지므로 이번 슬라이스 밖이다. mock 에 표시용 필드를
  더해 `외 N명` 렌더만 확인하고, 모델 전환은 해당 spec 갱신 때 한다.
- **우선순위·상태 배지 시나리오는 넣지 않았다.** 새 Figma 는 우선순위 배지를 36×36 원 → 42×40 pill 로
  바꾸고 색을 재배정했는데(`상` 빨강, `하` 회색), `TaskPriorityBadge` / `TaskStatusBadge` 는
  `task-report` 의 `TaskReportTable` · `TaskReportMetaRow` 와 공유한다. yot 의 `업무보고 · 목록`(`1:3510`)이
  같은 배지를 쓰는지 확인한 뒤 전역 변경할지 업무 전용으로 뗄지 정한다. 그때 시나리오를 추가한다.
- **S9 빈 상태 문구는 Figma 근거가 없다.** yot `업무관리 · 목록` 에 빈 상태 프레임이 없어
  구 결정(`등록된 업무가 없습니다.`)을 승계했다.
- S10 은 상태와 무관하게 "완료기한이 오늘 이전"으로만 판정한다(구 결정 승계).
- S17~S19 의 확인 모달은 기존 `src/shared/ui/DeleteConfirmationDialog` 를 재사용한다.
- 케밥 메뉴 컴포넌트는 우선 `src/features` 에 두고 `src/shared/ui` 승격은 보류한다.
- **2026-09-07 재승인 사유**: `업무관리 · 상세`(`133:9725`) 화면이 추가되면서 `/tasks/:id` 가 상세가 되고
  수정이 `/tasks/:id/edit` 로 내려간다. S16 의 이동 대상이 그에 따라 바뀌었다(개발자 결정).
  S5 는 경로가 그대로지만 도착 화면의 성격이 상세로 바뀐다.
- 승인 시 기존 `tests/e2e/task-list.spec.ts` 는 S11 때문에 반드시 다시 변환해야 한다
  (현재 91행이 `공개범위` 컬럼을 단언한다). 변환 후 `node scripts/approve.mjs task-list --freeze` 로 재동결한다.
