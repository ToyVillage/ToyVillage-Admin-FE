# Scenario Draft — task-list

출처: `harness/publishing/specs/task-list.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 목록 진입 기본 상태
- Given: 업무관리 목록 라우트 `/tasks`
- When: 화면에 진입한다
- Then: 제목 `업무관리`와 부제 `토이빌리지 업무 지시`가 보이고, `전체 업무` 탭이 활성이며, 1페이지 행이 표시된다

### S2: 업무 등록하기 이동
- Given: `/tasks` 화면
- When: `업무 등록하기` 버튼을 클릭한다
- Then: `/tasks/create` 로 이동한다

### S3: `진행중` 탭 필터
- Given: `/tasks` 화면, `전체 업무` 탭 활성
- When: `진행중` 탭을 클릭한다
- Then: `진행중` 탭이 활성이 되고 상태가 `진행중`인 행만 남는다

### S4: `완료` 탭 필터
- Given: `/tasks` 화면
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭이 활성이 되고 상태가 `완료`인 행만 남는다

### S5: `전체 업무` 탭으로 복귀
- Given: `/tasks` 화면, `완료` 탭 활성
- When: `전체 업무` 탭을 클릭한다
- Then: 모든 상태의 행이 다시 보인다

### S6: 행 클릭 → 수정 화면 이동
- Given: `/tasks` 화면
- When: 목록의 행을 클릭한다
- Then: 해당 업무의 `/tasks/:id` 로 이동한다

### S7: 페이지네이션 이동
- Given: `/tasks` 화면, 결과가 한 페이지(4건)를 초과해 페이지 버튼이 보임
- When: `2 페이지` 버튼을 클릭한다
- Then: 2페이지의 행으로 목록이 바뀐다

### S8: 컬럼 표시 확인
- Given: `/tasks` 화면
- When: 테이블 헤더를 확인한다
- Then: `담당자` `제목` `상태` `우선순위` `완료기한` `공개범위` 6개 컬럼이 순서대로 보인다

### S9: 상태·우선순위 배지 표시
- Given: `/tasks` 화면, `전체 업무` 탭
- When: 목록의 행을 확인한다
- Then: 각 행에 상태 pill(`진행중`/`완료`/`반려`)과 우선순위 배지(`상`/`중`/`하`)가 텍스트로 표시된다

## 엣지 케이스

### S10: 결과 없음 → 빈 상태
- Given: `/tasks` 화면
- When: 결과가 없는 탭으로 전환한다
- Then: 행이 사라지고 `등록된 업무가 없습니다.` 가 표시되며 페이지네이션이 보이지 않는다

### S11: 탭 전환 시 1페이지로 리셋
- Given: `/tasks` 화면에서 2페이지를 보는 중
- When: 다른 탭으로 전환한다
- Then: 목록이 다시 1페이지부터 표시된다

### S12: 페이지네이션 경계 비활성
- Given: `/tasks` 화면, 목록 1페이지를 보는 중
- When: 페이지네이션을 확인한다
- Then: `이전 페이지` 버튼이 비활성이고, 마지막 페이지에서는 `다음 페이지` 버튼이 비활성이다

### S13: 완료기한 초과 표시
- Given: `/tasks` 화면, 완료기한이 오늘보다 이전인 업무가 있음
- When: 목록을 확인한다
- Then: 상태와 무관하게 해당 행의 완료기한 셀이 위험색으로 표시된다

### S14: 삭제 성공 토스트 표시
- Given: 수정 화면에서 삭제에 성공해 `/tasks` 로 돌아온 상태
- When: 목록 화면이 렌더된다
- Then: 우상단에 `데이터 삭제에 성공했습니다` 토스트가 표시되고 일정 시간 후 사라진다

### S15: 삭제 실패 토스트 표시
- Given: 업무 삭제가 실패한 상태로 `/tasks` 목록에 토스트 조건이 전달된 경우
- When: 목록 화면이 렌더된다
- Then: 우상단에 `데이터 삭제에 실패했습니다` 토스트가 표시된다

### S16: 키보드 조작
- Given: `/tasks` 화면
- When: 키보드만으로 탭 전환·페이지 이동·행 진입을 시도한다
- Then: 모든 조작이 가능하고 포커스 표시가 outline 으로 보인다

### S17: 사이드바 `업무관리` 메뉴 이동
- Given: 임의의 화면에서 사이드바를 연 상태
- When: `업무관리 바로가기` 메뉴 항목을 클릭한다
- Then: `/tasks` 로 이동하고 사이드바가 닫힌다

## 승인 메모

- 라우트는 `/tasks`, `/tasks/create`, `/tasks/:id` 로 확정했다.
- S10 의 빈 상태 문구는 `등록된 업무가 없습니다.` 로 확정했다.
- S13 은 상태와 무관하게 "완료기한이 오늘 이전"으로만 판정한다.
- S14·S15 는 `task-edit` 구현 이후에 검증 가능하다. e2e 변환 시 mock 진입 경로를 사용한다.
- S9 의 `반려` 기준 프레임은 `3056:2599` 다(`3085:2924` 사본은 pill 텍스트 누락).
- S17 은 사이드바에 `업무관리 바로가기` 항목을 추가하는 것을 전제로 한다.
