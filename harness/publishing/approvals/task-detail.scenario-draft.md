# Scenario Draft — task-detail

출처: `harness/publishing/specs/task-detail.spec.md` (행동명세가 source of truth)

## 핵심 시나리오

### S1: 상세 진입 기본 상태
- Given: 업무 상세 라우트 `/tasks/:id`
- When: 화면에 진입한다
- Then: 요약행(담당자·상태·우선순위·완료기한)과 제목·상세 내용이 보인다

### S2: 담당자 표기
- Given: 담당자가 여럿인 업무와 1명인 업무
- When: 요약행의 담당자를 확인한다
- Then: 여럿이면 `이승현 외 3명`, 1명이면 이름만 보인다

### S3: 첨부 다운로드 표시
- Given: 첨부가 있는 업무의 상세
- When: 첨부자료를 확인한다
- Then: 첨부 수만큼 chip 이 보이고 각 chip 에 다운로드 버튼이 있다

### S5: 업무보고 목록
- Given: 업무보고가 제출된 업무의 상세
- When: 업무 보고 카드를 확인한다
- Then: 담당자별 항목과 심사 상태 배지가 보인다

### S6: 업무보고 상세 진입
- Given: 업무 보고 카드
- When: 항목을 클릭한다
- Then: `/task-reports/:reportId` 로 이동한다

### S10: 케밥 메뉴 열기
- Given: `/tasks/:id` 화면
- When: 우상단 `⋮` 를 클릭한다
- Then: `수정` / `삭제` 두 항목이 보인다

### S12: 케밥 수정 → 편집 이동
- Given: 케밥 메뉴가 열려 있음
- When: `수정` 을 클릭한다
- Then: `/tasks/:id/edit` 로 이동한다

### S13: 케밥 삭제 → 확인 모달
- Given: 케밥 메뉴가 열려 있음
- When: `삭제` 를 클릭한다
- Then: `정말 삭제하시겠습니까?` 확인 모달이 열린다

### S15: 삭제 확인 → 목록 이동
- Given: 삭제 확인 모달이 열려 있음
- When: `확인` 을 클릭한다
- Then: `/tasks` 로 이동하고 `데이터 삭제에 성공했습니다` 토스트가 뜬다

## 엣지 케이스

### S4: 첨부 없음
- Given: 첨부가 없는 업무
- When: 상세에 진입한다
- Then: 첨부자료 카드가 보이지 않는다

### S7: 진행도 요약
- Given: 업무보고가 여러 건인 업무의 상세
- When: 진행도 카드를 확인한다
- Then: `전체 N · 승인 N · 반려 N · 심사대기 N` 이 실제 건수와 일치하고, `재제출` 건은 `심사대기` 에 합산돼 있다

### S8: 업무보고 없음
- Given: 업무보고가 없는 업무
- When: 상세에 진입한다
- Then: 빈 문구가 보이고 진행도 카드가 사라진다

### S9: 뒤로가기
- Given: `/tasks/:id` 화면
- When: `뒤로가기` 를 클릭한다
- Then: 확인 없이 `/tasks` 로 이동한다

### S11: 케밥 닫기
- Given: 케밥 메뉴가 열려 있음
- When: 메뉴 바깥을 클릭하거나 `Escape` 를 누른다
- Then: 메뉴가 닫히고 초점이 `⋮` 로 돌아온다

### S14: 삭제 취소
- Given: 삭제 확인 모달이 열려 있음
- When: `취소` 를 클릭한다
- Then: 모달이 닫히고 상세 화면이 그대로 남는다

### S16: 삭제 실패
- Given: 삭제가 실패하는 조건
- When: 모달에서 `확인` 을 클릭한다
- Then: 상세 화면에 `데이터 삭제에 실패했습니다` 토스트가 뜨고 화면이 유지된다

### S17: 없는 업무
- Given: 존재하지 않는 id
- When: `/tasks/:id` 로 진입한다
- Then: `업무를 찾을 수 없습니다.` 와 목록 복귀 링크가 보인다

### S18: 완료기한 위험색 미적용
- Given: 완료기한이 오늘보다 이전인 업무
- When: 상세 요약행의 완료기한을 확인한다
- Then: 목록과 달리 위험색이 아니라 기본 글자색이다

### S19: 키보드 조작
- Given: `/tasks/:id` 화면
- When: 키보드만으로 케밥 열기·항목 실행·업무보고 진입을 시도한다
- Then: 모든 조작이 가능하고 포커스 표시가 outline 으로 보인다

## 승인 메모

- **신규 spec 이다.** yot 의 `업무관리 · 상세`(`133:9725`)는 저장소에 대응 화면이 없다.
- `/tasks/:id` 를 상세로 가져가고 수정을 `/tasks/:id/edit` 로 내리는 결정에 따른 것이다(2026-09-07).
  이 결정으로 **`task-list` 의 승인 시나리오 S16 도 함께 바뀌어 재승인이 필요하다.**
- S13~S16 삭제 시나리오는 `task-edit` 에서 이관해 온 것이다. 문구·모달은 목록과 동일하게 재사용한다.
- S18 은 목록(`task-list` S10)과 반대 규칙임을 못박는 시나리오다. Figma 상세의 완료기한이 검정이다.
- 진행도 도넛 자체의 시각 검증(조각 각도·색)은 시나리오로 넣지 않았다 — 요약 문구(S7)로 대신한다.
- `재제출` 은 진행도 요약에서 `심사대기` 에 합산한다(2026-09-07 개발자 결정). S7 이 그 합산을 검증한다.
  업무보고 목록 항목의 배지에는 `재제출` 이 그대로 보인다.
