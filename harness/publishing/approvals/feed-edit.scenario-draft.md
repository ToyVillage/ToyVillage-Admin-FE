# Scenario Draft — feed-edit

출처: `harness/publishing/specs/feed-edit.spec.md` (2026-10-28 4층·5층 수정안 우선)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 4층 수정 화면 복원
- Given: 4층 기록 `카피바라 · 동식이`, 2026.09.03 09:30, 이승현, 염소사료, 200 `GML`, 잔량 100, 특이사항 `평소보다 식욕이 왕성함.`
- When: `/feeds/<id>/edit` 로 들어온다.
- Then: 제목 `급여 기록 수정`, 부제 `카피바라 · 동식이의 급여 기록을 수정합니다`.
  읽기 전용 `대상 개체` `급여일시` `급여자` 와 입력 `먹이 종류`(염소사료) `급여량`(200 + 고정 단위 `g/ml`) `잔량`(100 + `g/ml`) `특이사항` 이 보인다.

### S2: 5층 수정 화면 복원
- When: `/feeds/fifth-floor/<id>/edit` 로 들어온다.
- Then: 카드는 `대상 개체` `급여일`(읽기 전용 `YYYY.MM.DD`) `급여자` `먹이 종류` `급여량` 다섯 개다. 잔량·특이사항 칸은 없다.

### S3: 4층 저장 — 목록에서 왔을 때
- Given: 목록 케밥 `수정` 으로 들어왔다.
- When: 먹이 종류 `단배추`, 급여량 `250`, 잔량 `30`, 특이사항 `잔반 조금` 으로 바꾸고 `저장하기`.
- Then: 수정 요청이 한 번 나가고(`feedUnit` 은 원래 `GML`), 들어온 목록 주소로 돌아가 `데이터 수정에 성공했습니다` 토스트가 보인다.

### S4: 5층 저장 — 기록 상세에서 왔을 때
- Given: 5층 기록 상세 케밥 `수정` 으로 들어왔다.
- When: 먹이 종류·급여량을 바꾸고 `저장하기`.
- Then: 5층 수정 요청이 한 번 나가고 그 기록 상세로 돌아가 `데이터 수정에 성공했습니다` 토스트가 보인다.

### S5: 저장 — 급여 이력에서 왔을 때
- Given: 개체별 급여 이력 행 케밥 `수정` 으로 들어왔다.
- When: `저장하기`.
- Then: 그 개체의 급여 이력 화면으로 돌아가 성공 토스트가 보인다.

### S6: 필수 검증
- When: 4층에서 먹이 종류·급여량·잔량을 비우고 `저장하기`.
- Then: 세 카드 아래에 `먹이 종류를 입력해주세요!` `급여량을 입력해주세요!` `잔량을 입력해주세요!` 가 함께 보이고 요청은 없다.

## 엣지 시나리오

### S7: 숫자 칸 규칙
- When: 급여량에 `2 kg` 를 붙여 넣는다 / 급여량 `0` / 잔량 `0` 으로 저장한다.
- Then: 급여량 칸에는 `2` 만 남는다. 급여량 0 은 `급여량을 숫자로 입력해주세요!`, 잔량 0 은 오류가 아니다.

### S8: `KGL` 기록
- Given: 단위가 `KGL` 인 기록이다.
- Then: 입력칸 단위가 `kg/l` 이고 저장 요청 `feedUnit` 은 `KGL` 이다.

### S9: 저장 실패와 중복 제출
- Given: 수정 요청이 느리게 실패한다.
- When: `저장하기` 를 연달아 누른다.
- Then: 요청은 한 번이고 그동안 버튼이 `저장 중` 비활성이며, 실패 후 `저장하지 못했습니다. 다시 시도해 주세요.` 가 보이고 입력이 남아 있다.

### S10: 이탈 보호
- Given: 먹이 종류를 바꿨다.
- When: `뒤로가기`.
- Then: `정말 나가시겠습니까?` 확인창이 뜨고 `취소` 면 머문다. 원래 값으로 되돌리면 확인창 없이 나간다.

### S11: 불러오기 실패와 다시 시도
- Given: 상세 조회가 500 이다.
- Then: `정보를 불러오지 못했습니다` 오류 카드와 `다시 시도`. 회복 뒤 누르면 폼이 보인다.

### S12: 없는 기록
- When: 숫자가 아닌 id 또는 404 id 로 들어온다.
- Then: `/feeds` 로 돌아간다.
