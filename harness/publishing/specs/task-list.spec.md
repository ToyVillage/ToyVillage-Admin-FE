## 목적

운영 관리자가 토이빌리지 직원에게 내린 업무 지시를 한 화면에서 확인한다. 담당자·상태·우선순위·완료기한을 표로
훑고, 상태 탭으로 좁혀 보고, 행의 케밥 메뉴로 수정·삭제하거나 새 업무를 등록한다.

## 범위

- 포함: 목록 조회, 상태 탭 필터, 페이지네이션, 행 클릭 이동, 업무 등록 진입, 행 케밥 메뉴(수정·삭제),
  삭제 확인 모달, 빈 상태, 생성·삭제 결과 토스트 표시
- 제외: 실제 API 연동(`/api` 스킬 담당), 업무 생성·수정 폼(`task-create` / `task-edit`),
  업무 보고 화면(`task-report`), 검색·정렬, 행 다중 선택

## 라우트와 진입

- `/tasks` → 업무관리 목록을 표시한다.
- `업무 등록하기` 클릭 → `/tasks/create` 로 이동한다.
- 행 본문 클릭 → `/tasks/:id`(업무 상세)로 이동한다. `task-detail.spec.md` 가 그 화면을 소유한다.
- 케밥 메뉴 `수정` → **`/tasks/:id/edit`(수정 폼)로 이동한다.** `task-edit.spec.md` 가 그 화면을 소유한다.
- 목록 진입 시 항상 `전체 업무` 탭과 1페이지에서 시작한다.
- 사이드바 `업무 관리 바로가기` → `/tasks`. 사이드바 자체 동작은 `sidebar.spec.md` 를 따른다.

## 동작 (behavioral spec — source of truth)

### 목록·필터·페이지네이션

- 화면 진입 → 제목 `업무관리`, 부제 `토이빌리지 업무 지시`, `전체 업무` 탭 활성, 1페이지 목록이 보인다.
- `업무 등록하기` 버튼 클릭 → `/tasks/create` 로 이동한다.
- `진행중` 탭 클릭 → 상태가 `진행중`인 업무만 남고 목록이 1페이지로 리셋된다.
- `완료` 탭 클릭 → 상태가 `완료`인 업무만 남고 목록이 1페이지로 리셋된다.
- `지연` 탭 클릭 → 완료되지 않고 완료기한이 지난 업무만 남고 목록이 1페이지로 리셋된다.
- `전체 업무` 탭 클릭 → 모든 상태의 업무가 다시 보인다.
- 페이지 번호 클릭 → 해당 페이지의 행으로 목록이 바뀐다. 한 페이지는 10행이다(2026-09-08 개발자 결정).
- `이전 페이지` / `다음 페이지` 클릭 → 한 페이지씩 이동한다. 1페이지에서 `이전 페이지`,
  마지막 페이지에서 `다음 페이지`는 비활성이다.
- 현재 탭의 결과가 없으면 → 행 대신 `등록된 업무가 없습니다.` 를 표시하고 페이지네이션을 숨긴다.
- 완료기한이 오늘보다 이전인 업무 → 완료기한 셀을 위험색(`colors.danger`)으로 표시한다.

### 상태 (2026-09-08 개발자 결정)

- 업무지시의 상태는 `진행중` / `완료` / `지연` 세 가지다. **`반려` 는 존재하지 않는다.**
- 저장되는 값은 `진행중` / `완료` 뿐이고 `지연` 은 완료기한에서 파생한다 —
  **완료되지 않았고 완료기한이 오늘보다 이전이면 `지연`** 이다.
- **완료된 업무는 기한이 지나도 `완료`다.** `완료` 탭에서 빠지지 않는다.
  이때 완료기한 셀의 위험색은 그대로 남아 늦게 끝난 건을 알 수 있다.
- 탭은 `전체 업무` / `진행중` / `완료` / `지연` 네 개다(Figma `task / 상태 탭바` `1194:14850`).
  상태와 무관하게 날짜만으로 판정한다.

### 담당자 표기

- 담당자가 1명이면 이름만 표시한다 (예: `김수인`).
- 담당자가 2명 이상이면 대표 1명의 이름 + `외 N명` 을 표시한다 (예: `이승현 외 5명`).
  `N` 은 대표를 제외한 나머지 인원 수다.

### 케밥 메뉴

- 행 우측 끝 `⋮` 버튼 클릭 → 그 행의 메뉴가 열리고 `수정` / `삭제` 두 항목이 보인다.
- 메뉴가 열린 상태에서 다른 행의 `⋮` 클릭 → 이전 메뉴가 닫히고 새 메뉴가 열린다. 동시에 하나만 열린다.
- 메뉴 바깥 클릭 또는 `Escape` → 메뉴가 닫힌다.
- `⋮` 클릭은 행 클릭 이동을 발생시키지 않는다.
- `수정` 클릭 → 메뉴가 닫히고 `/tasks/:id/edit` 로 이동한다.
- `삭제` 클릭 → 메뉴가 닫히고 삭제 확인 모달이 열린다.

### 삭제

- 삭제 확인 모달: 제목 `정말 삭제하시겠습니까?`, 본문 `삭제하신 뒤에는 영구삭제되며` / `복구 할 수 없습니다`,
  버튼 `취소` / `확인`.
- `취소` 또는 바깥 클릭 또는 `Escape` → 모달이 닫히고 아무것도 삭제되지 않는다.
- `확인` → 해당 업무를 삭제하고 모달을 닫는다. 목록이 갱신되고 `데이터 삭제에 성공했습니다` 토스트가 뜬다.
- 삭제 실패 → 모달을 닫고 `데이터 삭제에 실패했습니다` 토스트가 뜬다. 목록은 그대로 둔다.
- 삭제 처리 중에는 `확인` 을 다시 눌러도 요청이 중복 전송되지 않는다.

### 토스트

- 목록 화면에서 뜨는 토스트는 세 가지다.
  - `데이터 삭제에 성공했습니다` (성공)
  - `데이터 삭제에 실패했습니다` (실패)
  - `데이터 생성에 성공했습니다` (성공) — `/tasks/create` 에서 생성 후 목록으로 돌아온 경우
- 표시 시간은 3초, 동시 1개다.

## 데이터

```ts
// 저장값은 진행 상태 두 가지뿐이다.
type TaskProgressStatus = 'IN_PROGRESS' | 'DONE' // 진행중 / 완료
// 화면 표기용. `OVERDUE` 는 완료기한에서 파생된다.
type TaskStatus = TaskProgressStatus | 'OVERDUE' // 진행중 / 완료 / 지연
type TaskPriority = 'HIGH' | 'MEDIUM' | 'LOW' // 상 / 중 / 하

interface TaskListItem {
  id: string
  assignees: TaskAssignee[] // 담당자 (다중)
  title: string
  status: TaskStatus
  priority: TaskPriority
  dueDate: string // 완료기한, YYYY-MM-DD
}
```

- **담당자가 단수에서 복수로 바뀐다.** 현재 구현은 `Task.assigneeId: string` 이다.
  `assignees: TaskAssignee[]` 로 바꾸고, 목록 셀은 `assignees[0].name` + `외 {assignees.length - 1}명` 으로 렌더한다.
  `assignees.length <= 1` 이면 `외 N명` 을 렌더하지 않는다.
- **`visibility`(공개범위) 필드가 목록에서 빠진다.** 새 Figma 목록 표에 공개범위 컬럼이 없다.
  생성·수정 폼에 남는지는 `task-create` / `task-edit` spec 갱신 시 확인한다.
  필드 자체를 지울지는 API 계약 확정 후 결정한다.
- `status` 는 목록 표시 전용 파생값이다. 목록에서 상태를 바꾸는 UI 는 없다.
- 조회 endpoint 후보: `GET /tasks`, query key: `['tasks']`
- 이번 슬라이스는 `src/entities/task/model/mock.ts` 의 고정 mock 으로 대체하고 실제 API 는 연결하지 않는다.
  mock 은 Figma 기준 4행(이승현 외 5명, 김수인/완료/하, 이지아/완료/상, 이승현 외 2명/중)과
  페이지네이션·빈 상태를 재현할 추가 행을 포함한다.
  **총 14건**이다 — 한 페이지 10행이라 2페이지가 나와야 페이지네이션을 확인할 수 있다
  (2026-09-08, id 11~14 추가). 저장 상태는 진행중 9 · 완료 5 이고,
  기준일 2026-09-08 에서 표기는 진행중 6 · 완료 5 · 지연 3(id 1·4·8)이다.
  **완료기한이 실제 시간과 함께 흘러 표기가 바뀐다.** 진행중으로 남길 행은 2027-01 이후로 두었다.
- **완료기한 mock 값은 Figma 그대로 두지 않는다.** Figma 캡처가 2026-07 이라 그대로 두면 1페이지가
  전부 기한 초과(위험색)로 보여 정상 표시를 확인할 수 없다. 1·2행은 Figma 값(2026-07-03 / 2026-07-01)을
  유지해 초과 표시를 남기고(1행은 그래서 `지연`, 2행은 완료라 `완료`), 나머지는 미래로 옮겨

## 접근성

- 탭은 `aria-pressed`(또는 tablist semantics)로 활성 상태를 노출한다.
- 각 행은 키보드로 활성화 가능하며 접근 가능한 이름에 담당자와 제목을 포함한다.
- `⋮` 버튼은 `aria-haspopup="menu"` 와 `aria-expanded` 를 제공하고 접근 가능한 이름에 대상 업무를 포함한다.
  메뉴는 `role="menu"`, 항목은 `role="menuitem"` 이며 `Escape` 로 닫히고 초점이 `⋮` 로 돌아온다.
- 삭제 확인 모달은 열릴 때 초점을 가두고, 닫히면 초점을 호출한 `⋮` 버튼으로 되돌린다.
- 상태·우선순위 배지는 색만이 아니라 텍스트로도 값을 전달한다.
- 페이지네이션 버튼은 `이전 페이지` / `다음 페이지` / `N 페이지` 이름을 제공하고 경계에서 `disabled` 로 표시한다.
- 토스트는 `role="status"`(성공) / `role="alert"`(실패)로 알린다.
- focus-visible 은 색만이 아닌 outline 으로 표현한다.

## 반응형

- 980px 이하에서는 제목 크기와 카드 padding 을 줄이고 본문은 가용 너비를 사용한다.
- 표는 좁은 화면에서 가로 스크롤을 허용하되 페이지 전체가 가로 스크롤되지 않게 한다.
- 컨트롤의 터치 영역은 최소 44px 을 유지한다.

## 기능 테스트 수용 기준 (초안 — 게이트 ② 승인 필요)

- S1: `/tasks` 진입 → 제목·부제가 보이고 `전체 업무` 탭이 활성이며 4행이 보인다.
- S2: `업무 등록하기` 클릭 → `/tasks/create` 로 이동한다.
- S3: `진행중` 탭 클릭 → 상태가 `진행중`인 행만 남는다.
- S4: `완료` 탭 클릭 → 상태가 `완료`인 행만 남는다.
- S24: `지연` 탭 클릭 → 완료되지 않고 완료기한이 지난 행만 남는다.
- S5: 행 본문 클릭 → `/tasks/:id`(상세)로 이동한다.
- S6: `2 페이지` 클릭 → 2페이지 행으로 바뀐다.
- S7: 1페이지에서 `이전 페이지`, 마지막 페이지에서 `다음 페이지`가 비활성이다.
- S8: 2페이지를 보는 중 탭을 바꾸면 1페이지로 리셋된다.
- S9: 결과가 없는 탭 → 빈 상태 문구가 보이고 페이지네이션이 사라진다.
- S10: 완료기한이 지난 행 → 완료기한 셀이 위험색으로 보인다.
- S11: 컬럼이 `담당자` `제목` `상태` `우선순위` `완료기한` 5개이고 `공개범위` 가 없다.
- S12: 담당자가 여럿인 행은 `이승현 외 5명`, 1명인 행은 `김수인` 으로 보인다.
- S13: `⋮` 클릭 → `수정` / `삭제` 메뉴가 열리고, 행 이동은 일어나지 않는다.
- S14: 메뉴가 열린 상태에서 다른 행 `⋮` 클릭 → 이전 메뉴가 닫히고 하나만 열려 있다.

- S16: 메뉴 `수정` 클릭 → `/tasks/:id/edit`(수정 폼)로 이동한다.
- S17: 메뉴 `삭제` 클릭 → 삭제 확인 모달이 열린다.
- S18: 모달 `취소` → 모달이 닫히고 행이 그대로 남는다.
- S19: 모달 `확인` → 행이 사라지고 `데이터 삭제에 성공했습니다` 토스트가 뜬 뒤 사라진다.

- S23: 사이드바 `업무 관리 바로가기` → `/tasks` 로 이동하고 사이드바가 닫힌다.

## 결정 사항

- 라우트는 `/tasks`, `/tasks/create`, `/tasks/:id`(상세), `/tasks/:id/edit`(수정)다.
  상세·수정 분리는 2026-09-07 개발자 결정이며 `task-detail.spec.md` 가 근거다.
- 빈 상태 문구 `등록된 업무가 없습니다.` 를 유지한다. **새 Figma 에 업무관리 빈 상태 프레임이 없다**
  문구·레이아웃은 구 결정 승계이며 Figma 근거가 없다.
- 완료기한 위험색은 상태와 무관하게 "오늘 이전"으로만 판정한다.
- 상태(`진행중/완료/지연`)는 표시 전용 파생값이며 목록에서 변경 UI 를 만들지 않는다.
- **한 페이지 10행이다**(2026-09-08 개발자 결정). Figma 표 높이 472(헤더 72 + 행 100 × 4)는
  4행 기준 렌더라 카드가 그만큼 길어진다.
- **업무지시에 `반려` 상태는 없다**(2026-09-08 개발자 결정, 같은 날 Figma 도 `지연` 으로 갱신됐다).
  세 번째 상태는 저장값이 아니라 완료기한에서 파생한다.
  명칭 후보 중 `만료`·`기한초과`·`미완료` 대신 `지연` 을 골랐다.
- **완료된 업무는 기한이 지나도 `완료`다**(2026-09-08 개발자 결정). `완료` 탭에서 빠지지 않고,
  완료기한 셀의 위험색으로 늦게 끝났음을 알린다.
