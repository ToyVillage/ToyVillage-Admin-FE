# Scenario Draft — feed-edit

출처: `harness/publishing/specs/feed-edit.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

> 목록·상세 조회는 이미 실제 API 에 연결돼 있으므로 테스트에서 Playwright 라우트로 흉내 낸다
> (`tests/e2e/support/feed-api.ts` 재사용). 수정·삭제는 퍼블리싱 mock 이다.

## 핵심 시나리오

### S1: 목록 행 케밥에서 수정·삭제 메뉴가 열린다
- Given: `/feeds` 목록에 급여 기록 행이 있다.
- When: 첫 행의 케밥을 누른다.
- Then: `수정`, `삭제` 순서의 메뉴가 열리고 URL 은 그대로다(상세로 이동하지 않는다).

### S2: 수정을 고르면 기존 값이 채워진 수정 화면으로 간다
- Given: S1 상태다.
- When: `수정` 을 누른다.
- Then: URL 이 `/feeds/<id>/edit` 가 되고 제목 `급여 기록 수정`, 부제 `<종> · <개체명>의 급여 기록을 수정합니다` 가 보인다.
  `대상 개체` `<종> · <개체명>`, `급여일시` `YYYY.MM.DD HH:mm`, `급여자` 가 읽기 전용으로,
  `먹이 종류` · `급여량`(입력값은 숫자 `1.2`, 바로 뒤에 고정 단위 `kg`) · `잔량`(입력값 `0`, 고정 단위 `kg` — 화면에 `kg` 단위는 2개) · `특이사항` 이 입력값으로 채워져 있다.

### S3: 값을 고쳐 저장하면 목록으로 돌아가 수정 성공 토스트를 띄운다
- Given: 수정 화면이다.
- When: 먹이 종류를 `닭가슴살`, 급여량을 `2.5kg`, 특이사항을 `잔반 조금 남김` 으로 바꾸고 `저장하기` 를 누른다.
- Then: 목록으로 돌아가(진입 전 조회 조건 유지) `데이터 수정에 성공했습니다` 토스트가 뜬다.
  새로고침하면 토스트는 다시 뜨지 않는다.

### S4: 삭제를 확인하면 성공 토스트가 뜬다
- Given: `/feeds` 목록이다.
- When: 첫 행 케밥 → `삭제` → 확인 모달에서 `확인` 을 누른다.
- Then: 모달이 닫히고 `데이터 삭제에 성공했습니다` 토스트가 뜨며 목록을 다시 불러온다.

## 엣지 케이스

### S5: 먹이 종류·급여량을 비우면 두 오류를 함께 보이고 저장하지 않는다
- Given: 수정 화면이다.
- When: 먹이 종류와 급여량을 비우고(공백만 남겨도 같다) `저장하기` 를 누른다.
- Then: `먹이 종류를 입력해주세요!` 와 `급여량을 입력해주세요!` 가 각 카드 아래에 보이고 URL 은 그대로다.

### S6: 급여량에는 숫자만 들어가고 0 이하는 숫자 오류를 보인다
- Given: 수정 화면이다.
- When: 급여량 칸에 `많이`, `2 kg`, `1.2.3` 을 차례로 입력하고, 마지막으로 `0` 을 넣고 `저장하기` 를 누른다.
- Then: 입력값이 각각 빈칸, `2`, `1.23` 이 되고 `kg` 단위는 계속 보인다.
  `0` 으로 저장하면 `급여량을 숫자로 입력해주세요!` 가 보이고 저장되지 않는다.

### S6-1: 잔량은 숫자만 받고 0 을 허용하며, 비우면 오류를 보인다
- Given: 수정 화면이다.
- When: 잔량 칸에 `조금` 을 입력하고 `저장하기` 를 누른다. 이어서 `0.5 kg` 를 입력하고 `저장하기` 를 누른다.
- Then: `조금` 은 걸러져 빈칸이 되고 `잔량을 입력해주세요!` 가 보이며 저장되지 않는다.
  `0.5 kg` 는 `0.5` 가 되고 저장되며 요청 본문에 `remainingAmount: 0.5`, `feedUnit: 'KGL'` 이 들어간다.
  (`0` 은 오류가 아니다.)

### S7: 오류 줄은 다음 제출 때 다시 검증해야 사라진다
- Given: S5 상태다.
- When: 먹이 종류만 다시 채우고 `저장하기` 를 누른다.
- Then: 먹이 종류 오류는 사라지고 급여량 오류는 남는다.

### S8: 읽기 전용 항목은 바꿀 수 없다
- Given: 수정 화면이다.
- When: `대상 개체` · `급여일시` · `급여자` 입력에 글자를 친다.
- Then: 값이 바뀌지 않는다.

### S9: 바꾼 값이 있으면 뒤로가기 때 이탈을 확인한다
- Given: 수정 화면에서 특이사항을 바꿨다.
- When: `뒤로가기` 를 누르고 `취소` 를 누른 뒤, 다시 `뒤로가기` → `확인` 을 누른다.
- Then: `취소` 뒤에는 수정 화면과 입력이 그대로이고, `확인` 뒤에는 목록으로 돌아가며 토스트는 뜨지 않는다.

### S10: 바꾼 값이 없으면 바로 뒤로 간다
- Given: 수정 화면에 아무것도 바꾸지 않았다.
- When: `뒤로가기` 를 누른다.
- Then: 확인 없이 목록으로 돌아간다.

### S11: 삭제 확인에서 취소하면 아무것도 지우지 않는다
- Given: `/feeds` 목록이다.
- When: 첫 행 케밥 → `삭제` 후 `취소`(다음으로 `Escape`)를 누른다.
- Then: 모달이 닫히고 행은 그대로이며 토스트는 없다. 초점은 그 행 케밥으로 돌아온다.

### S12: 케밥 메뉴는 Escape 와 바깥 클릭으로 닫힌다
- Given: 첫 행 케밥 메뉴가 열려 있다.
- When: `Escape` 를 누르고, 다시 열어 메뉴 바깥을 누른다.
- Then: 두 번 모두 메뉴가 닫힌다.

### S13: 없는 기록의 수정 주소는 목록으로 돌려보낸다
- Given: 상세 조회가 404 를 준다(또는 id 가 숫자가 아니다).
- When: `/feeds/999999/edit`(또는 `/feeds/abc/edit`)로 들어간다.
- Then: `/feeds` 로 옮겨진다.

### S14: 조회 실패면 안내 문구를 보인다
- Given: 상세 조회가 500 을 준다.
- When: `/feeds/<id>/edit` 로 들어간다.
- Then: 폼 대신 `급여 기록을 불러오지 못했습니다. 다시 시도해 주세요.` 가 보인다.

### S15: 목록 조회 조건을 유지한 채 수정하고 돌아온다
- Given: `/feeds?tab=포유류&page=2` 처럼 조건이 걸린 목록이다.
- When: 행 케밥 → `수정` → `뒤로가기` 를 누른다.
- Then: 같은 조건(`tab=포유류&page=2`)의 목록으로 돌아온다.
