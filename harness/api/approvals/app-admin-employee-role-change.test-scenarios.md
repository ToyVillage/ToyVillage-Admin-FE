# API Test Scenarios — app-admin-employee-role-change

공통 사전 조건: `support/employee-api` 가 GET `/app/admin/employees` 에 8명을 응답하고 `/settings/permissions` 에 진입한다. 1 김수인·2 이승현·3 이지아는 `MIDDLE_ADMIN`, 4 박도현·5 최민지·6 정하윤·7 오세훈·8 한지민은 `EMPLOYEE` 다. PATCH 성공은 200 `{ message }` 이고 픽스처의 `role` 을 바꾼다. 오류 body 는 Contract 의 공통 오류 바디다.

## Mock S1 — 목록과 후보를 role 로 나눈다

- 목적: 조회 하나로 중간 관리자와 지정 후보를 나눈다
- 기대 결과: GET 1회, 목록은 김수인·이승현·이지아 순서 3행과 `총 3명`, `지정일` 없음. 모달을 열면 후보는 박도현·최민지·정하윤·오세훈·한지민이다

## Mock S2 — 지정 성공

- 사용자 동작: 모달에서 최민지를 골랐다가 박도현으로 바꾼 뒤 `지정하기`
- 기대 결과: PATCH `/app/admin/employees/4/role` 1회만(Bearer, 본문 `{ "role": "MIDDLE_ADMIN" }`), 모달 닫힘, `권한 부여에 성공했습니다`, 목록 재조회로 박도현 행 추가, `총 4명`

## Mock S3 — 지정 실패(404·500)

- 기대 결과: 모달 유지, 박도현 선택 유지, `권한 부여에 실패했습니다`, 목록은 `총 3명`

## Mock S4 — 해제 성공

- 사용자 동작: 김수인 행 `해제` → 확인 모달 `해제`
- 기대 결과: PATCH `/app/admin/employees/1/role` 1회(Bearer, 본문 `{ "role": "EMPLOYEE" }`), 모달 닫힘, `권한 해제에 성공했습니다`, 김수인 행 사라짐, `총 2명`. 모달을 열면 후보에 김수인이 있다

## Mock S5 — 해제 취소

- 기대 결과: PATCH 없음

## Mock S6 — 해제 실패(404·500)

- 기대 결과: 모달 닫힘, `권한 해제에 실패했습니다`, 김수인 행 유지, 초점은 그 행 `해제` 버튼

## Mock S7 — 중복 제출 방지

- 사용자 동작: 지정과 해제 응답을 각각 지연시키고 버튼을 다시 누른다
- 기대 결과: 각 PATCH 1회. 지정 중에는 `취소`와 `지정하기` 가 비활성이고 모달이 `aria-busy` 다. 해제 중에는 버튼 문구가 `해제 중` 이다

## Mock S8 — 응답 형식 오류

- 사용자 동작: PATCH 가 200 에 `message` 없는 본문을 준다
- 기대 결과: 지정은 S3, 해제는 S6 과 같은 실패 처리

## Mock S9 — 목록 조회 실패(500)와 형식 오류

- 기대 결과: 표 대신 `중간 관리자 목록을 불러오지 못했습니다. 다시 시도해 주세요.` 상태 카드. `role` 이 없거나 허용값이 아닌 항목이 있어도 같다

## Mock S10 — 빈 상태

- 사용자 동작: 전원이 `EMPLOYEE` 인 응답으로 진입
- 기대 결과: `지정된 중간 관리자가 없어요`, `총 N명` 없음. 전원이 `MIDDLE_ADMIN` 이면 모달에 `지정할 수 있는 직원이 없습니다`
