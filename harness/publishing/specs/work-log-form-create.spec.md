## 목적

운영 관리자가 업무일지에 쓸 양식을 새로 만든다. 1단계에서 양식명과 질문 항목을 정의하고,
2단계에서 그 양식이 적용될 구역 번호를 설정한 뒤 양식을 생성한다.

## 범위

- 포함: 2단계 위저드, 양식명 입력, 질문 항목 추가·삭제, 질문 유형 선택, 선택지·기타 추가·삭제,
  검증 에러 표시, 구역 자동 생성·직접 추가·삭제·전체 삭제, 구역 미설정 모달, 생성
- 제외: 실제 API 연동(`/api` 스킬 담당), 양식 수정(`work-log-form-edit.spec.md`),
  양식 상세·목록·삭제, 파일 업로드 유형의 실제 업로드 동작

## 라우트와 진입

- `/work-logs/forms/create` → 1단계 `항목 설정`으로 진입한다.
- 목록(`/work-logs?tab=forms`)의 `양식 생성하기` 클릭으로 진입한다(이미 구현되어 있음).
- 단계는 라우트를 바꾸지 않고 페이지 내부 상태로 전환한다(Figma에 2단계 전용 URL 근거 없음).
- `뒤로가기` — 1단계에서는 `/work-logs?tab=forms`, 2단계에서는 1단계로 돌아간다.
- 단계 전환·진입 시 스크롤은 항상 맨 위에서 시작한다.

## 질문 유형

유형 드롭다운(`1:3797`, 240×400)의 항목은 다음 4개다. 각 행은 아이콘 24px + 텍스트 22px,
행 높이 72, 행 사이 1px `#DDDDE3` 구분선, 드롭다운은 셀렉트 바로 아래에 붙고 radius `0 0 8px 8px`,
그림자 `0 0 8px 1px rgba(100,100,100,0.25)`. 첫 행은 현재값(`선택`)이며 아이콘이 없다.

| 드롭다운 항목 | 코드 타입 | 답변 영역 |
|---|---|---|
| `주관식` | `TEXT` | 밑줄 한 줄 + placeholder `텍스트` |
| `객관식 질문` | `CHOICE` | 라디오 아이콘 32px + 선택지 목록 |
| `체크박스` | `CHECKBOX` | 체크박스 아이콘 32px + 선택지 목록 |
| `파일 업로드` | `FILE` | 업로드 드롭존 (아래 참고) |

> **Figma 개정으로 확정됨 (2026-09-14).** 이전 버전의 드롭다운은 `단답형`/`장문형`을 따로 두어
> 카드 배지의 `주관식` 표기와 어긋났는데, 개정판에서 두 항목이 **`주관식` 하나로 합쳐졌다**
> (드롭다운 높이 472 → 400). 이제 배지와 드롭다운 문구가 일치한다.
> `1:3981`에 남아 있는 `드롭다운` 배지는 폐기된 유형으로 읽는다.
> 이 4개 중 `TEXT`/`CHOICE`/`CHECKBOX` 는 양식 상세 spec(`work-log-form-detail`)의
> `workLogFormQuestionTypes` 와 같은 체계다 — 편집기에는 `FILE` 이 더 있다.

### 선택지 목록 (객관식 질문 · 체크박스)

- 선택지 행 — 아이콘 32px + 값 텍스트 22px `#484854`, 행 1102×64 padding 20/24, 배경 없음,
  행 끝에서 60px 떨어진 자리에 삭제 X 40px
- `기타:` 행 — 아이콘 + `기타:` + 밑줄 입력(높이 40, 하단 1px `#AFAFBA`) + 삭제 X

## 동작 (behavioral spec — source of truth)

### 초기 상태

- 1단계 진입 → 양식명은 비어 있고, 빈 질문 카드 2개가 있다(`1:3710`).
- 질문 카드의 유형은 `선택`이고 답변 영역이 없다.
- 스텝 인디케이터는 1단계 활성이다.

### 1단계 조작

- `항목 추가하기` 클릭 → 목록 맨 아래에 빈 질문 카드를 추가하고, 추가된 카드의 질문명으로 포커스를 옮긴다.
- 질문 카드의 휴지통 클릭 → 그 카드를 삭제한다. 카드가 1개만 남았을 때도 삭제할 수 있다.
- 유형 셀렉트 클릭 → 드롭다운을 연다. 항목 선택 → 유형이 바뀌고 드롭다운이 닫힌다.
  - `객관식 질문`/`체크박스`로 바꾸면 선택지가 없는 상태에서 시작한다(추가 행만 보인다).
  - 유형을 바꿔 선택지가 필요 없어지면 입력했던 선택지는 버린다.
- 드롭다운은 바깥 클릭과 Escape로 닫는다.

### 1단계 검증 (`다음` 클릭)

`1:3981` 기준. 에러가 있는 카드에 빨간 1px 테두리를 두르고, 카드 아래 16px 간격에
경고 아이콘 24px + 빨간 18px/500 메시지를 붙인다.

- 양식명이 공백만 → `양식명을 입력해주세요!`
- 질문명이 공백만 → 그 카드에 `해당 항목을 입력해주세요!`
- 유형이 `선택`인 카드 → 그 카드에 `해당 항목을 입력해주세요!`
- `객관식 질문`/`체크박스`인데 선택지가 0개이거나 공백만인 선택지가 있음 → 그 카드에 `해당 항목을 입력해주세요!`
- 에러가 하나라도 있으면 2단계로 넘어가지 않고, 첫 번째 에러 요소로 포커스와 스크롤을 옮긴다.
- 에러가 없으면 2단계로 전환한다.
- 에러 표시 후 해당 입력을 고치면 그 카드의 에러 표시를 즉시 해제한다.

### 2단계 조작

- 접두 셀렉트 — 항목은 `A`, `B`, `없음`(`1:5438`). 기본값 `없음`. 현재 선택값은 파란색으로 표시한다.
  - 열렸을 때 셀렉트는 `#5C5C68` 1px 테두리 + radius `8px 8px 0 0`, 드롭다운이 아래에 붙는다.
- 시작·끝 번호 — 숫자 입력. 기본값은 각각 `1`, `24`로 두고 placeholder 색 `#848491`로 보인다.
- `생성` 클릭 → 시작~끝 범위의 구역을 만들어 `설정된 구역`에 추가한다.
  - 접두가 `A`면 `A1`…`A24`, `없음`이면 `1`…`24`.
  - 시작 > 끝이거나 숫자가 비어 있으면 아무것도 추가하지 않는다.
  - 이미 있는 값은 중복 추가하지 않는다.
- `직접 추가` 입력에 값을 넣고 `추가` 클릭 → 그 값 하나를 추가하고 입력을 비운다.
  - 앞뒤 공백을 제거한다. 비었거나 이미 있으면 추가하지 않는다.
  - Enter 는 `추가` 클릭과 같다.
- 칩의 X 클릭 → 그 구역 하나를 삭제한다.
- `전체 삭제` 클릭 → `정말 삭제하시겠습니까?` 확인 모달을 띄운다(`DeleteConfirmationDialog`).
  - 설명 `삭제하신 뒤에는 영구삭제되며 복구 할 수 없습니다`, 버튼 `취소` / `확인`
  - `확인` → 설정된 구역을 모두 비운다. `취소` → 아무것도 지우지 않는다.
  - 구역이 0개면 `전체 삭제`를 노출하지 않는다.
- `설정된 구역`의 `(n)`은 현재 개수다. 구역이 0개면 `(0)`이고 칩 줄은 비어 있다.
- 구역 순서는 추가한 순서를 유지한다.

### 2단계 검증과 생성 (`생성하기` 클릭)

- 설정된 구역이 0개 → `구역 번호를 설정해주세요` 모달을 띄우고 생성하지 않는다(`1:5256`).
  - 버튼 `확인` 하나. `확인` 클릭 → 모달을 닫고 `직접 추가` 입력으로 포커스를 옮긴다.
- 구역이 1개 이상 → 생성 요청을 한 번 보낸다.
  - 요청 중에는 `생성하기`를 비활성화해 이중 제출을 막는다.
  - 성공 → 양식 목록 query(`['work-log-forms','list']`)를 무효화하고 `/work-logs?tab=forms`로 이동한다.
  - 실패 → 입력값과 현재 단계를 유지하고 다시 시도할 수 있게 한다.

### 뒤로가기

- 2단계의 `뒤로가기` → 1단계로 돌아간다. 1단계 입력값은 그대로 유지한다.
- 1단계의 `뒤로가기` → `/work-logs?tab=forms`로 이동한다.
- 1단계의 `뒤로가기`는 **입력값이 하나라도 채워져 있으면** 나가기 확인 모달을 먼저 띄운다.
  - Figma 생성 프레임에는 없고 수정 섹션 `1:5016`에만 있으나, 생성에도 붙이기로 결정했다
    (2026-09-14, 개발자 확인). 문구와 구성은 `1:5016` 과 같다.
  - 제목 `정말 나가시겠습니까?` / 설명 `저장하지 않고 돌아갈 시 입력된 정보가 삭제됩니다` / `취소`·`확인`
  - `확인` → 입력을 버리고 `/work-logs?tab=forms` 로 이동한다. `취소` → 모달만 닫는다.
  - 아무것도 입력하지 않았으면 모달 없이 바로 이동한다.
- 2단계의 `뒤로가기`는 1단계로 돌아가는 것이므로 모달을 띄우지 않는다(입력을 버리지 않는다).

## 접근성

- 양식명·질문명·선택지·구역 입력은 보이는 라벨 또는 접근 가능한 이름과 연결한다.
- 유형 셀렉트와 접두 셀렉트는 키보드로 열고 방향키로 이동하고 Enter/Escape로 확정·취소할 수 있어야 한다.
- 검증 에러 메시지는 `aria-describedby`로 해당 입력과 연결하고, 에러 입력에 `aria-invalid`를 준다.
- 구역 미설정 모달은 `role="alertdialog"`, `aria-modal="true"`, 포커스 트랩을 제공한다.
- 삭제 아이콘 버튼(`휴지통`, `X`)에는 대상이 드러나는 접근 이름을 준다.
- focus-visible 은 색만이 아닌 outline 으로 표현한다.

## 기능 테스트 수용 기준

- S1: `/work-logs/forms/create` 진입 → 스텝 인디케이터(1단계 활성), `뒤로가기`, 양식명 카드,
  빈 질문 카드 2개, `항목 추가하기`, `다음`이 보인다.
- S2: `항목 추가하기` 클릭 → 질문 카드가 하나 늘어난다.
- S3: 질문 카드의 휴지통 클릭 → 그 카드가 사라진다.
- S4: 유형 셀렉트 클릭 → `주관식`, `객관식 질문`, `체크박스`, `파일 업로드` 4개가 보인다.
- S5: `객관식 질문` 선택 → 배지가 `객관식 질문 *`로 바뀌고 `옵션 추가` 행이 보인다.
- S6: `옵션 추가` 클릭 → 선택지 행이 하나 추가되고 추가 행이 `옵션 추가 또는 기타 추가`로 바뀐다.
- S7: `기타 추가` 클릭 → `기타:` 행이 추가되고 `기타 추가`가 더 이상 보이지 않는다.
- S8: 선택지 행의 X 클릭 → 그 선택지가 사라진다.
- S9: 양식명이 빈 상태로 `다음` 클릭 → `양식명을 입력해주세요!`가 보이고 2단계로 넘어가지 않는다.
- S10: 질문명이 빈 카드가 있는 상태로 `다음` 클릭 → 그 카드에 `해당 항목을 입력해주세요!`가 보인다.
- S11: 1단계를 모두 채우고 `다음` 클릭 → 2단계(`구역 번호 설정`)가 보이고 인디케이터가 2단계 활성이 된다.
- S12: 2단계에서 `뒤로가기` 클릭 → 1단계로 돌아가고 입력값이 유지된다.
- S13: 접두 `A`, 시작 `1`, 끝 `3`으로 `생성` 클릭 → 칩 `A1`, `A2`, `A3`과 `(3)`이 보인다.
- S14: `직접 추가`에 `기타`를 넣고 `추가` 클릭 → 칩 `기타`가 추가되고 입력이 비워진다.
- S15: 이미 있는 값을 다시 추가 → 칩이 늘지 않는다.
- S16: 칩의 X 클릭 → 그 칩이 사라지고 `(n)`이 줄어든다.
- S17: `전체 삭제` 클릭 → 칩이 모두 사라지고 `(0)`이 된다.
- S18: 구역이 0개인 상태로 `생성하기` 클릭 → `구역 번호를 설정해주세요` 모달이 보이고 생성되지 않는다.
- S19: 구역이 있는 상태로 `생성하기` 클릭 → 생성 요청이 한 번 전송되고 `/work-logs?tab=forms`로 이동한다.
- S20: 1단계에서 `뒤로가기` 클릭 → `/work-logs?tab=forms`로 이동한다.
- S21: 키보드만 사용 → 양식명·질문명·유형 선택·선택지 추가·구역 추가·생성을 수행할 수 있다.
- S26: 유형을 `파일 업로드`로 선택 → 업로드 드롭존(`클릭하거나 파일을 끌어다 놓으세요`)이 보인다.
