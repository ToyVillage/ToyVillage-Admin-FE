## 목적

운영 관리자가 특정 날짜에 직원이 앱으로 올린 먹이 급여 기록을 층(4층·5층)별로 조회한다.
4층과 5층은 앱 입력 양식이 달라 표의 열이 다르다(앱에서 입력하지 않는 칸은 보여주지 않는다).

## 범위

- 포함: 조회날짜 필터, 층 탭(4층·5층), 층별 급여 내역 표, 페이지네이션, 행 클릭 이동, 행 케밥(수정·삭제), 토스트
- 제외: 실제 API 연동(`/api` 스킬 담당 — 4층은 이미 연동된 조회를 그대로 쓰고 5층은 mock 경계로 둔다),
  급여 기록 생성, 검색·정렬, `내역 내보내기`(흰 사각형으로 덮여 있다 — 구현하지 않는다)

## 라우트와 진입

- `/feeds` → 먹이 급여 관리 목록. URL 이 조회 조건을 가진다: `date=YYYY-MM-DD`(없으면 오늘), `floor=5`(없으면 4층), `page=N`(1이면 생략).
  잘못된 값은 기본값으로 본다. 새로고침·뒤로가기에서 조건이 유지된다.
- 4층 행 클릭 → `/feeds/:id`(4층 급여 기록 상세). 5층 행 클릭 → `/feeds/fifth-floor/:id`(5층 급여 기록 상세).
  `:id` 는 급여 기록 id 다. 이동할 때 목록 주소(`location.search`)를 state `listSearch` 로 넘긴다.
- 사이드바 `먹이 급여 관리` 항목은 `/feeds` 로 간다(`sidebar.spec.md`).

## 동작 (behavioral spec — source of truth)

- 화면 진입 → 제목 `먹이 급여 관리`, 부제 `4층·5층별 먹이 급여 내역`, `조회날짜` 필터, 층 탭(`4층` 선택), 4층 표 1페이지가 보인다.
- 조회날짜 년/월/일 드롭다운 동작은 기존과 같다(업무일지관리 목록과 동일 — 열기·닫기·바깥 클릭·Escape·연도 5개·말일 보정).
  날짜를 바꾸면 1페이지로 돌아가고 층은 유지된다.
- 층 탭은 디자인 시스템 `animal species` 탭(`CategoryTabs`)이다. 선택된 층은 검정 SemiBold + 아래 2px 밑줄, 나머지는 회색 Medium.
  탭 클릭 → 그 층의 표로 바뀌고 1페이지로 돌아간다. 날짜는 유지된다.
- 표는 디자인 시스템 `list`(`1:11043`) 외형의 `DataTable` 이다(머리 행 52px #DDDDE3 · 머리 글자 20px #36363F, 행 92px,
  본문 24px 검정, 시간·사람 열 22px #848491, 행 구분선 #848491, 테두리 #A1A1A1 radius 20).
- 4층 표의 열: `일반명` / `개체명` / `급여시간` / `먹이 종류` / `급여량` / `잔량` / `특이사항` / `급여자` / 케밥.
  - 급여시간은 `HH:mm`, 급여자와 함께 회색 22px 다.
  - 급여량·잔량은 숫자 뒤에 앱이 고른 단위를 붙인다: `GML` → `g/ml`, `KGL` → `kg/l` (예 `150 g/ml`). 잔량이 없으면 `-`.
  - 특이사항이 없으면 `-`. 칸보다 길면 한 줄로 자르고 말줄임표를 붙인다(예 `평소보다 식욕이…`).
- 5층 표의 열: `일반명` / `개체명` / `먹이 종류` / `급여량` / `급여자` / 케밥. 급여자는 회색 22px 다.
- 한 페이지는 10행이다(개발자 결정 `b885d4c` — Figma 는 4행). 페이지네이션(`이전 페이지` / 번호 / `다음 페이지`)은 기존 규약 그대로다
  (1페이지에서 이전, 마지막 페이지에서 다음 비활성).
- 그 층·날짜에 기록이 없으면 → 행 대신 `해당 날짜에 급여 내역이 없습니다.` 를 보이고 페이지네이션을 숨긴다(기존 문구 유지).
- 로딩 중에는 같은 자리에 빈 표(값 자리 막대)를 두어 레이아웃이 튀지 않게 한다.
- 조회 실패 → 다른 목록 화면과 같은 상태 카드 `급여 내역을 불러오지 못했습니다. 다시 시도해 주세요.`(기존 유지).

### 행 케밥

- 각 행 오른쪽 끝 케밥(⋮) 클릭 → 그 행 아래에 메뉴(`수정`, `삭제` 빨간 글자)가 열린다. 행 클릭 이동은 일어나지 않는다.
  바깥 클릭·Escape → 닫힘. 한 번에 하나만 열린다(기존 규약).
- `수정` → 그 층의 수정 화면(`/feeds/:id/edit` 또는 `/feeds/fifth-floor/:id/edit`)으로 간다. state 로 `listSearch` 와 `from: 'list'` 를 넘긴다.
- `삭제` → 공통 삭제 확인 모달(`정말 삭제하시겠습니까?` / `삭제하신 뒤에는 영구삭제되며 복구 할 수 없습니다`).
  `확인` → 삭제 요청 1회(요청 중 `삭제 중` 비활성). 성공 → 목록 재조회, 행이 사라지고 `데이터 삭제에 성공했습니다` 토스트.
  실패 → `데이터 삭제에 실패했습니다` 토스트, 행 유지. `취소`/Escape → 닫히고 초점은 그 케밥으로 돌아간다.
  삭제로 현재 페이지가 비면 앞 페이지로 옮긴다.
- 수정 화면에서 저장하고 목록으로 돌아오면 `데이터 수정에 성공했습니다` 토스트가 뜬다(Figma `3309:26096`, 우상단).

## 데이터

- 4층 목록: 기존 연동 `getFeeds`(`GET /feed-log/admin`, 1-based page·size 4). 분류 탭이 없어져 `animalTaxonomic` 은 보내지 않는다.
  화면에 필요한 값(`feedUnit`, `significant`)을 응답에서 더 읽는다. `significant` 는 목록 응답에 아직 없어(백엔드 추가 요청 중) 없으면 `-`.
- 5층 목록: 퍼블리싱에서는 `entities/feed` 의 mock 함수 `getFifthFloorFeeds({ date, page, size })` 로 둔다(`/api` 스킬이 교체).
- 쿼리키: `feedQueryKeys.list(date, floor, page)`. 다른 직원이 계속 기록을 올리므로 `staleTime: 0`(기존 유지).
- 삭제: 4층은 기존 연동 `deleteFeed`, 5층은 mock `deleteFifthFloorFeed`.

## 컴포넌트 구조/props

- `FeedListPage` — URL 조건·케밥·삭제·토스트를 소유한다.
- `FeedTable { floor, feeds, onRowClick, renderRowAction, pagination, emptyLabel, loading }` (entities/feed/ui) — 층별 열 정의로 `DataTable` 을 래핑한다.

## 비고 / 제약

- 기존 분류 탭(전체·포유류·파충류·조류·어류), `종`·`급여날짜` 열, `먹이 종류 · 급여량` 합친 열은 없앤다.
- 4층/5층 기록은 서로 다른 API 이므로 같은 id 가 두 층에 있을 수 있다. 라우트로 층을 구분한다.
- 스타일은 Emotion 을 사용한다. solid color/font family 는 theme 의미 토큰, px·rgba 등 구현값은 styled 블록에 직접 쓴다.
