# Scenario Draft — feed-record-detail

출처: `harness/publishing/specs/feed-record-detail.spec.md`
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 4층 급여 기록 상세
- Given: 4층 기록 `카피바라 · 동식이`, 2026.09.03 09:30, 이승현, 염소사료, 200 `GML`, 잔량 100, 특이사항 `평소보다 식욕이 왕성함.`
- When: `/feeds/<id>` 로 들어온다.
- Then: 제목 `급여 기록 상세`, 부제 `카피바라 · 동식이의 급여 기록입니다`, 카드가 `대상 개체` `급여일시` `급여자` `먹이 종류` `급여량` `잔량` `특이사항` 순서로
  `카피바라 · 동식이` `2026.09.03 09:30` `이승현` `염소사료` `200 g/ml` `100 g/ml` `평소보다 식욕이 왕성함.` 를 보인다.

### S2: 5층 급여 기록 상세
- When: `/feeds/fifth-floor/<id>` 로 들어온다.
- Then: 카드가 `대상 개체` `급여일` `급여자` `먹이 종류` `급여량` 다섯 개이고 `급여일` 은 `YYYY.MM.DD` 다. `잔량`·`특이사항`·`급여일시` 카드는 없다.

### S3: 급여 이력 보기
- When: `급여 이력 보기` 를 누른다(4층 / 5층).
- Then: 각각 `/feeds/animals/<개체 id>`, `/feeds/fifth-floor/animals/<개체 id>` 로 이동한다.

### S4: 뒤로가기
- Given: `/feeds?date=<날짜>&floor=5` 목록에서 행을 눌러 들어왔다.
- When: `뒤로가기` 를 누른다.
- Then: `/feeds?date=<날짜>&floor=5` 로 돌아간다. 주소로 바로 들어왔다면 `/feeds` 로 간다.

### S5: 케밥 수정
- When: 제목 옆 케밥 → `수정`.
- Then: 그 층의 수정 화면으로 이동한다.

### S6: 삭제 성공
- When: 케밥 → `삭제` → 확인 모달 `확인`.
- Then: 그 개체의 급여 이력 화면으로 이동하고 `데이터 삭제에 성공했습니다` 토스트가 보인다.

## 엣지 시나리오

### S7: 삭제 실패·취소
- Then: 실패면 이 화면에 머물고 `데이터 삭제에 실패했습니다` 토스트. 취소면 아무 일도 없다.

### S8: 값이 없을 때
- Given: 4층 기록에 잔량·특이사항이 없다.
- Then: `잔량`·`특이사항` 카드 값이 `-` 다.

### S9: 불러오기 실패와 다시 시도
- Given: 상세 조회가 500 으로 실패한다.
- Then: `정보를 불러오지 못했습니다` / `일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요` / `다시 시도` 가 보이고,
  조회가 회복된 뒤 `다시 시도` 를 누르면 상세 카드가 보인다.

### S10: 없는 기록
- When: `/feeds/abc` 또는 404 인 id 로 들어온다.
- Then: `/feeds` 로 돌아간다.

### S11: 이력에서 들어간 기록 삭제
- Given: 급여 기록 상세(`/feeds/1`) → `급여 이력 보기` → 개체 이력(`/feeds/animals/1`)에서 2번 행을 눌러 `/feeds/2` 로 들어왔다.
- When: 케밥 → `삭제` → `확인`.
- Then: `/feeds/animals/1` 로 이동해 `데이터 삭제에 성공했습니다` 토스트가 보이고 행이 1개로 준다. 이력의 `뒤로가기`는 자기 자신이 아니라 처음 들어왔던 `/feeds/1` 로 간다.

### S12: 이력에서 들어간 기록 수정 뒤 뒤로가기
- Given: S11 과 같은 경로로 `/feeds/2` 에 들어왔다.
- When: 케밥 → `수정` → `저장하기` 뒤, `뒤로가기`를 두 번 누른다.
- Then: 저장 뒤 `/feeds/2` 로 돌아오고, 첫 `뒤로가기`는 `/feeds/animals/1`, 두 번째는 `/feeds/1` 로 간다.
