# Scenario Draft — account-create

출처: `harness/publishing/specs/account-create.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 계정 생성 화면 표시

- Given: 로그인한 관리자가 `/settings/accounts/create`에 직접 진입한다.
- When: 페이지 렌더링이 완료된다.
- Then: 로고, 제목 `계정 생성`, 안내 문구, 이름·아이디 입력, 초기 비밀번호 안내 문구, `계정 생성` 버튼이 보이고 오류 문구는 보이지 않는다.

### S2: 빈 값 제출 시 두 필드 오류

- Given: 이름과 아이디가 비어 있다.
- When: `계정 생성` 버튼을 클릭한다.
- Then: `이름을 입력해주세요!`와 `아이디를 입력해주세요!`가 함께 보이고, 두 입력이 invalid로 표시되며 이름 입력에 포커스가 가고 제출 함수는 호출되지 않는다.

### S3: 아이디만 비었을 때

- Given: 이름만 입력되어 있다.
- When: `계정 생성` 버튼을 클릭한다.
- Then: 아이디 오류만 보이고 아이디 입력에 포커스가 가며 제출 함수는 호출되지 않는다.

### S4: 유효한 값 제출

- Given: 이름과 아이디에 앞뒤 공백이 섞인 유효한 값이 입력되어 있다.
- When: `계정 생성` 버튼을 클릭한다.
- Then: 공백을 제거한 `{ name, username }`으로 제출 함수가 한 번 호출된다.

### S5: Enter로 제출

- Given: 이름과 아이디가 유효하게 입력되어 있다.
- When: 아이디 입력에서 Enter를 누른다.
- Then: 버튼 클릭과 같게 제출 함수가 한 번 호출된다.

### S6: 제출 성공

- Given: 유효한 값으로 제출했다.
- When: 제출 함수가 성공한다.
- Then: 두 입력이 비워지고 이름 입력에 포커스가 가며 `계정이 생성되었습니다` 토스트가 보인다.

## 엣지 케이스

### S7: 입력하면 해당 필드 오류만 사라짐

- Given: 빈 값 제출로 두 오류가 보인다.
- When: 이름 입력에 값을 입력한다.
- Then: 이름 오류만 사라지고 아이디 오류는 남는다.

### S8: 공백만 입력

- Given: 이름과 아이디에 공백만 입력되어 있다.
- When: 제출한다.
- Then: 두 필드 모두 미입력 오류가 보이고 제출 함수는 호출되지 않는다.

### S9: 중복 제출 방지

- Given: 제출이 진행 중이다.
- When: 버튼을 다시 누르거나 Enter를 다시 누른다.
- Then: 제출 함수가 추가로 호출되지 않는다.

### S10: 제출 실패

- Given: 유효한 값으로 제출했다.
- When: 제출 함수가 실패한다.
- Then: 입력값은 유지되고 `계정 생성에 실패했습니다` 토스트가 보인다.

### S11: 오류 표시 시 레이아웃 고정

- Given: 초기 상태에서 `계정 생성` 버튼의 위치를 확인한다.
- When: 빈 값으로 제출해 오류 문구가 나타난다.
- Then: `계정 생성` 버튼의 위치가 변하지 않는다.

### S12: 키보드만으로 조작

- Given: 계정 생성 페이지에 있다.
- When: Tab으로 이동하며 입력하고 Enter로 제출한다.
- Then: 이름 → 아이디 → `계정 생성` 순서로 포커스가 이동하고 제출할 수 있다.
