## 핵심 시나리오

### S1: 목록 진입 기본 상태
- Given: 업무보고 목록 라우트 `/task-reports`
- When: 화면에 진입한다
- Then: 제목 `업무보고`와 부제 `토이빌리지 업무 보고 관리`가 보이고, `심사대기` 탭이 활성이며 1페이지 행이 표시된다

### S2: 컬럼 표시 확인 (수정)
- Given: `/task-reports` 화면
- When: 테이블 헤더를 확인한다
- Then: `담당자` `상태` `우선순위` `완료기한` 4개 컬럼이 순서대로 보이고, `제목` `공개범위` 컬럼은 없다

### S3: 탭 라벨에 건수 표시 (수정)
- Given: `/task-reports` 화면
- When: 탭바를 확인한다
- Then: `심사대기` `완료` `반려` 세 탭이 각각 `{상태명} {건수}` 형태로 보이고, `재제출` 탭은 없다

### S4: `완료` 탭 필터 (수정)
- Given: `/task-reports` 화면, `심사대기` 탭 활성
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭이 활성이 되고 심사 상태가 승인인 보고만 남으며, 각 행의 `상태` 칸에 `심사대기` 배지가 없다

### S25: 표 `상태` 칸은 심사 상태 배지 (추가)
- Given: `/task-reports` 화면
- When: `심사대기` 탭과 `반려` 탭의 행을 차례로 확인한다
- Then: `심사대기` 탭 행의 `상태` 칸에는 `심사대기` 배지, `반려` 탭 행에는 `반려` 배지가 보인다

### S6: 페이지네이션 이동
- Given: `/task-reports` 화면, `심사대기` 탭 결과가 한 페이지(3건)를 초과해 페이지 버튼이 보임
- When: `2 페이지` 버튼을 클릭한다
- Then: 2페이지의 행으로 목록이 바뀐다

### S7: 탭 전환 시 첫 페이지로 복귀
- Given: `/task-reports` 화면, `심사대기` 탭에서 2페이지를 보고 있음
- When: `완료` 탭을 클릭한다
- Then: `완료` 탭의 1페이지가 표시된다

### S8: 행 클릭 → 상세 이동
- Given: `/task-reports` 화면
- When: 목록의 행을 클릭한다
- Then: 해당 보고의 `/task-reports/:id` 로 이동한다

### S26: 행 케밥 메뉴 열기 (추가)
- Given: `/task-reports` 화면
- When: 첫 행의 `⋮` 버튼을 클릭한다
- Then: `승인하기` `반려하기` 두 항목의 메뉴가 열리고, 화면은 목록에 머문다(상세로 이동하지 않는다)

### S27: 목록에서 승인 (추가)
- Given: `/task-reports` 화면, `심사대기` 탭
- When: 한 행의 `⋮` → `승인하기` 를 클릭한다
- Then: 목록에 머물고 `승인에 성공했습니다` 토스트가 보이며, 그 보고가 `심사대기` 탭에서 빠지고 `완료` 탭에서 조회된다

### S28: 목록에서 반려 (추가)
- Given: `/task-reports` 화면, `심사대기` 탭
- When: 한 행의 `⋮` → `반려하기` 를 눌러 열린 반려 사유 모달에 사유를 입력하고 `확인` 을 클릭한다
- Then: 모달이 닫히고 `반려에 성공했습니다` 토스트가 보이며, 그 보고가 `반려` 탭에서 조회된다

### S9: 상세 표시 내용 (수정)
- Given: 업무보고 상세 `/task-reports/:id`
- When: 화면을 확인한다
- Then: `우선순위:` `상태:` `담당자:` `완료 기한:` 요약이 보이고 `공개 범위:` 는 없으며,
  한 카드 안에 `제목` `상세 업무 내용` `첨부자료` 가 보이고, 하단에 `반려하기` `승인하기` 버튼이 보인다

### S10: 첨부자료는 조회 전용
- Given: 첨부가 있는 업무보고 상세
- When: 첨부자료 영역을 확인한다
- Then: 파일명과 다운로드 버튼만 있고 삭제 버튼과 업로드 영역은 없다

### S11: 상세에서 승인 (수정)
- Given: 심사대기 보고의 상세 화면
- When: `승인하기` 버튼을 클릭한다
- Then: `/task-reports` 로 이동해 `승인에 성공했습니다` 토스트가 보이고, 해당 보고가 `완료` 탭에서 조회된다

### S12: 상세에서 반려 (수정)
- Given: 심사대기 보고의 상세 화면에서 `반려하기` 를 눌러 반려 사유 모달이 열려 있음
- When: 반려 사유를 입력하고 `확인` 을 클릭한다
- Then: `/task-reports` 로 이동해 `반려에 성공했습니다` 토스트가 보이고, 해당 보고가 `반려` 탭에서 조회된다

## 엣지 케이스

### S13: 처리 중 중복 제출 차단
- Given: 처리 지연이 주입된 상세 화면
- When: `승인하기` 버튼을 연속으로 두 번 클릭한다
- Then: 두 버튼이 비활성 상태가 되고 처리 요청은 한 번만 전송된다

### S14: 결과 없음 → 빈 상태
- Given: `/task-reports` 화면
- When: 결과가 없는 탭으로 전환한다
- Then: 행이 사라지고 `등록된 업무보고가 없습니다.` 가 표시되며 페이지네이션이 보이지 않는다

### S15: 없는 보고 진입
- Given: 존재하지 않는 id 의 `/task-reports/:id`
- When: 화면에 진입한다
- Then: `업무보고를 찾을 수 없습니다.` 안내와 목록으로 돌아가는 링크가 보인다

### S16: 업무 상세의 보고 줄은 연동 전까지 진입 보류 (수정)
- Given: 업무보고가 올라온 업무의 상세 `/tasks/:id`
- When: 담당자별 보고 현황을 확인한다
- Then: 보고 줄은 보이지만 누를 수 있는 버튼이 없고 업무 상세에 머문다
  (2026-09-12 커밋 979228c — 업무보고 API 연동 때 `/task-reports/:workReportId` 이동으로 되돌린다)

### S17: 사이드바 업무보고 메뉴 이동
- Given: 다른 화면에서 사이드바를 연 상태
- When: `업무 보고 바로가기` 를 클릭한다
- Then: `/task-reports` 로 이동하고 사이드바가 닫힌다

### S18: 상세에서 뒤로가기
- Given: 업무보고 상세 `/task-reports/:id`
- When: 상단 `뒤로가기` 를 클릭한다
- Then: 승인·반려 처리 없이 `/task-reports` 로 이동한다

### S19: 반려하기 → 반려 사유 모달 표시
- Given: 심사대기 보고의 상세 화면
- When: `반려하기` 버튼을 클릭한다
- Then: `반려 사유를 작성해주세요` 제목과 `반려 사유 작성` placeholder 입력란, `확인` 버튼이 있는 모달이 열리고,
  화면은 상세에 머무르며 반려 요청은 아직 전송되지 않는다

### S20: 사유 미입력 시 확인 불가
- Given: 반려 사유 모달이 열려 있고 입력란이 비어 있음
- When: 모달의 `확인` 버튼을 확인한다
- Then: `확인` 버튼이 비활성이고, 공백만 입력해도 비활성이 유지된다

### S21: 모달 이탈 시 반려되지 않음
- Given: 반려 사유 모달이 열려 있음
- When: Esc 를 누른다(또는 모달 바깥 영역을 클릭한다)
- Then: 모달이 닫히고 상세 화면에 머무르며, 반려 요청은 전송되지 않는다

### S29: 목록 반려 모달 이탈 시 반려되지 않음 (추가)
- Given: 목록에서 한 행의 `⋮` → `반려하기` 로 반려 사유 모달이 열려 있음
- When: Esc 를 누른다
- Then: 모달이 닫히고 목록에 머무르며, 반려 요청은 전송되지 않고 초점이 그 행의 `⋮` 버튼으로 돌아간다

### S22: 입력한 반려 사유 저장
- Given: 반려 사유 모달에 사유를 입력하고 `확인` 을 눌러 반려가 끝난 상태
- When: 저장된 반려 사유를 확인한다
- Then: 해당 보고 id 로 입력한 사유가 mock 저장소에 남아 있다

### S23: 모달 처리 중 중복 확인 차단
- Given: 처리 지연이 주입된 상태에서 반려 사유를 입력한 모달
- When: `확인` 버튼을 연속으로 두 번 클릭한다
- Then: `확인` 버튼이 비활성이 되고 반려 요청은 한 번만 전송된다

### S24: 모달 처리 중 초점 유지
- Given: 처리 지연이 주입된 상태에서 반려 사유를 입력한 모달
- When: `확인` 을 눌러 반려 요청이 진행 중인 상태에서 Tab 을 누른다
- Then: 초점이 사유 입력란에 남아 모달 밖으로 빠져나가지 않는다

### S30: 목록 승인 실패 (추가)
- Given: 승인 실패가 주입된 `/task-reports` 화면
- When: 한 행의 `⋮` → `승인하기` 를 클릭한다
- Then: 목록에 머물고 `승인에 실패했습니다` 토스트가 보이며, 그 보고는 `심사대기` 탭에 그대로 있다

### S31: 목록 반려 실패 (추가)
- Given: 반려 실패가 주입된 `/task-reports` 화면
- When: 한 행의 `⋮` → `반려하기` → 사유 입력 → `확인` 을 클릭한다
- Then: 모달이 닫히고 `반려에 실패했습니다` 토스트가 보이며, 그 보고는 `심사대기` 탭에 그대로 있다

### S32: 상세 승인 실패 (추가)
- Given: 승인 실패가 주입된 심사대기 보고의 상세 화면
- When: `승인하기` 버튼을 클릭한다
- Then: 상세에 머물고 `승인에 실패했습니다` 토스트가 보이며, `승인하기` `반려하기` 버튼을 다시 누를 수 있다

### S33: 상세 반려 실패 (추가)
- Given: 반려 실패가 주입된 심사대기 보고의 상세 화면에서 반려 사유 모달에 사유를 입력함
- When: `확인` 을 클릭한다
- Then: 모달이 닫히고 상세에 머물며 `반려에 실패했습니다` 토스트가 보이고, 두 버튼을 다시 누를 수 있다
