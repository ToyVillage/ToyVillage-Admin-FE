## 핵심 시나리오

### S1: 수정 화면 진입
- Given: 상세 화면 `/tasks/:id`
- When: 케밥 메뉴에서 `수정` 을 클릭한다
- Then: `/tasks/:id/edit` 로 이동한다

### S2: 기존 값 복원
- Given: `/tasks/:id/edit` 진입
- When: 폼을 확인한다
- Then: 우선순위·완료기한·제목·상세 내용이 저장된 값으로 채워져 있다

### S3: 담당자 복원과 접힌 트리
- Given: 담당자가 지정된 업무의 수정 화면
- When: 담당자 트리를 확인한다
- Then: 모든 팀이 접힌 채로 보이고, 팀을 펼치면 저장된 직원이 체크돼 있다

### S5: 기존 첨부 표시
- Given: 첨부가 있는 업무의 수정 화면
- When: 첨부자료를 확인한다
- Then: 저장된 개수만큼 chip 이 보이고 각 chip 에 다운로드 컨트롤이 있다

### S8: 제목 수정 저장
- Given: `/tasks/:id/edit` 화면
- When: 제목을 고치고 `저장하기` 를 클릭한다
- Then: `/tasks/:id` 로 이동하고 상세에 바뀐 제목이 보인다

### S9: 담당자 추가 저장
- Given: `/tasks/:id/edit` 화면
- When: 담당자를 추가하고 저장한다
- Then: 목록과 상세의 `외 N명` 이 늘어난다

## 엣지 케이스

### S4: 부분 선택 복원
- Given: 일부 직원만 담당자인 업무의 수정 화면
- When: 해당 팀 행을 확인한다
- Then: 체크박스가 `mixed` 로 보이고 카운트가 `2/6명` 처럼 맞는다

### S6: 공개범위 부재
- Given: `/tasks/:id/edit` 화면
- When: 폼 전체를 확인한다
- Then: 공개범위 필드가 존재하지 않는다

### S7: 삭제 버튼 부재
- Given: `/tasks/:id/edit` 화면
- When: 하단 버튼을 확인한다
- Then: 라벨이 `저장하기` 이고 `삭제하기` 버튼이 없다

### S10: 제목 미입력 검증
- Given: 제목을 비운 상태
- When: `저장하기` 를 클릭한다
- Then: 요청을 보내지 않고 `제목을 입력해주세요` 모달이 뜬다

### S11: 담당자 전체 해제 검증
- Given: 담당자를 전부 해제한 상태
- When: `저장하기` 를 클릭한다
- Then: `담당자를 선택해주세요` 모달이 뜬다

### S12: 변경 후 이탈 보호
- Given: 값을 바꾼 상태
- When: `뒤로가기` 를 클릭한다
- Then: `정말 나가시겠습니까?` 모달이 뜨고 `취소` 시 입력이 유지된다

### S13: 무변경 이탈
- Given: 아무것도 바꾸지 않은 상태
- When: `뒤로가기` 를 클릭한다
- Then: 확인 없이 `/tasks/:id` 로 이동한다

### S14: 저장 중복 제출 방지
- Given: 저장 요청이 진행 중
- When: `저장하기` 를 다시 클릭한다
- Then: 요청이 한 번만 전송된다

### S15: 없는 업무
- Given: 존재하지 않는 id
- When: `/tasks/:id/edit` 로 진입한다
- Then: `업무를 찾을 수 없습니다.` 와 목록 복귀 링크가 보인다

### S16: 키보드 조작
- Given: `/tasks/:id/edit` 화면
- When: 키보드만으로 복원 확인·편집·저장을 시도한다
- Then: 모든 조작이 가능하고 포커스 표시가 outline 으로 보인다

## 승인 메모

- 구 승인본은 폐기된 파일 기준이라 전면 교체했다.
- **라우트가 `/tasks/:id` → `/tasks/:id/edit` 로 바뀐다**(2026-09-07 개발자 결정). S1·S13 이 그 결과다.
- **삭제 시나리오를 전부 뺐다** — 삭제는 `task-detail` 로 이관했다. `task-detail` S13~S16 이 대신 검증한다.
- **업무 보고 진입 시나리오를 뺐다** — 상세 화면의 업무보고 목록(`task-detail` S5·S6)이 맡는다.
- 필드 편집·검증 동작은 `task-create` 가 계약을 갖는다. 여기서는 복원·저장·이탈만 검증해 중복을 피했다.
- 저장 성공 토스트는 Figma 근거가 없어 시나리오에 넣지 않았다.
