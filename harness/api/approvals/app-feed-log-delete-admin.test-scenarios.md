# API Test Scenarios — app-feed-log-delete-admin

공통 사전 조건: `support/feed-api` 기본 mock(오늘 급여 기록 12건, 1페이지 10행)에
`DELETE **/feed-log/admin/{id}`(200 본문 없음, 성공 시 그 기록을 목록 데이터에서 제거)를 더하고 `/feeds` 에 진입한다.
오류 body 는 Contract 형식 `{ message, status, timestamp, description }`.

## Mock S1 — 삭제 성공

- 사용자 동작: 1행(표범 · 레오) 케밥 → `삭제` → `확인`
- Mock request: DELETE `/feed-log/admin/1`, Bearer 헤더, 본문 없음
- 기대 결과: DELETE 1회, 모달 닫힘, `데이터 삭제에 성공했습니다` 토스트, 목록 재조회 후 `표범` 행이 사라진다

## Mock S2 — 취소하면 요청하지 않는다

- 사용자 동작: 1행 케밥 → `삭제` → `취소`
- 기대 결과: DELETE 없음, 행 유지

## Mock S3 — 없는 기록(404)·서버 오류(500)

- 기대 결과: 모달 닫힘, `데이터 삭제에 실패했습니다` 토스트, 행 유지, 초점은 그 행 케밥

## Mock S4 — 중복 삭제 방지

- 사전 조건: DELETE 응답 지연
- 사용자 동작: `확인` 을 누르고 응답 전에 다시 누른다
- 기대 결과: DELETE 1회, 응답 전까지 확인 버튼은 `삭제 중` 비활성

## Mock S5 — 마지막 페이지를 비우면 앞 페이지로 간다

- 사용자 동작: 2페이지(2행)에서 두 행을 차례로 삭제
- 기대 결과: DELETE 2회, 두 번째 삭제 뒤 1페이지 목록이 보인다

## Mock S6 — 삭제한 기록의 상세는 캐시를 쓰지 않는다

- 사용자 동작: 1행 상세(`/feeds/1`)에 들어갔다 목록으로 돌아와 1행을 삭제한 뒤 `/feeds/1` 로 다시 들어간다
- 기대 결과: 상세 GET 을 다시 요청하고(404) 목록으로 되돌아간다
