# Scenario Draft — login

출처: `harness/publishing/specs/login.spec.md` (행동명세가 source of truth)
상태: draft (게이트 승인 전)

## 핵심 시나리오

### S1: 로그인 화면 표시

- Given: 비인증 사용자가 `/login`에 직접 진입한다.
- When: 페이지 렌더링이 완료된다.
- Then: 로고, 제목, 안내 문구, 아이디·비밀번호 입력과 로그인 버튼이 보이며 전역 사이드바는 보이지 않는다.

### S2: 비밀번호 표시 전환

- Given: 비밀번호 입력에 값이 있고 값은 가려져 있다.
- When: 비밀번호 표시 버튼을 클릭한다.
- Then: 입력값과 포커스를 유지한 채 값이 보이고, 다시 클릭하면 값이 가려진다.

### S3: 아이디 필수 검증

- Given: 아이디가 비어 있다.
- When: 로그인 버튼을 클릭하거나 비밀번호 입력에서 Enter를 누른다.
- Then: 제출 함수를 호출하지 않고 아이디 필수 오류를 연결하며 아이디 입력으로 포커스가 이동한다.

### S4: 비밀번호 필수 검증

- Given: 아이디는 입력했고 비밀번호는 비어 있다.
- When: 로그인 버튼을 클릭하거나 비밀번호 입력에서 Enter를 누른다.
- Then: 제출 함수를 호출하지 않고 비밀번호 필수 오류를 연결하며 비밀번호 입력으로 포커스가 이동한다.

### S5: 유효한 자격 증명 제출

- Given: 아이디와 비밀번호가 유효하게 입력되어 있다.
- When: 로그인 버튼을 클릭한다.
- Then: 앞뒤 공백을 제거한 아이디와 원본 비밀번호를 제출 함수에 한 번 전달한다.

### S6: Enter로 제출

- Given: 아이디와 비밀번호가 유효하게 입력되어 있다.
- When: 비밀번호 입력에서 Enter를 누른다.
- Then: 로그인 버튼 클릭과 동일하게 제출 함수가 한 번 호출된다.

### S7: 로그인 성공

- Given: 유효한 값으로 로그인 제출을 시작했다.
- When: 제출 함수가 성공한다.
- Then: `/`로 이동한다.

## 엣지 케이스

### S8: 중복 제출 방지

- Given: 로그인 제출이 진행 중이다.
- When: 로그인 버튼을 다시 누르거나 Enter를 다시 입력한다.
- Then: 제출 함수를 추가로 호출하지 않는다.

### S9: 로그인 실패 시 안전한 입력 상태

- Given: 유효한 값으로 로그인 제출을 시작했다.
- When: 제출 함수가 실패한다.
- Then: `/login`과 아이디는 유지하고 비밀번호는 비운 뒤 비밀번호 입력으로 포커스가 이동한다.

### S10: 공백 아이디 검증

- Given: 아이디가 공백 문자만 포함하고 비밀번호는 입력되어 있다.
- When: 로그인을 제출한다.
- Then: 제출 함수를 호출하지 않고 아이디를 빈 값으로 검증한다.

### S11: 키보드 접근

- Given: 로그인 페이지에 있다.
- When: 키보드 Tab과 Enter만 사용한다.
- Then: 아이디·비밀번호 입력, 비밀번호 표시 전환과 로그인을 순서대로 조작할 수 있다.
