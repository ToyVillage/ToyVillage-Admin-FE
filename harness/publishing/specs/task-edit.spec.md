## 목적

운영 관리자가 이미 등록한 업무 지시를 열어 내용을 고치고 저장한다. 저장 실패나 실수로 인한 이탈에도
입력과 기존 데이터를 잃지 않아야 한다.

## 범위

- 포함: 기존 업무 조회와 폼 복원, 필드 편집, 첨부 확인·다운로드·추가·제거, 저장, 이탈 보호,
  없는 업무 처리
- 제외: 실제 API 연동(`/api` 스킬 담당), **삭제(`task-detail` 소관 — 상세 화면 케밥이 맡는다)**,
  상세 조회(`task-detail`), 업무 생성(`task-create`), 업무 보고 화면(`task-report`),
  상태(`진행중/완료/반려`) 변경, 수정 이력

## 라우트와 진입

- 상세 화면(`/tasks/:id`) 케밥 `수정` → `/tasks/:id/edit` 로 이동한다.
- `/tasks/:id/edit` → 해당 ID 업무의 수정 화면을 표시한다.
- `뒤로가기` → **`/tasks/:id`(상세)로 돌아간다**(변경이 있으면 이탈 확인을 거친다).
- 저장 성공 → `/tasks/:id`(상세)로 이동한다.
- 없는 id → `업무를 찾을 수 없습니다.` 와 `목록으로 돌아가기` 링크를 표시한다.

## 동작 (behavioral spec — source of truth)

### 복원

- 진입 시 저장된 값이 모두 채워진 상태로 보인다 — 우선순위 pill 선택, 완료기한 값, 담당자 트리의
  체크 상태, 제목, 상세 내용, 기존 첨부 chip.
- **담당자 트리는 모든 팀이 접힌 채로 보인다**(2026-09-08 개발자 결정). 복원된 선택은 팀 행의
  3상태 체크박스(`mixed` / 체크)와 `n/m명` 카운트로 읽는다. 팀을 펼치면 저장된 직원이 체크돼 있다.
- 카운트(`n/m명`)는 복원된 선택을 반영한다.
- 기존 첨부는 다운로드 컨트롤을 제공한다.

### 편집

- 필드 편집 동작·검증 순서·검증 문구는 모두 `task-create.spec.md` 를 따른다. 여기서 다시 정의하지 않는다.
- 첨부는 기존 항목을 제거하거나 새 파일을 추가할 수 있다.

### 저장

- 버튼 라벨은 **`저장하기`** 다(생성 화면의 `생성하기` 자리).
- 필수값이 비어 있으면 → 요청을 보내지 않고 `task-create` 의 검증 순서대로 모달을 띄운다.
- 저장 요청은 한 번만 보낸다. 요청 중에는 중복 제출을 막는다.
- 저장 성공 → 업무 query 를 갱신하고 `/tasks/:id` 로 이동한다.
- 저장 실패 → 현재 URL 과 모든 입력을 보존하고 실패를 알린다.

### 이탈 보호

- 값이 하나라도 바뀐 상태에서 `뒤로가기` / 사이드바 이동 / 브라우저 뒤로가기 → 이탈 확인 모달을 띄운다.
  제목 `정말 나가시겠습니까?`, 본문 `저장하지 않고 돌아갈 시 입력된 정보가 삭제됩니다`, 버튼 `취소` / `확인`.
- 바꾼 값이 없으면 확인 없이 바로 이동한다.
- 저장 성공에 의한 이동은 이탈 확인 대상에서 제외한다.

## 화면 구조와 시각 규격

`task-create.spec.md` 의 규격과 동일하다. 차이는 두 가지뿐이다.

1. 하단 버튼 라벨이 `저장하기` 다(123×61, 본문 우측 끝 정렬).
2. 담당자 트리는 진입 시 모두 접혀 있어 폼 높이가 생성 화면과 같은 1534 다.
   `1:3584` 의 1822 는 사육팀 4행(288)을 펼친 상태를 그린 것이다.
3. `add file` 카드(1320×140)에 기존 첨부 chip 3개가 @40,60 부터 220 pitch 로 놓인다.

제목·상세 내용·첨부자료는 생성 화면과 같이 **각각 독립 카드**다(2026-09-08 Figma 갱신 반영).

## 컴포넌트 구조/props

- `EditTaskPage` — `/tasks/:id/edit` 페이지. **신규 파일**. 기존 `TaskDetailPage` 는 상세로 바뀌므로
  수정 폼 화면을 이 파일로 옮긴다.
- `TaskForm { mode: 'edit', initialValue, onSubmit }` — `task-create` 와 공용. 삭제 관련 props 는 없다.
- `TaskAssigneeTree` — 공용. 초기 펼침은 없고 복원된 선택은 체크 상태·카운트로만 드러난다.
- `LeaveConfirmationDialog` / `ValidationDialog` / `Toast` — 기존 재사용.
- `TaskBackLink` — 기존 재사용. 이동 대상만 `/tasks/:id` 로 바뀐다.

## 접근성

- `task-create.spec.md` 의 접근성 규칙을 그대로 따른다.
- 복원된 담당자 트리의 팀 행은 접힌 상태의 `aria-expanded="false"` 와 `aria-checked="mixed"` 를
  정확히 노출한다. 펼침 버튼의 이름은 `<팀이름> 펼치기` / `<팀이름> 접기` 다.
- 기존 첨부의 다운로드 버튼은 접근 가능한 이름에 파일명을 포함한다.

## 기능 테스트 수용 기준 (초안 — 게이트 ② 재승인 필요)

- S1: 상세 케밥 `수정` → `/tasks/:id/edit` 로 이동한다.
- S2: 진입 시 우선순위·완료기한·제목·상세 내용이 기존 값으로 채워져 있다.
- S3: 모든 팀이 접힌 채로 보이고, 팀을 펼치면 저장된 직원이 체크돼 있다.
- S4: 부분 선택된 팀의 체크박스가 `mixed` 로 보이고 카운트가 `2/6명` 처럼 맞는다.
- S5: 기존 첨부 chip 이 저장된 개수만큼 보이고 각 chip 에 다운로드 컨트롤이 있다.
- S6: 공개범위 필드가 없다.
- S7: 하단 버튼 라벨이 `저장하기` 이고 `삭제하기` 버튼이 없다.
- S8: 제목을 고치고 `저장하기` → `/tasks/:id` 로 이동하고 상세에 바뀐 제목이 보인다.
- S9: 담당자를 추가하고 저장 → 목록·상세의 `외 N명` 이 늘어난다.
- S10: 제목을 비우고 `저장하기` → 요청 없이 `제목을 입력해주세요` 모달이 뜬다.
- S11: 담당자를 전부 해제하고 `저장하기` → `담당자를 선택해주세요` 모달이 뜬다.
- S12: 값을 바꾼 뒤 `뒤로가기` → `정말 나가시겠습니까?` 모달이 뜨고 `취소` 시 입력이 유지된다.
- S13: 아무것도 바꾸지 않고 `뒤로가기` → 확인 없이 `/tasks/:id` 로 이동한다.
- S14: 저장 요청 중 재클릭 → 중복 요청을 보내지 않는다.
- S15: 없는 id 로 진입 → `업무를 찾을 수 없습니다.` 와 목록 복귀 링크가 보인다.
- S16: 키보드만으로 복원 확인·편집·저장을 수행할 수 있다.

## 결정 사항

- 라우트를 `/tasks/:id/edit` 로 분리한다(2026-09-07 개발자 결정).
- **삭제를 이 화면에서 제거**하고 상세 화면 케밥으로 옮긴다.
- **업무 보고 진입을 이 화면에서 제거**하고 상세 화면의 업무보고 목록으로 옮긴다.
- 저장 성공 시 목록이 아니라 상세로 돌아간다(수정 결과를 바로 확인할 수 있게).
- 필드·검증 계약은 `task-create.spec.md` 하나만 두고 여기서 복제하지 않는다.
- **담당자 트리는 진입 시 모두 접힌다**(2026-09-08 개발자 결정). Figma `1:3584` 는 사육팀을
  펼쳐 그렸지만, 복원된 담당자가 많을수록 폼이 길어져 다른 필드가 밀리는 문제가 있어
  접힌 상태로 통일했다. 생성 화면과 진입 모습이 같아지는 이점도 있다.
